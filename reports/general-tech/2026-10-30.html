Security Oct 25–28

PHP2Shell gets chained into real break-ins: 25 servers rooted, including three in a U.S. government-affiliated network

Israeli firm Dream says a suspected China-nexus actor combined PHP2Shell (CVE-2026-109618 and -109619, CVSS 9.2, unauthenticated RCE) with Fragnesia (CVE-2026-46300, a Linux kernel privilege escalation). The targets were firewall management servers running PHP 8.0.30. The attacker fingerprinted about 19,000 exposed devices, narrowed to 240, and rooted 25 across the U.S., Japan, Taiwan and South Korea. Claude Code, DeepSeek and Kimi tooling were found on the attack infrastructure; there's no direct evidence AI wrote the exploit.

Fixed PHP releases are 8.5.12, 8.4.27, 8.3.36 and 8.2.35 (Oct 21). Older branches like 8.0 and 8.1 get no official release. WordPress.com, VIP and Pressable say they're covered; self-hosted sites must update PHP itself, since a WordPress update doesn't fix it. EU CERT and the UK NCSC told anyone who can't patch to isolate or take sites offline.

So what for TSD: Patch instruction: today, list every client or prospect site on self-hosted WordPress or any PHP host, check the PHP version, and get it to a fixed release or behind a WAF rule. Anything on PHP 8.0/8.1 has no official fix and should move. Your Next.js/Vercel builds don't run PHP, so they're clear.

Supabase Oct 30

Supabase's Data API change reaches every project today: new tables need explicit grants

Announced in April, the change now applies to all existing projects. New tables in the public schema are no longer granted to anon, authenticated and service_role automatically, so the REST and GraphQL APIs can't see them until you grant access. Existing tables keep their grants. A missing grant shows up as PostgREST error 42501 with a hint naming the GRANT you need.

So what for TSD: Update your migration template now: every create table gets its grant lines, enable row level security and policies in the same file. Otherwise the next table you add to a client app will throw 42501 in production.

Vercel Oct 29

Vercel makes Node.js 26 LTS the default and splits AI crawlers from AI assistants in the Firewall

Node.js 26 LTS is GA for builds and Functions and is the default for new projects. Firewall managed rulesets can now block AI training crawlers and AI assistant bots independently. Also shipped: more accurate IP geolocation with city and postal code for more visitors, Vercel Flags starting 7x faster on cold starts, and auto-configured webhooks for X, Twilio and Telegram in Vercel Connect.

Next.js shipped only canaries this week (16.5.0-canary.25 through .34). Canary.30 swapped jsonwebtoken for fast-jwt with no security note attached. The Oct 14 fixes (16.4.1 / 15.5.28) are still the floor.

So what for TSD: Pin existing client projects to their current Node version and test 26 on one before moving the rest. Set the crawler and assistant rules on each client site on purpose: most SMBs want assistants able to book, and some won't want training crawlers.
