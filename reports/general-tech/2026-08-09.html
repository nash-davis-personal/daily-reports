Research August 8

HTTP Terminator turned the HTTP spec into 30,000 attack vectors and broke about 700 targets

James Kettle at PortSwigger fed 138 HTTP and SMTP RFCs into a system that fragmented them into roughly 15,000 pieces and generated 30,000 candidate attack vectors, using Claude for document extraction and test-case generation. Run against 30,000 authorized test websites, it found approximately 700 vulnerable targets. The list of who was affected is the uncomfortable part: banks, government infrastructure, security products, and an airport. A single technique built on Content-Type: multipart/byteranges exposed more than 200 websites including an unnamed US bank.

The techniques themselves are new, not rediscoveries. Dual-matching Content-Length patterns trigger desync where previous methods failed. A "dangling-byte" trick makes response queue poisoning reliable enough to be practical. Shared-Parser Confusion generalizes the whole category. It also produced an Apache Traffic Server zero-day, CVE-2026-63078, though Kettle credits human-guided cascade analysis for that one rather than the AI working alone. PortSwigger's advice is to avoid HTTP/1.1 on upstream connections, and where that isn't possible, allow-list methods at both layers and restrict which methods may carry a request body. HTTP Terminator is on GitHub.

So what for TSD: The defensive read matters more than the headline. Every client site you host on Vercel terminates at an edge you don't control, so the exposure here is mostly on the self-hosted and legacy stacks you inherited, which is where an Nginx or Apache proxy sits in front of an old app. If you have any client running their own reverse proxy, that is a real conversation this week. The commercial read: an open-source tool that finds real bugs at this scale is the honest version of the security pitch, because "someone can now scan the entire internet cheaply" is a fact rather than a scare tactic.

Malware August 8

A Go-based macOS stealer arrives through copy-paste and empties crypto wallets partially

Huntress researcher Andrew Brandt disclosed a ClickFix campaign targeting macOS. The delivery is social engineering rather than an exploit: the victim is convinced to paste a command into Terminal. That runs a Bash profiler and loader which fingerprints the system, then pulls down a Mach-O payload matched to the CPU architecture. It attempts privilege escalation by showing a fake system error asking for credentials.

It takes browser passwords, iCloud Keychain data and cached credentials, and then runs a routine literally named DRAIN with separate functions for Bitcoin, Litecoin, Dogecoin, Monero, Ethereum and XRP. Huntress flags one detail as new: this is "the first time we have seen malware capable of emptying a cryptocurrency wallet that could be used to remove any less than the entire wallet's value," meaning it can skim rather than clean out, which delays detection. The infrastructure traces to Aeza Group, a Russian bulletproof hosting provider under US, UK and Australian sanctions.

So what for TSD: You are the target profile. You paste commands into Terminal from documentation and error messages dozens of times a day, and your Keychain holds Supabase service keys, Vercel tokens and client credentials. Adopt one rule with no exceptions: never paste a command you did not type or read in full, and treat any web page that tells you to run something in Terminal as hostile. If you ever have pasted a blind one-liner, rotate the Vercel and Supabase tokens rather than assuming.

Vulnerability August 7

NatJack hijacks TCP sessions by manipulating NAT connection state

Malcolm Stagg disclosed this at Black Hat USA 2026 through SODIUM-24. It's a new attack class rather than a single bug, and it works by manipulating NAT connection tracking state. Four paths: replace a NAT mapping to redirect traffic from a live TCP connection, interfere with DNS requests to enable forged responses, disclose externally mapped ports, and flood the NAT connection table with spoofed flows. Independently developed NAT implementations turned out to be susceptible in the same ways.

Two CVEs so far. CVE-2026-56181 at CVSS 8.3 covers Windows NAT in Hyper-V, and Microsoft has fixed Windows 11 and Server 2025. CVE-2026-63913 at CVSS 8.2 covers Linux Netfilter conntrack, with fixes in stable kernels 5.10.259, 5.15.210, 6.1.176, 6.6.143, 6.12.93, 6.18.35, 7.0.12 and 7.1, though that only mitigates the broader downstream-spoofing technique. There is no single universal patch. The practical limit is real: the attacker needs privileged access to a system behind the same NAT as the victim. No public evidence of exploitation as of August 7.

So what for TSD: Low urgency for you specifically, because the same-NAT requirement means this is an office-network and shared-hosting problem rather than a public web problem. Where it does apply is any client with a flat network where the guest wifi, the POS terminals and the back office all sit behind one router, which describes most of the trades and retail shops you work with. It's a legitimate reason to recommend network segmentation on the next site visit, and it costs them nothing from you.

Social engineering August 8

UNC6671 calls personal phones to get into company SaaS

A data extortion group is running voice phishing against personal devices rather than corporate ones, capturing credentials on the call and then deploying Python and PowerShell scripts to pull data out of cloud accounts. The personal-phone angle is the point, since it sits outside whatever mobile management and call filtering the company has bought.

So what for TSD: Every SMB you serve has the same hole, which is that the owner's cell is the real admin console and it has no controls on it at all. When you set up a client's Supabase or Google Workspace, turn on phishing-resistant MFA rather than SMS codes, and tell the owner plainly that nobody from you will ever call asking for a code. That sentence, said once at handoff, defeats most of this.

Platform August 8

Vercel put Grok Imagine Image 2.0 on the AI Gateway as a preview

xAI's Imagine Image 2.0 is now available through Vercel's AI Gateway in preview, with image generation and text rendering. Yesterday's General AI brief covered the model landing second to GPT-Image-2 in both the Image Edit and Text-to-Image arenas, with the caveat that API access was listed as coming soon and therefore not automatable.

A gateway preview is not the same as a general xAI API, and preview status on Vercel means it can change or disappear. But it is a route to calling the model from code with billing you already have set up.

So what for TSD: This closes the gap that made yesterday's item a manual tool. Text rendering inside generated images is the specific thing that has forced you into Photoshop for client social assets, so spend thirty minutes putting a real client's product shot through it via the Gateway. If the text holds up, a monthly social-image package becomes something you can actually automate and bill for. Keep it off anything load-bearing while it's in preview.
