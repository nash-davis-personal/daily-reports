◆ Patch and rotate today

Security Oct 26

Gheist: stolen GitHub tokens push a workflow that prints every repo secret into Actions logs

Wiz has tracked the campaign since September 15. With any token that has write access, the tool pushes a ci-sync-xxxxxx branch adding .github/workflows/sync-check.yml (commit message "ci: sync config"). The workflow prints the job's environment and every readable secret in base32, which slips past GitHub's log masking, then downloads the log and deletes the run seconds later. One variant runs a job per deployment environment to grab production-scoped secrets. Wiz found 13,500+ planted branches across 850+ compromised accounts, including private enterprise repos, and the campaign was still running as of October 24.

GitHub has held suspicious runs for approval since July 28, but only on public github.com repositories. Private repos are not covered. Tokens come from infostealer logs and earlier supply-chain hits such as the March Trivy compromise.

So what for TSD: Do this today. Search every TSD and client repo for ci-sync- branches or a sync-check.yml workflow. Replace classic personal access tokens with fine-grained, short-lived ones or GitHub Apps. Add required reviewers on any environment that holds production secrets. If you find a planted branch, rotate every secret that repo could read (Supabase service keys, Stripe, Anthropic) and never approve a held sync-check run.
The Hacker News, Oct 26
Security Oct 25

"Tailworm": unpatched Tailscale SSH flaws let one compromised device reach root on other servers

Erica Windisch of Cyberdione Labs published lab results (Tailscale 1.104.2, headscale 0.29.5) showing that when Tailscale SSH allows port forwarding, an attacker who already controls one permitted device can escalate to root on the target. Tailscale's VP of engineering confirmed on Reddit that the company found issues and is working on fixes, but there is no bulletin, CVE or fixed version yet, and Tailscale is not telling everyone to disable Tailscale SSH. Tailnet Lock blocked the final key-theft step. Other researchers dispute the "wormable" label, and nobody has independently reproduced the findings.

So what for TSD: The daily-reports hub and Nash OS sit on a tailnet. Rewrite SSH grants as single source-to-destination pairs, turn off SSH port forwarding where you don't use it, remove any tailscale serve forward to a Unix socket, enable node-key expiry, and turn on Tailnet Lock. Watch for the fixed release and update every node when it ships.
The Hacker News, Oct 25
Security Oct 21–24

Railway, OpenCode Console and LiteLLM: three incidents where stored platform secrets leaked

Railway (disclosed Oct 21) said an unauthorized party may have accessed encrypted environment variables and decrypted some of them. It paused all deployments, told every customer to roll all env vars and registry credentials, and believes this is part of a series of attacks on platform companies aimed at AI inference providers. OpenCode said keys that about 1.4% of Console users had saved for OpenAI, Anthropic or Google may have been exposed after an intrusion on October 16. Keys stored locally by its CLI were not affected, and some users report unauthorized charges. LiteLLM disclosed Friday that an unrevoked master key, exposed in a public repo in late May, let an attacker steal GitHub tokens and push a malicious release.

So what for TSD: Give every product and every client its own Anthropic and OpenAI key, with a spend limit on each, so one leak stays small and traceable. Never paste provider keys into third-party consoles when an env var on Vercel will do. If any client project ever touched Railway, rotate its secrets now.

Security Oct 26

A file planted in Downloads told a coding agent to install malware, and the trick also worked on Claude Code

Forever Security caught an AGENTS.md disguised as engineering notes on a customer's machine. It told OpenAI's Codex to register a server in its config and install the npm package function-color, part of the MALFEX campaign. The agent was stopped before anything ran. In isolated tests Codex ran the malware more than 90% of the time. Claude Code, given a CLAUDE.md version, did so about half the time with a long engineering-doc framing, because it usually asks for approval on those writes. A web page can drop a file into Downloads silently.

So what for TSD: Never start Claude Code in ~/Downloads (it's an inbox, keep it empty). Read any CLAUDE.md in a freshly cloned client repo before running an agent there, and check .claude/settings.json for MCP servers or base URLs you didn't add.
The Hacker News, Oct 26

Vercel Oct 23–26

Vercel CLI adds spend budgets; Connect issues restricted Stripe keys per agent; pnpm installs about 14% faster

vercel budgets shows spend, sets an On-Demand Budget, can pause projects at 100% and lists alert history. Vercel Connect can now create a separate restricted Stripe API key for each agent or task. Deployments show build-cache size, and pnpm installs on Pro with a restored cache are about 14% faster on average (Oct 26). Kimi K3.1 Pro is also on AI Gateway.

So what for TSD: Set a budget with pause-at-100% on every client project this week. It's the cheapest insurance against a runaway bot or a leaked key. Per-agent restricted Stripe keys are the right pattern for any booking or payments agent you build.

Status Oct 14–24

No new Next.js or Supabase advisories; the Brotli decoder bug spreads to Bun and Python

The newest Next.js security release is still October 14 (16.4.1 and 15.5.28): a critical use cache RCE, a critical image-optimization SVG RCE via sharp and a Server Actions DoS. On 15.x, confirm sharp resolves to 0.35.5 or later, because an old lockfile can keep the vulnerable decoder. Separately, the Brotli memory-corruption bug behind the Node.js RCE also affects Bun, Python and other software that bundles its own decoder. Supabase's only recent changes are the knowledge-base beta and the November 10 TLS cipher cutoff.

So what for TSD: Run npm ls next sharp on every client app and update anything below 16.4.1, or below 15.5.28 with sharp 0.35.5 or later. Update Node and any Bun or Python services as their Brotli fixes ship.
