Advisory CVE-2026-64638 ◆ CVSS 8.9

A WordPress username field chains to code execution, and every legacy client site is in scope

The bug lives in how WordPress renders a failed login. A specially crafted username survives the sanitization filters and lands as attacker-controlled live DOM on the failed-login page. From there it interacts with WordPress's own user-profile.js to steer the application into same-origin requests it should never make. The pwn.ai research team demonstrated the full chain, which they call XSS2Shell, ending in PHP execution and exposure of database credentials plus a persistent foothold.

The initial XSS needs no authentication. Full exploitation needs a logged-in administrator to visit a page the attacker controls, which is a phishing email, not a hard problem. WordPress shipped 7.0.3 on August 6 and pwn.ai disclosed on August 7. Older branches did not get backports.

So what for TSD: You don't run WordPress, but a real share of the SMBs you sell into do, and the ones you migrated to Next.js often still have the old site parked somewhere with a live wp-admin. Spend an hour today pulling the version off every WordPress domain you or a client still own and get them all to 7.0.3. Then make it a product: a $150 one-time "we checked and patched every site you forgot you had" is the easiest yes on the list, and it gets you inside their hosting account, which is where the redesign conversation actually starts.

Exploited CVSS 10.0 ◆ no CVE assigned

A Metabase zero-day was used against Metabase Cloud, and Framework says customer data got out

An unauthenticated attacker can inject arbitrary SQL into the Metabase application database and come out with administrator access. From there it's configuration changes, stolen database credentials for every connected source, and bulk export. It scores a flat 10.0 and no CVE has been assigned yet. Metabase says Metabase Cloud was attacked by someone using an unknown zero-day, and Framework, the modular-laptop maker, has confirmed customer data exposure through that attack.

Six branches are affected: v1.58.0–1.58.23, v1.59.0–1.59.20, v1.60.0–1.60.16, v1.61.0–1.61.10, v1.62.0–1.62.8 and v1.63.0–1.63.3. Fixed builds are 1.58.24, 1.59.21, 1.60.17, 1.61.11, 1.62.9 and 1.63.5 or later. If you can't patch a self-hosted instance immediately, block the /api/session/reset_password endpoint and grep your logs for POST calls to it returning 400. Post-patch cleanup is the real work: revoke sessions, rotate every credential Metabase held, review admin accounts and audit the query history.

So what for TSD: Metabase is the BI tool a bootstrapped SMB self-hosts on a spare droplet and then forgets, and it holds credentials to everything. If any client dashboard you built talks to a Metabase instance, that instance holds your Supabase connection string. Check it today and rotate the keys regardless of what you find, because a 10.0 with in-the-wild use and no CVE means the scanning started before the advisory did.

Supply chain August 8

Roughly 800 npm packages skip the install hook and wait for you to import them

Paul McCarty of OpenSourceMalware and Sonatype, which tracks it as Flooding Dropper, found about 800 malicious packages on npm. The interesting part is the delivery. Most supply-chain malware fires from a postinstall hook, which is exactly what scanners watch. These packages do nothing at install time and instead instruct the developer to load them with require(). That call runs WEL1DROPPER, a downloader that fingerprints your OS and CPU architecture and then fetches a matching payload from a Cloudflare Workers domain, a DNS TXT record at wel1[.]ru, or a per-platform fallback host.

Payloads differ by platform. On Windows it patches ETW and AMSI to blind local telemetry, persists via Registry Run keys and scheduled tasks, and pulls an encrypted executable. On macOS it does comparable evasion and persists with a LaunchAgent. On Linux it drops Sliver, an open-source command-and-control framework. Package names are typosquats and what the researchers describe as AI-generated slop names built to look plausible in a search.

So what for TSD: This is aimed directly at you. You install packages fast, on a machine holding client Vercel tokens, Supabase service keys and an Anthropic key, and a Registry Run key or LaunchAgent on that laptop is the whole business. Two rules starting today: nothing gets installed because an AI or a blog post suggested the name, and any package whose README tells you to require() it for setup gets read before it gets imported. Run npm ls against your active projects this weekend and eyeball anything you don't remember adding.

◆ The agent you deployed is a data-exfil path

Partially fixed August 8

Two teams found two ways to make Atlassian Rovo hand over Jira and Confluence data, and one still works

PromptArmor's version hides instructions inside a document. A user asks Rovo to summarize the file, the hidden text tells Rovo to go fetch internal data and append it to a URL the attacker controls, and the user sees a perfectly normal summary while the data leaves. Varonis Threat Labs found a second route they call RovoBlast: a crafted URL carrying a rovoChatPrompt parameter preloads instructions into Rovo Chat, and in their words, "One click from an authenticated user was enough for Rovo to run them with that user's privileges and send the results to an attacker-controlled server."

Atlassian fixed RovoBlast server-side on July 8 and that fix is validated. The content-injection path is a different story. PromptArmor disclosed it on May 23, followed up on July 29, got no further communication, and published on August 5. It remains unresolved as of August 8. Neither issue has a CVE.

So what for TSD: This is the failure mode of every RAG product you sell, including Concierge. Any agent that both reads untrusted input and can reach the network is one hidden paragraph away from being an exfiltration tool, and the vendor timeline here shows how long a fix can take once it's shipped. Make outbound network access an explicit allowlist in your agent configs rather than something the model can improvise, and write "we do not let the assistant call arbitrary URLs" into the proposal, because Atlassian just demonstrated the alternative in public.

◆ Your stack

Platform August 7

Vercel added Skill Packs, opened container registry repos, and is giving Pro subscribers a domain

Skill Packs let you assemble a custom collection of agent skills out of the skills.sh directory rather than wiring them one at a time, which is the natural follow-on to the Agent Plugins 1.0 spec that went out on August 6. Alongside it: Hermes Agent can now use Vercel AI Gateway for inference across 200-plus models with no markup on tokens, Container Registry repositories can be made public for read-only access, and audit log drains added Datadog, Splunk and Panther as destinations. New Pro subscriptions include a free domain for one year across six TLDs.

So what for TSD: The free Pro domain quietly kills a line item in your onboarding — you've been eating or passing through a domain fee on new client projects. Skill Packs are the packaging layer for the plugin play from Thursday's brief: one TSD pack containing your Front Desk, Concierge and Booking Bridge skills is a thing a prospect can install in ten seconds, and installs are a metric you can show the next prospect.

Breaking change Week of August 9

Self-hosted Supabase makes Envoy the default API gateway, replacing Kong

Starting the week of August 9, a self-hosted Supabase stack gets Envoy as its API gateway by default. Kong is still available, but you have to opt back in, and you need to if you depend on Kong's HTTPS listener, a custom kong.yml, or anything referencing the kong service name — a Docker Compose file or an internal URL, for instance. Separately, Realtime Broadcast now carries binary payloads over WebSockets, the REST API and the database, which removes the JSON encoding overhead for things like sensor streams and image frames.

So what for TSD: If everything you run is hosted Supabase, this is a non-event. If you stood up a self-hosted instance for a client who wanted their data on their own box, pin the image version before Monday so an unattended pull doesn't swap the gateway under a production site while you're in class.
