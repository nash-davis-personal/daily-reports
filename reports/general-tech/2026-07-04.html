◆ Supply chain under siege

Breach July 3, 2026

Tata Electronics breach leaks unreleased Apple iPhone 18 Pro secrets

India is investigating a cyberattack on Tata Electronics — now a major node in Apple's supply chain as production shifts from China to India — after confidential files leaked online. The dump reportedly includes iPhone 18 Pro / Pro Max engineering documents, prototype photos, component specs, manufacturing records, and at least six internal documents naming which companies make hundreds of individual iPhone components. Files tied to Tesla, Qualcomm and TSMC were reportedly caught up in the same leak.

So what for TSD: Even Apple's suppliers get popped. When you sell an SMB an AI product that touches their data, the vendor conversation is now part of the pitch: name where data lives (Supabase, Vercel, Anthropic), keep secrets out of the repo, and put a one-page "here's how your data is handled" in every proposal. Trust is a differentiator you can charge for.

◆ Your stack this week

Heads-up week of July 6

Supabase is changing config and logging defaults — read before your next deploy

Two changes land this week. For self-hosted setups, the default API_EXTERNAL_URL now includes an /auth/v1 path prefix, GOTRUE_JWT_ISSUER shifts to ${API_EXTERNAL_URL}, and SAML SSO gateway routes move from /sso/saml/* to /auth/v1/sso/saml/*. Separately, new projects created after July 9 get log_connections=off by default, and existing Free/Pro projects will have it flipped off starting July 9 to cut log noise. Supabase's next Launch Week is July 26.

So what for TSD: TSD's apps run on hosted Supabase, so the self-hosted URL change likely doesn't bite you — but if any client project is self-hosted or has hard-coded auth callback paths, verify them before the next push. The log_connections=off flip is benign but will change what you see in logs; don't chase a "missing" connection log as a bug on July 9+.

Patch this week

A short patch-now list — and a reminder for your own repos

CISA says threat actors are actively exploiting a recently patched Microsoft SharePoint RCE (CVE-2026-45659), and attackers are using public proof-of-concept code against NetScaler appliances to read arbitrary memory from HTTP responses. Neither is on TSD's stack directly. What is on-stack: the coordinated April Next.js / React Server Components release (DoS CVE-2026-23869 plus the earlier RSC RCE fixes) — patched in Next.js 15.5.15 / 16.2.3 and later.

So what for TSD: No new framework advisory dropped this week, so this is a hygiene check, not a fire drill. Run npm ls next react across the fleet and confirm every app is on a patched Next build (16.2.5+ is safe). If a client site has been sitting untouched since spring, it's the one to check.
