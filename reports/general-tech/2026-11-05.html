◆ Patch and migrate: the Supabase items

Breaking Nov 4

Supabase CLI v3.0.0 changes which project a command runs against and when it asks

Supabase filed v3 as a breaking change. The rollout started Nov 2; npm, Homebrew, Scoop, the Linux packages and supabase/setup-cli now install v3 by default. Database commands target the local stack unless you pass --remote, which replaces --linked, --project-ref and --db-url (still accepted, now deprecated). Every command that changes a hosted project asks first, and the default answer is No; in CI the command fails unless you pass --yes. Flags and environment variables now override config.toml everywhere, with one resolution order: flag, shell env, project env files, config file, default. pg-delta is the default diff engine, so generated SQL from db diff and db pull can change. The [inbucket] config section is now [local_smtp], the separate supabase-go binary is gone, secrets unset needs --all to clear everything, and config push now applies [auth.sms] enable_confirmations as written.

Supabase's stated reason: in v2 some commands defaulted to the linked project and others to local, four flags chose a target, and a flag-less command could reach a production database.

So what for TSD: Any GitHub Action or Vercel build step that runs supabase db push or gen types will either hit the wrong target or fail the next time it installs the CLI. Pin the CLI version in CI today, then migrate each client pipeline deliberately: add --remote --yes to hosted commands, rename [inbucket] to [local_smtp], and re-run db diff once to see what pg-delta changes. The upside is real: the new defaults make it much harder for an agent or a tired human to push a migration at production by accident.

Deprecation Nov 10

Supabase drops a subset of TLS 1.2 ciphers on project HTTP APIs next Tuesday

The changelog says clients that do not support modern cipher suites will fail to connect from Nov 10. Supabase puts the affected share at under 0.0001% of its traffic. Browsers and current Node, Deno and Bun runtimes are fine. The exposure is older embedded devices, legacy PHP or Java hosts calling PostgREST directly, and anything pinned to an old OpenSSL.

So what for TSD: Your Next.js on Vercel sites are unaffected. The one thing to check is any client integration that calls Supabase from outside your stack: a POS, a booking widget on a legacy host, a Zapier-style connector. Ask each client with such a connection to confirm it still works on Nov 10, and have the fix ready (route it through a Vercel function).

◆ Security: the hiring lure

Incident Oct 31 – Nov 3

Binance's $6.3B heist: months inside, three engineers' machines, a fake job interview

Binance's incident report, covered by CoinDesk on Nov 3, says a software engineer was approached in September through a legitimate job platform by someone posing as a project director; the campaign compromised three engineers' computers and the attackers stayed for months before the theft. The FBI attributed the hack to North Korea's TraderTraitor group, the same actors behind last year's $1.5B Bybit theft, said most of the proceeds were converted to Ethereum, and asked exchanges to block the addresses. North Korea called the probe "a trite provocation." Binance says it has replaced 90% of the stolen amount with company money. TechCrunch notes researchers had warned about these exact hiring tactics for years; Binance itself blocked a similar "Contagious Interview" wave on Oct 27.

So what for TSD: You are a one-person shop that holds client keys, so you are the whole attack surface. The lure was a job offer with a "coding test" that runs code on the target's machine. Rule for yourself and for Grant and Bishop: never run a recruiter's repo or installer on a machine that holds credentials. Put that line in the client security one-pager; owners of salons and shops get the same fake-vendor approach by email.
CoinDesk (Nov 3) PBS NewsHour TechCrunch

◆ Platform changes on the stack

Vercel Nov 3–4

Workflow SDK gets idempotent starts; Vercel CI no longer needs a linked project; vercel doctor

Nov 4: Workflow SDK start() can claim a hook token atomically; duplicate starts with the same token throw HookConflictError and never become a run. Nov 3: Vercel CI works standalone without a Vercel project, and a new vercel doctor command checks CLI version, login, team, project link and vercel.json and suggests fixes. (Vercel Security Review's public beta was covered yesterday.)

So what for TSD: Idempotent starts are the fix for the double-fire you get when a Stripe or Twilio webhook retries: pass the event ID as the hook token and the second delivery is a no-op. Worth adopting in Booking Bridge. Run vercel doctor before the next scope mix-up; it prints the team and project link you are about to deploy to.
Vercel changelog
Cloudflare Nov 4

AI Gateway model aliases, and per-agent access policies for personal AI agents

Model aliases let an app call a pool of models by one name such as custom/support-fast; the gateway tries them in order, falls back on failure or uses smart routing, and you can swap models without redeploying. Separately, "Configure AI bot policies" is now "AI Crawler and Agent access policies," and the top personal agents (ones that browse or fetch on a person's behalf) can be allowed or blocked individually under Security > Settings. The same day's changelog also lists a Browser Isolation beta that blocks data entry while keeping search, copy and zoom.

So what for TSD: Two client conversations in one changelog. First, for any client whose site sits behind Cloudflare, decide on purpose whether shopping and research agents may read their catalog; the default now has a switch, and "let agents in" is a lead-gen setting for a retailer like Bisque. Second, model aliases are a cheap way to give Concierge a fallback model without a code change.
