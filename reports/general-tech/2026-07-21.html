◆ Patch this, watch that

Pending Checked 07:30 ET, Jul 21

The first scheduled Next.js security release has now slipped twice and had not published at filing time

Vercel appended a note to its July 13 announcement: "The July security release originally targeted for July 20 is now expected on July 21, 2026." Checking npm directly this morning, the latest tag on next is 16.2.10 (published July 1) and the backport tag is 15.5.20 (also July 1). The most recent publish of any kind was a 16.3 canary late last night. Nothing security-related has landed.

What is known and unchanged: the release covers the 16.2 and 15.5 lines and fixes 4 high and 5 medium severity issues. CVE identifiers and technical details publish only once the patch is out — that's deliberate, so advance notice arms defenders without handing attackers a target list. The 13.x and 14.x majors are not on the list; in the May coordinated release those majors got no back-patches and users were told to move to a patched 15.5.x or 16.2.x.

So what for TSD: Do nothing yet, and check again this evening. Concretely: run npm view next dist-tags — when latest moves off 16.2.10 or backport moves off 15.5.20, read the blog post, then bump and redeploy every client project on 16.2/15.5 the same night. Any project still on 13.x or 14.x doesn't get a patch at all, so schedule the major upgrade now rather than discovering it under pressure. Don't act on version numbers from a secondhand blog; several are already circulating and none of them are official.

Patch now Jul 2026

Two RabbitMQ flaws leak OAuth client secrets and expose cross-tenant queue metadata

CVE-2026-57219 (CVSS 8.7): an obsolete GET /api/auth management endpoint returns the client secret on any installation configured with the management.oauth_client_secret key. Unlike every other sensitive management endpoint, its authorization check was hard-coded to always allow the request. An attacker exchanges the secret for an administrator token and owns every message, queue, user and broker setting. The bug has been present since 3.13.0 shipped in early 2024.

CVE-2026-57221 (CVSS 5.3): any authenticated user who can reach a virtual host can enumerate every queue and exchange name in it and read message and consumer counts, regardless of their actual permissions. Fixed in 4.3.0, 4.2.6, 4.1.11, 4.0.20 and 3.13.15. No evidence of exploitation before disclosure. Beyond patching: rotate the OAuth client secret if the management UI is internet-reachable, and firewall port 15672.

So what for TSD: You don't run RabbitMQ, so the direct exposure is zero — but check any client stack you inherited during a migration, because a legacy PHP or Java app with a message broker bolted on is exactly where a 2024-era RabbitMQ hides. The reusable lesson is the shape of the bug: an old endpoint nobody removed, with an auth check that was never wired up. Worth a grep through your own Supabase edge functions and API routes for handlers that were built before you added auth middleware.

◆ Your stack

Feature Jul 20, 2026

Vercel let you choose where Workflows keeps run state, and gave Turborepo a Remote Cache purge

Two shipped July 20. Configure where run state lives in Vercel Workflows means a durable workflow's state no longer has to sit wherever the platform put it by default. Purge your Remote Cache's build and CI artifacts gives Turborepo users a way to clear a poisoned or bloated cache without support tickets.

That follows a busy July 17: Sandbox data downloads became free, runtime logs started showing the reason behind each cache decision, immutable static assets got CDN caching improvements, Chat SDK added native Slack agent support, and the Vercel plugin gained Kimi Code CLI support.

So what for TSD: The cache-purge is the one you'll use. Next time a client deploy serves stale output and you can't work out why, purge the Remote Cache instead of burning an hour bisecting. And the runtime-log cache reasons from the 17th are the fastest way to prove to a client that their site is actually being cached at the edge — screenshot material for a performance report.

Improve Jul 2026

Supabase's July developer update: binary Realtime payloads, audit log drains, one-click Connect

Realtime Broadcast now carries binary payloads alongside JSON, which cuts encoding overhead for things like telemetry and live screenshot streams. Audit Log Drains stream a project's audit logs to an external destination. Connect copies every environment variable @supabase/server needs in a single click. @supabase-labs/tanstack-db is in alpha for syncing TanStack DB collections over PostgREST and Realtime, and Wrappers v0.6.2 can query and join MongoDB collections from Postgres.

Two defaults to know: Postgres log_connections is now off for new projects on all tiers as of July 9, with existing Free and Pro projects being migrated, and pg_graphql v1.6.2 ships with schema introspection off by default.

So what for TSD: If a client build uses GraphiQL or GraphQL codegen against Supabase, introspection being off by default will break your tooling on the next project you spin up — enable it per schema. Audit Log Drains are the cheap version of a compliance story: any client who asks "who can see my data" now gets a real answer for the cost of pointing a drain somewhere.

◆ Silicon and the buildout

New Jul 16–20, 2026

TSMC put another $100B into Arizona and raised capex, days after the chip index entered a bear market

TSMC committed an additional $100 billion to Arizona for at least four more 2nm-or-better fabs, taking its total US investment to $265 billion across 10 fabs, two advanced packaging facilities and an R&D center. 2026 capex guidance went from $52–56B up to $60–64B. When the announced fabs are complete, roughly 30% of TSMC's 2nm-and-below capacity will sit in Arizona. The CFO said on July 20 that the company is accelerating the build-out on an AI "megatrend."

The timing is the story. The Philadelphia Semiconductor Index closed in a bear market on July 17 after Moonshot's Kimi K3 landed. The company closest to the actual demand signal is spending harder while the market marks the sector down more than 20%.

So what for TSD: No trade here, and don't try to have one. The operating read is that inference capacity keeps getting cheaper and more abundant on a multi-year schedule, which is the single assumption underneath every AI product you sell. Build offers that get better as tokens get cheaper — a receptionist that answers more calls, a concierge that reads more pages — rather than offers that depend on scarcity.
