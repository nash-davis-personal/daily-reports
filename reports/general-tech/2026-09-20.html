◆ The dev platform Nash actually ships on

New September 18

Vercel shipped WebMCP in mcp-handler

Experimental WebMCP support in mcp-handler exposes an application's MCP tools to browser-based agents without a separate OAuth configuration. The same changelog day added Spend Management for Enterprise Flexible Commitment plans, with email alerts, webhooks and optional pausing of production deployments; npm credential support in v0, which now reads NPM_TOKEN and NPM_RC to install private packages from custom registries; and Z.ai's GLM 5.3 FlashX on the AI Gateway at 200 tokens per second behind one API key with automatic fallbacks, spend tracking and request traces.

The day before brought sub-second static artifact deployments in the Vercel CLI, per-deployment Turbo build machines as an opt-in cost control, Harbor 0.22.0 evals running Terminal-Bench inside Vercel Sandbox microVMs, and Notion-hosted skills installable through the skills CLI without a Git repo.

So what for TSD: WebMCP is the first cheap way to make a client site do something useful when an agent shows up instead of a person. Build one this week on a demo site — a "check availability and book" tool — record an agent using it, and that video is the entire pitch for a new productized service. The GLM 5.3 FlashX gateway entry is also worth a look for the cheap lane of Nash's own agent stack.

Housekeeping Current as of September 20

No new Next.js advisory this window — confirm you are on the patched floor anyway

Nothing new landed on Nash's stack between September 12 and 20. The framework's most recent stable release is 16.3.5, published September 11 on the LTS branch. The standing patch floors from earlier in the year remain the ones that matter: the React Server Components denial-of-service and source-exposure issues tracked as CVE-2026-23864 and CVE-2026-23869, patched in Next.js 15.5.16 and 16.2.5 alongside react-server-dom-* 19.0.6, 19.1.7 and 19.2.6; the August security release requiring 16.3.3 or 15.5.24; and CVE-2026-44578, the 8.6-CVSS SSRF in the WebSocket upgrade handler that affects self-hosted Next.js on the built-in Node server from 13.4.13 up to 15.5.16 and 16.2.5.

Vercel-hosted applications are not affected by the SSRF, and Vercel's WAF carries rules for the RSC denial-of-service class.

So what for TSD: Run npx next --version across every client repo and confirm nothing is below 16.3.3 or 15.5.24. Anything Nash self-hosts on a plain Node server is the real exposure, since the Vercel-hosted sites are covered by the platform WAF. Ten minutes of checking beats explaining an SSRF to a client.

◆ Silicon, and the money behind it

Supply chain September 20

CXMT reached mass production on fifth-generation DRAM

China's CXMT is in mass production on 11.95nm fifth-generation DRAM, with die yield per wafer up more than 50% against the previous generation. That gives Chinese manufacturers a second sourcing option for memory at a moment when AI demand has made memory the tight part of every bill of materials.

The contrast on the other side of the same market is stark. South Korea posted $59.98 billion in August ICT exports, up 162.6% year over year, with $46.67 billion of that in chips, up 209%. Infineon agreed to sell its NOR flash and F-RAM businesses to Winbond for $1.12 billion in cash to concentrate on core lines. Huawei used its Connect conference to lay out a 2027 roadmap: Ascend 960DT in Q1 and 960PR in Q3, both on its UnifiedBus interconnect.

So what for TSD: Memory prices set the floor under every laptop, phone and server Nash or his clients buy for the next two years. A second high-volume source is the only thing that caps that. No action today; it is the variable to watch before quoting any hardware-inclusive project.

Markets September 14

SoftBank borrowed $11.87 billion and the chip trade wobbled

SoftBank secured an $11.87 billion two-year loan and its stock fell 13%, the worst single-day drop since mid-July, against a stated plan to put $65 billion into OpenAI by October. Nvidia, Intel, Marvell and Micron all fell the same session, with Nasdaq 100 futures down more than 1.5% and TSMC off roughly 2%.

The same day, Microsoft circulated a draft AI code of conduct framework and several lab chiefs publicly called for slower frontier development — a pairing that made the session read as a referendum on how much debt the buildout can carry.

So what for TSD: The AI buildout is now financed with borrowed money at a moment when the Fed is raising rates. That does not change what Nash builds; it changes how he prices. Favor retainers a client can cancel monthly over large fixed-scope projects that need a credit decision on the buyer's side.

◆ Security: the attacker had an agent

Breach September 18

An AI agent executed a complete login, probe and exfiltration chain

Spain's data regulator received a breach notification describing an AI agent that identified system vulnerabilities, accessed a system, modified personal information and viewed billing records. The investigation is open. In a separate incident the same day, security researchers reached an OpenAI employee's ChatGPT account by way of a weakness in a third-party-hosted community forum.

The rest of the week's list is conventional and still expensive. Check Point Security Management and Log Servers carry a critical flaw allowing remote code execution with root privileges. CVE-2026-58138 is an unauthenticated RCE exploitable through inline workflow definitions. Microsoft patched across Azure and its AI-branded products, mostly privilege escalation. Revolut disclosed a customer data breach against a base of more than 80 million. Identity-verification provider IDScan confirmed a third party may have accessed customer information in its cloud. And a RubyGems supply-chain attack first seen in May, in which AI agents uploaded hundreds of malicious packages, surfaced publicly this month.

So what for TSD: Two concrete jobs. First, audit Nash's own third-party account surface — the forums, community tools and SaaS logins attached to work email are now a credible path into a client system. Second, lock dependency versions and scan on install in every repo; the RubyGems pattern will repeat on npm, and a poisoned package in a client build is the one mistake the money-back guarantee cannot cover cheaply.
