◆ Desktop and daily driving

Fix 2.1.317

Project MCP servers stop dropping, and project effort settings stick

Two desktop fixes land together. Project and local MCP servers were disconnecting after the first turn in some Claude desktop sessions; that's fixed. A project's effortLevel setting was also being ignored by sessions an app pre-starts and then opens in the project, which the changelog names as new sessions in the desktop app's Code tab.

Related: Claude Desktop's Code tab now shows a notice when an organization's remote managed settings haven't loaded for the session, and another once they do.

So what for TSD: You run nearly everything from the Code tab with a long MCP list. If Supabase, Vercel or tsd-portal tools have gone missing mid-session in a client repo, update and retest before blaming the server config. Any project you set to a fixed effort level now gets it from the first turn.
Changelog, 2.1.317
Changed 2.1.317

The Read tool returns content on every read

Claude Code removed the Read tool's "file unchanged since your last Read" stub. Reading an unchanged file again now returns its content. A separate fix stops resumed sessions telling Claude again about a file change it already knew about.

So what for TSD: Long sessions on Bisque or Sonderwerks code where context got compacted could leave Claude holding a stub with nothing behind it. Re-reads now give it the real file, so fewer edits built on a stale picture. Expect slightly higher token use on repeat reads.
Changelog, 2.1.317

◆ Agents and automation

New 2.1.317

Agent SDK hooks get onFailure: "block"

Agent SDK hook callbacks accept onFailure: "block". With it set, a callback that fails blocks the action. Without it, a crashed or erroring guard lets the action through.

So what for TSD: Any client agent you build on the SDK with a guard hook (no refunds over a limit, no writes to the live Supabase table, no outbound SMS without approval) should set this. A guard that fails open is a liability you'd be selling. Add it to the agent starter template.
Changelog, 2.1.317
Improved 2.1.317

Scheduled tasks: connector warning, plus loop and listing fixes

/schedule now warns when a new cloud scheduled task gets connectors you did not ask for, and says how to remove them. It also now includes the next run time and link in its results after creating or updating a task. Self-paced /loop wakeups were sometimes not scheduled when Claude left a field out of its request; fixed. Stored scheduled tasks could not be listed or deleted after scheduled tasks were turned off; fixed. New cloud scheduled tasks now start on the organization's default environment.

So what for TSD: Your scout runs, Fleet Steward and Nash OS jobs are all unattended. Next time you create a cloud task, read the connector warning and strip Gmail, Square and Stripe from anything that only needs to read and push a repo. Fewer connectors on a robot means less it can break.
Changelog, 2.1.317
Changed 2.1.317

Subagents: faster messages, their own effort level, safer Ctrl+C

A SendMessage to a running background agent arrives earlier: its running command moves to the background and keeps going. Subagents and teammates on a different model from the main conversation now use that model's saved effort level or its default. Ctrl+C used to clear typed text at the prompt and also stop every running background agent; that's fixed. Auto mode now shows a notice when its check has no answer for a subagent's tool call.

So what for TSD: If you fan out Haiku or Sonnet subagents from an Opus session, they no longer inherit your high effort setting, which should make them cheaper and quicker. If a cheap subagent's work looks thin, set that model's effort explicitly. And you can clear the prompt without killing a long build agent.
Changelog, 2.1.317

◆ Privacy and carry-over

New 2.1.317

Claude asks before sending your account email out

Claude Code now asks before a web or shell tool call sends your account email address to the network.

So what for TSD: Expect an occasional new prompt in scripts that pass your tsd-ventures address to an API. Approve it when it's yours on purpose. In unattended runs this could stall a step, so check the next scout logs.

Opus 4.8 fast mode removal is 27 days out

Carried from the previous briefings: fast mode on Opus 4.8 is removed on November 30, 2026, after which those requests error. Nothing in 2.1.317 changes that.

So what for TSD: Still open. Grep scheduled tasks, launchd jobs and client SDK code for pinned Opus 4.8 with fast mode and move them to Opus 5.5.
