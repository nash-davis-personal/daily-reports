◆ Agent reliability: fewer silent stalls

Fix 2.1.268

WebFetch no longer hangs on a server that never finishes

A server that keeps the connection open without completing the response used to leave WebFetch waiting forever. It now fails after 300 seconds by default. CLAUDE_CODE_WEBFETCH_DEADLINE_MS overrides the deadline, and setting it to 0 turns the limit off entirely.

So what for TSD: Any research or competitor-scan task you've handed to an agent — pulling a client's current site, checking a vendor's docs — could stall a whole session on one bad server with zero indication why. Now it fails loud and moves on. Worth knowing the env var exists if you ever need a longer window for a slow but legitimate endpoint.

Fix 2.1.268

MCP tool calls stop returning a fake "empty message" reply

Claude would sometimes reply "your message came through empty" right after a legitimate MCP tool call completed — a rendering bug, not an actual empty response. Fixed. Alongside it, a separate fix stops sustained high CPU usage from a busy loop in long-running idle sessions, and from rapid terminal focus reports during a session recap.

So what for TSD: You run Supabase, Vercel, and nash-os as MCP servers through most of your delivery sessions. A tool call quietly reporting "empty" when it wasn't is the kind of bug that erodes trust in agent output for no real reason — worth knowing it wasn't your MCP config. The CPU fix matters if you leave sessions idle on a laptop; it was pinning a core for nothing.

◆ Code review gets more trustworthy

Fix 2.1.268

A dead verifier no longer kills the whole review

If one of the agents verifying a finding failed midway through, the review used to end as incomplete. It now replaces that agent and still reaches a verdict. Two smaller companion fixes: resolving a finding's comment thread (not just replying to it) is now what stops later reviews from re-counting it as open, and a push-triggered review queued behind another running review no longer posts after the pull request has since been converted to draft.

So what for TSD: If you've used /ultrareview on a client repo and gotten an "incomplete" result with no clear reason, this was a plausible cause — one verifier dying shouldn't have tanked the whole run. And if you resolve findings by just replying instead of hitting resolve on the thread, later runs were still flagging them as open; that's now consistent.

◆ Security and the surfaces you script from

Security 2.1.268

A respawned teammate could borrow an untrusted agent's identity

A respawned in-process teammate could pick up the tools or system prompt of a same-named agent file sitting in a folder you have not trusted. Closed. Separately, permission deny/ask rules on symlinked directories (/etc, /tmp, /var on macOS; /bin on Linux) now apply when a path is given by its real location instead of its symlink spelling, and plugin/marketplace errors and MCP config output no longer print a token, password, or ${VAR}-resolved secret in plain text.

So what for TSD: If you ever run agent teams inside a client repo that has stray agent-definition files you haven't vetted — a cloned template, a fork with leftover config — this closes a real identity-spoofing path. The secret-leak fixes matter if you've ever pasted an MCP error or a plugin log into a client Slack channel or support ticket; check whether older logs you still have around are clean.

Improve 2.1.268

Plugin management is now fully scriptable

--json added to claude plugin install, uninstall, update, enable, and disable; errorDetails and noteDetails now show on every row of claude plugin list --json. Also added: configDirectory in claude auth status --json.

So what for TSD: If you ever standardize plugin setup across a fresh machine or a client's dev environment with a script instead of clicking through /plugin, this is the missing piece — you can now install and verify in one shot with a parseable exit state instead of screen-scraping CLI output.
