◆ Fixes that protect your repo

Fix 2.1.304

claude --worktree could delete a worktree and its branch at exit

Per the changelog, claude --worktree removed the worktree and its branch without asking at exit when HEAD was detached or on another branch, "which could lose commits." That is now fixed. This follows a similar 2.1.301 fix for worktrees made by a WorktreeCreate hook.

So what for TSD: Update before your next parallel-worktree session. If you've used --worktree recently and switched branches or checked out a commit inside one, run git reflog in the main repo to confirm nothing went missing.
Changelog, 2.1.304 bug fixes
Fix 2.1.304

Sandbox no longer chokes on Next.js dynamic-route folders

On Linux, sandboxed commands failed to start when a sandbox.filesystem.denyRead glob contained brackets that aren't a character class. The changelog's own example is a [user-id] route folder. Separately, rm -r of a mounted drive or top-level mount folder (/Volumes, /media, WSL's /mnt/c) now gets the same safety prompt as rm -rf /Applications.

So what for TSD: Every Next.js App Router client build has bracketed folders. If you turned the sandbox off for a client repo because it broke, especially in Linux cloud or CI sessions, turn it back on and retest.
Changelog, 2.1.304 bug fixes

◆ Automation and agents

New 2.1.304

/auto-mode-setup teaches auto mode about your environment

A guided setup that reads your project and recent sessions so auto mode knows your environment. It's also available on Bedrock, Vertex, Foundry, the Claude apps gateway and telemetry-disabled sessions. Auto mode session files also get smaller because the safety classifier's context is no longer stored with every request.

So what for TSD: Run it once in each active client repo (Bisque, Studio C, Sonderwerks). Fewer needless classifier blocks means fewer stalled unattended runs.
Changelog, 2.1.304 added and improvements
Fix 2.1.304

Headless and scheduled runs are better behaved

A plugin could keep a headless run going past --max-turns, Stop, or ended input by spawning subagents or re-running a finished one. That's fixed. Self-paced /loop wakeups set at the 1-hour maximum fired just after the 1-hour prompt cache expired, which meant an uncached re-read each time. That's fixed too. Other changes: responsiveness and throughput are better with many subagents running at once, subagents no longer forget their latest work when messaged right after finishing, and resuming large compacted sessions in SDK and headless mode is faster.

So what for TSD: Your Nash OS hub jobs run headless. The --max-turns fix caps runaway cost on any job with plugins loaded. Hourly /loop jobs should cost less per tick with no changes from you.
Changelog, 2.1.304 bug fixes and improvements

◆ Code Review and usage

Feature 2.1.304

Code Review: Quick / Standard / Deep, and org-wide coverage

Owners pick a review level for the organization (Standard is the default), and individual repositories can have their own. A new admin option reviews every repository in a GitHub organization, including ones added later. PRs opened within a minute or two of enabling Code Review were silently skipped. They are now retried.

So what for TSD: Set Deep on the client repos where a bug costs you money (booking and payment flows) and Quick on internal tooling. Turn on "every repo" so new client repos are covered without you remembering to opt them in.
Changelog, 2.1.304 added
Improved 2.1.304

Warning before an expensive resume on Pro and Max

Resuming an inactive conversation now warns you when it would use a noticeable share of your 5-hour usage limit. You can resume anyway, or start a new conversation where Claude can look up the old one if you refer to it. Related: CLAUDE_CODE_AUTO_COMPACT_WINDOW=200k silently set a 100K window. It now accepts k and M suffixes and warns on bad values.

So what for TSD: When the warning shows, take the new-conversation option. Resuming a cold client session re-reads the whole context at full price. If you set the auto-compact window with a k suffix, check that you've been getting the window you asked for.
