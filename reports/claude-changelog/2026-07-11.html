◆ Speed and daily feel

Fix 2.1.207

The terminal no longer freezes while streaming long output

Streaming a response with a very long list, table, paragraph, or code block would freeze the terminal and make your keystrokes lag. That's fixed. There's a related fix for the transcript jumping above the start of the answer when a response finishes streaming.

So what for TSD: Update to 2.1.207. If you've been watching the cursor stutter through big Supabase migration diffs or full-component rewrites, that stops. Pure throughput win, no config change needed.

◆ Unattended runs and security

Security 2.1.207

Headless and SDK runs were auto-consenting to managed settings

Remote managed settings applied from a non-interactive run — claude -p or the SDK — were being permanently recorded as consented without the security consent dialog ever appearing. The dialog now gates those runs the way it does interactive ones.

So what for TSD: Your daily scheduled tasks and Fleet Steward loops run through exactly this surface. If any managed settings are in play for your setup, update and verify what got auto-consented before this fix landed. If you don't use managed settings, this is a non-event — but worth knowing the gap existed.
Claude Code changelog — 2.1.207
Fix 2.1.207

Benign system updates stop triggering prompt-injection warnings

Spurious prompt-injection warnings were firing on benign, system-generated conversation updates. Those false alarms are gone. Same build also hardens plugin shell handling: ${user_config.*} in shell-form hook/monitor/headersHelper commands is now rejected as a shell-injection vector — use exec form or $CLAUDE_PLUGIN_OPTION_<KEY>.

So what for TSD: Fewer false alarms mid-run means one less thing to babysit in unattended jobs. If you author plugins with shell-form commands that interpolate config, they'll now be rejected — move to the exec form or read the value inside the script.
Claude Code changelog — 2.1.207

◆ Config changes that can silently break your setup

Fix 2.1.207

Auto-updater stops overwriting a custom launcher

The auto-updater was overwriting a custom launcher script or symlink at ~/.local/bin/claude on every release. It now leaves an externally managed launcher alone, and /doctor reports when one is in place.

So what for TSD: You run custom launchd wiring across two Macs. If you ever symlinked or hand-wrote the claude launcher, every update was quietly clobbering it. Update, run /doctor, and confirm the launcher line reads the way you expect on both machines.
Claude Code changelog — 2.1.207
Breaking 2.1.207

Auto mode and plugin options no longer read from repo-level settings

Auto mode no longer reads autoMode from a repo-resident .claude/settings.local.json — use ~/.claude/settings.json. Separately, plugin option values (pluginConfigs) are no longer read from project-level .claude/settings.json; only user settings, --settings, and managed settings are honored.

So what for TSD: If auto mode or any plugin option currently lives in a project's local or checked-in settings, it stops working with no error. Grep your client repos (Bisque, Studio C, Sonderwerks) for autoMode and pluginConfigs and hoist anything you rely on into ~/.claude/settings.json.
Claude Code changelog — 2.1.207

◆ Loops, worktrees, and background agents

Fix 2.1.207

Agent-teams crash loop and a worktree config leak, both fixed

A malformed teammate mailbox message in agent teams could trigger repeated errors every second until you manually deleted the mailbox file — that crash loop is fixed. Separately, extensions.worktreeConfig was being left in the repo's .git/config after the last worktree.sparsePaths worktree was removed, which broke go-git tools like tea; it's now cleaned up. Two background-session bugs also got patched: auto-named sessions not showing their name in the agent view, and worktree-entered sessions resuming blank after a cold reopen.

So what for TSD: These are the exact failure modes that bite loop-style automation running in isolated worktrees. If you've had a background agent go blank on resume or a loop wedge on a bad mailbox message, 2.1.207 removes those. Worth updating before the next unattended cycle.
