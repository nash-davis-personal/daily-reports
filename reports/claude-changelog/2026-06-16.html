◆ Config scoping & permissions

Improve 2.1.178

Per-directory .claude/ now resolves to the closest config

When a name collides, the agent, workflow, and output-style nearest the working directory wins, and project-scope workflow saves now target the closest existing .claude/workflows/. Skills in nested .claude/skills directories load when you work on files there; on a clash the nested one appears as <dir>:<name> so both stay reachable.

So what for TSD: You run a dozen project folders out of ~/Documents, each with its own .claude/. A skill or workflow named the same thing in Praxis and the TSD app will no longer step on each other — the one in the folder you are in takes priority. Worth dropping client-specific skills (e.g. a Bisque catalog helper) straight into that repo's .claude/skills now that scoping is reliable.
Changelog · 2.1.178
Feature 2.1.178

Permission rules can match a tool's input parameters

New Tool(param:value) syntax (with * wildcard) lets a permission rule key off what the tool is actually called with. The documented example is Agent(model:opus) to block Opus subagents.

So what for TSD: Cost control for your scheduled tasks and multi-agent runs. If a routine should never burn Opus on a subagent, a single deny rule now enforces it instead of trusting the prompt. Same lever for pinning which models your daily-report and Macroscope automations are allowed to reach.

◆ Agents & subagents

Improve 2.1.178

Auto mode evaluates a subagent before it launches

Subagent spawns now pass through the classifier before launch. That closes a gap where a subagent could request a blocked action without ever being reviewed.

So what for TSD: If you ever run the fleet in auto mode for unattended builds, this is the difference between trusting and verifying. A spawned agent can no longer route around your permission setup by being a child process. Safer to leave overnight workflows running.
Changelog · 2.1.178
Fix 2.1.178

Subagent transcripts, messages, and ctrl+b backgrounding all repaired

Three fixes in one: viewing a subagent's transcript now shows tool results and live progress, messages you send while it finishes its turn are no longer dropped, and backgrounding a running subagent with ctrl+b no longer restarts it from scratch.

So what for TSD: You lean on subagents and the Workflow tool for fan-out (the 66-agent Macroscope build, fleet security sweeps). Being able to actually watch a subagent's tool calls and background it without losing progress makes those runs debuggable instead of a black box.
Changelog · 2.1.178

◆ Long-session & auth reliability

Fix 2.1.178

Compaction falls back instead of failing

Compaction now honors --fallback-model: on an overload or model-availability error it walks the configured fallback chain instead of dying. A separate fix stops model requests from continuing to fail with auth errors after credentials were refreshed outside the session (a stale cached request config).

So what for TSD: Long marathon sessions — Carolina Ring, the RV master plans, anything where context fills up — used to risk a dead compaction when Opus was busy. They now degrade gracefully. Set a fallbackModel chain if you have not, so the overnight builds ride through capacity blips.
Changelog · 2.1.178
Fix 2.1.178

Claude in Chrome stops silently failing on the wrong account

When the Chrome OAuth token belonged to a different account than your Claude Code login, the connection would silently never establish. That now surfaces correctly. A related crash — an out-of-memory exit when the CLI inherited a stale websocket/OAuth file descriptor from a parent process — is also fixed.

So what for TSD: You verify front-end work through the browser preview and Chrome tools. A silent Chrome connect failure reads as "the tool is broken" when it is really an account mismatch — now you get told. If Chrome automation has been flaky, update before re-debugging.
