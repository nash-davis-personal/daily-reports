The claude-api skill dropped from ~200k tokens to ~25k

Reference docs now load on demand instead of all at once. That skill fires on nearly any Anthropic-API-shaped task, so it has been quietly eating most of a context window every time it triggered.

02

Sessions continue automatically when a usage limit resets

Hit the claude.ai limit mid-build and the session picks itself back up at reset instead of sitting dead. Toggle lives in /config under "Continue automatically at usage limit".

03

/goal stops hanging on dead turns and stalled background work

A goal now clears itself with a notice when a turn dies on revoked auth, exhausted credits or context overflow, and Claude checks in on background tasks that have kept a goal waiting 30+ minutes.

04

MCP diagnostics no longer print resolved secrets

Scope-conflict warnings now show the configured ${VAR} form and connection-failure details show only the server origin. Credential masking on relayed permission previews was tightened in the same release.

05

Session restarts stop dropping your permission flags

Accepting the fullscreen-renderer prompt used to restart the session without its permission mode, tool allow/deny rules, model or effort flags. /tui had the same problem with launch-time tool rules.

06

/permissions and /add-dir now open mid-turn

Rule changes apply to the rest of the current turn, so you can widen or tighten permissions without killing work in progress. /autocompact, /theme, /help, /config and /advisor also open mid-turn in the fullscreen TUI.

◆ Context and throughput

Improve 2.1.234

The bundled claude-api skill costs an eighth of what it did

The changelog puts the reduction at "~200k+ tokens to ~25k", achieved by loading reference docs on demand rather than up front. This is the single largest context change in the release.

The skill's own trigger rules are broad: it is supposed to load before you touch anything Anthropic-API-shaped, including agent, MCP and tool-definition work where the provider is not even stated. On a 200k baseline that meant one skill load could crowd out the actual codebase.

So what for TSD: Any session where you are wiring Claude into a client build — the Sonderwerks intake agent, anything touching the Anthropic SDK — just got most of its working context back. If you had been avoiding the skill or manually working around it to protect context, stop working around it.
Claude Code changelog — 2.1.234
Feature 2.1.234

Usage-limit resets resume the session for you

When a claude.ai usage limit resets, Claude Code now continues the session automatically. It is on by default with an opt-out in /config.

So what for TSD: Relevant to your unattended jobs specifically. A scheduled task that hit the limit used to die there and you found out later; now the run picks back up on its own. Worth deciding deliberately whether you want that on for automated runs, because a job resuming hours later still writes and pushes whatever it was doing.
Claude Code changelog — 2.1.234
Fix 2.1.234

Two long-session bugs that were costing you approvals

Auto mode had been repeatedly re-checking and denying sandboxed commands' network access after a conversation was compacted. Separately, session-scoped permission answers, including denies, were being dropped when you answered a background subagent's tool permission prompt.

So what for TSD: Both bit hardest in the long agent-heavy sessions you run on client builds. Answers you gave once should now stick past a compaction and past a subagent prompt, which cuts the interruption tax on anything you leave running.

◆ Secrets, permissions and trust

Fix 2.1.234

MCP diagnostics were printing resolved secrets

Scope-conflict warnings now display the configured ${VAR} placeholder rather than the resolved value, and connection-failure details are cut back to the server origin.

The same release tightened masking on relayed permission previews twice: credential masking could previously hide the command, path or destination from the person approving it, and provider API tokens failed to mask when followed directly by a shell delimiter.

So what for TSD: You run a wide MCP surface with live keys in it (Supabase, Vercel, Vapi, Upstash, Higgsfield). Anything you pasted from an MCP error into a chat, a note or a client thread before this release may contain a real secret. Skim recent debugging output before you assume it was already redacted.
Claude Code changelog — 2.1.234
Fix 2.1.234

Restarts no longer silently downgrade your permission mode

Accepting the "Try the new fullscreen renderer?" prompt restarted the session without its permission mode (including --dangerously-skip-permissions), tool allow/deny rules, model or effort flags. /tui dropped launch --allowed-tools and --disallowed-tools rules on restart; it now refuses to switch and tells you why when the session has restrictions a restart cannot carry.

So what for TSD: This cuts both ways and the second direction is the one to care about. A session you launched with narrow tool rules could quietly come back wide open after a restart. If you use launch flags to fence an unattended run, re-verify the mode after any renderer or /tui switch.
Claude Code changelog — 2.1.234
Improve 2.1.234

Windows NT-path hardening finished, and marketplace allowlists closed a host gap

Remote file reads, session restore, CLAUDE.md includes, workflow scripts and file uploads now reject Windows NT-namespace (\??\) paths, closing the remaining pre-approval file accesses against the NTLM credential-leak vector that 2.1.233 started on. Separately, strictKnownMarketplaces allowlists were accepting SCP-style git marketplace sources whose host differed from the one git would actually connect to.

So what for TSD: The NT-path work is a Windows vector and you are on darwin, so it is background. The marketplace allowlist bypass is the one worth noting if you ever pin plugin sources for a client machine.

◆ Agents, goals and Remote Control

Improve 2.1.234

/goal gets two failure modes it was missing

A goal now clears itself with a notice when a turn dies on an unrecoverable error such as revoked auth, an exhausted credit balance or a context overflow, instead of staying armed. And when background tasks keep a goal waiting 30+ minutes, Claude checks in on them rather than waiting indefinitely. Opt out with CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0.

So what for TSD: This is the loop-engineering failure mode you have been designing around by hand. A stalled background task no longer parks an unattended run forever, which removes one of the reasons your loops need an external timeout brake.
Claude Code changelog — 2.1.234
Fix 2.1.234

Cross-session messaging stops failing silently

Claude Desktop inter-session messages were being silently dropped by the recipient when cross-session messaging read as disabled, leaving the sender's query "thinking" for many minutes. SendMessage also stopped rejecting recipients copied out of ListAgents when the session name hit the 200-character cap or was emoji-heavy, and both tools now say when your account's session list was too long to check completely rather than treating unseen sessions as absent.

So what for TSD: If you tried multi-session agent coordination, hit a hang, and wrote the feature off, that was probably this. Worth one retry before you keep building around it.
Claude Code changelog — 2.1.234
Improve 2.1.234

Remote Control syncs state to phone and web properly now

Sessions hosted from Claude Code Desktop or VS Code keep phones and claude.ai/code current on permission mode and model as they change, effort picks made on a phone or on claude.ai/code apply back to terminal- and Desktop-hosted sessions, and files sent to you during a Remote Control session now actually upload instead of showing an empty card. Signing this computer into a different claude.ai account or org now stops the running session within seconds with a reason, replacing a misleading HTTP 404 hours later.

So what for TSD: Checking a running build from your phone between client stops is now a real workflow. The empty-card bug was the thing making it useless for reviewing generated output on the road.

◆ Terminal workflow

Feature 2.1.234

Dialogs open mid-turn, including /permissions and /add-dir

/permissions can be opened while Claude is working and rule changes apply to the rest of the current turn. /add-dir <path> works mid-turn too, and /add-dir, /autocompact, /theme, /help, /config and /advisor all open mid-turn in the fullscreen TUI.

So what for TSD: Adding a sibling directory mid-task is the common one for you — pulling the vault or a second repo into scope without restarting a session you have already spent context building up.
Claude Code changelog — 2.1.234
Fix 2.1.234

Queued input and ! shell mode got a cleanup pass

Five separate fixes: queued messages no longer reappear in prompt history while still queued, Esc while selecting a queued message no longer interrupts the turn, ! mode no longer sticks after a mid-turn submit, a queued ! command edited with up-arrow no longer gets sent to the model as plain text, and dialogs opened while a ! command was running no longer get dismissed when it finishes.

So what for TSD: The up-arrow one was the dangerous one. A queued shell command silently becoming a chat message means the command never ran while you believed it did.
Claude Code changelog — 2.1.234
Improve 2.1.234

Transcript rendering and session titles

Your own prompts now render markdown in the transcript the same way replies do, with highlighted code blocks, inline code and lists. Auto-generated session titles now read as short specific names such as "Login button bug" instead of sentences restating the request.

So what for TSD: Cosmetic, but the title change matters once you have a dozen parallel sessions across Bisque, Studio C and Sonderwerks and are picking one out of a list.
