Claude Code Changelog ◆Tuesday, August 25, 2026 ◆2 releases ◆ 2.1.243 and 2.1.245

2.1.243 lands 60 entries, and the ones that matter to you all fix unattended runs that used to fail without saying so.

Three separate bugs were killing scheduled and non-interactive sessions in silence: a request the API never answered could sit for 10+ minutes with no timeout, remote MCP servers in -p and SDK sessions never came back after a dropped connection, and background subagents did not wake when their last background Bash task finished. All three are fixed in one release. The same release adds a per-loop cost breakdown to /usage, which is the first way to see which of your scheduled jobs is actually burning tokens.

◆ Unattended runs stop failing quietly

Fix 2.1.243

A request the API never answered had no timeout at all

The entry describes sessions going silent for 10 or more minutes when the Anthropic API never started a response. There was no ceiling on the wait. The client now gives up after about 3 minutes, retries once, and then prints API Error: No response from API.

The distinction that matters is between a job that is slow and a job that is dead. Before this, both looked identical from the outside.

So what for TSD: This is the most likely cause of any scheduled task of yours that "just didn't run" and left no error behind — this changelog job included. Take the update, then stop treating a missing report as a logic bug until you have checked for the new error line.
Claude Code changelog — 2.1.243
Fix 2.1.243

Remote MCP servers in non-interactive and SDK sessions never reconnected

Once a remote MCP connection dropped inside a -p or SDK session, it stayed dropped for the life of the run. The server now reconnects automatically, or reports as failed so the session knows the capability is gone.

An interactive session gives you a chance to notice and restart. A headless one silently completes the job with a tool missing and produces a result that looks finished.

So what for TSD: Every scheduled job you run that touches Supabase, Vercel, or Notion through a remote MCP was exposed to this. A run that quietly lost its Supabase connection halfway through would still have written you a confident report. Worth re-reading the last week of scheduled output before trusting anything load-bearing in it.
Claude Code changelog — 2.1.243
Fix 2.1.243

Background subagents stalled after their last background Bash task completed

The wake signal was not firing, so a subagent whose final background command had already finished stayed asleep. The work was done and nothing picked it up.

The same release also fixed cloud sessions resuming after a mid-turn restart with a pending hook or background-task notification re-sent as the prompt instead of the normal continuation message, which is a second way a resumed run went off the rails.

So what for TSD: Directly relevant to any fan-out you run where agents kick off builds or migrations in the background. If a fleet run has ever finished with one agent's work missing and no error, this is the entry to point at.
Claude Code changelog — 2.1.243
Improve 2.1.243

--agents now exits with an error on invalid JSON instead of ignoring it

Invalid JSON or an invalid agent definition passed to --agents was silently dropped. It now fails loudly, matching how --mcp-config already behaved.

So what for TSD: If you script agent definitions into a scheduled run, a typo used to mean the run proceeded with the default agent and never mentioned it. After updating, a job that used to "work" may start failing — that failure is the truth, and it is telling you the definition was never loading.

◆ You can finally see what the loops cost

New 2.1.243

/usage gained a per-loop breakdown

The new section reports run count, total tokens, tokens per run, and last run for each loop. The changelog frames it as a way to spot runaway or chatty /loop tasks.

Tokens per run is the useful column. A job that costs a little and runs constantly and a job that costs a lot and runs daily look the same in a single total.

So what for TSD: Run /usage right after updating and read the tokens-per-run column for every scheduled job you have accumulated. Your automation surface has grown faster than your visibility into it, and this is the first cheap audit available.

◆ The client gets meaningfully lighter

Improve 2.1.243

Memory, startup, and download size all improved in one pass

Native builds load code on demand instead of holding the whole bundle resident, which the changelog puts at roughly 40–70 MB less memory per session. Peak memory in long-running sessions is down because the runtime garbage-collects sooner as the heap grows. Startup no longer blocks the first frame on sandbox and MCP bring-up, bare launches skip subcommand registration, and the auto-update binary is zstd-compressed to about 75 MB from about 340 MB on Linux x64.

Note the memory figure is per session. The saving scales with how many you keep open.

So what for TSD: You run parallel sessions across client repos on one Mac, so 40–70 MB each is the difference between comfortable and swapping. This is the single best argument for taking the update today rather than at the end of the week.
Claude Code changelog — 2.1.243
Improve 2.1.243

/loop collapses consecutive do-nothing wake-ups into one line

A loop that wakes up with nothing to do used to print every one of those wake-ups. They now fold into a single terminal line.

So what for TSD: Makes a long-running watch loop readable again, which means you will actually notice the wake-up where something did happen.

◆ Config traps and one pricing change

Fix 2.1.243

Hook if conditions matched commands they were never meant to match

A condition like Bash(cat *) fired on unrelated Bash commands whenever the command contained $() or backtick command substitution followed by further arguments. The hook ran on input its author never scoped it to.

Which direction that cuts depends entirely on what the hook does. An over-firing logger is noise. An over-firing gate or rewrite is a correctness problem you would have had no reason to look for.

So what for TSD: Read every if condition in your settings.json hooks once after updating and ask what the hook did on the runs where it fired wrongly. Anything that mutates, blocks, or writes deserves the closer look.
Claude Code changelog — 2.1.243
Changed 2.1.243

Sonnet 5's $2/$10 per Mtok is now its standard list price

The /model picker and the bundled claude-api skill now present $2/$10 per Mtok as Sonnet 5's standard list price rather than a limited-time promotional rate.

The number did not move. What moved is whether you can plan around it.

So what for TSD: This is the one entry today with a direct line to client pricing. Any AI feature you have quoted on Sonnet 5 token cost — Bisque, Studio C, Sonderwerks — can now be modeled at $2/$10 without a promo-expiry caveat in the proposal.
Claude Code changelog — 2.1.243
New 2.1.243

promptCacheTtl and subagentPromptCacheTtl settings

API-key and cloud-provider users can hold a 1-hour prompt cache on the main conversation while subagents stay at the 5-minute default. The split matters because subagents are short-lived and a long TTL on them buys nothing.

So what for TSD: Applies to work you run through an API key rather than your Claude account. If any client-side agent you have shipped re-sends a large system prompt on a slow cadence, this setting is the cheapest cost reduction on the list.
Claude Code changelog — 2.1.243
Changed 2.1.243

The sandboxed Bash prompt stopped listing allowed network hosts

Claude no longer sees the allowlist, so it attempts requests and you approve new hosts as they come up, instead of assuming an unlisted host is blocked. The same release also fixed sandbox network-violation details being dropped from the Bash result when the blocked command still exited 0 — a curl printing the proxy's 403 page, for example.

So what for TSD: Expect more host-approval prompts in sandboxed work at first. The 403-exiting-0 fix is the one to care about: a build step that "succeeded" while quietly fetching nothing is exactly the failure that reaches a client deploy.
