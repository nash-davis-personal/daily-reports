Claude Code Changelog ◆Wednesday, August 26, 2026 ◆1 release ◆ 2.1.246

Your Bash allowlist probably matches more commands than you think, and 2.1.246 now warns you about it at startup.

A rule like Bash(git * main) also matches options inserted before the subcommand, so it approves a wider set of commands than it reads like it does. Claude Code now flags those rules on startup, and separately it now always asks before running a malformed command with a dangling && or ||. The rest of this 61-entry release is cleanup, with the useful half aimed at background sessions that failed to start and at one retention bug that deleted git worktrees you created yourself.

◆ Permission rules were approving more than they read like

New 2.1.246

Startup warning for Bash allow rules with a wildcard before the subcommand

The changelog's example is Bash(git * main). The wildcard sits before the subcommand, so the rule also matches commands where options were inserted there. Anything the wildcard swallows is pre-approved. Claude Code now surfaces a warning at startup listing rules shaped this way.

This pairs with the hook if condition bug fixed in 2.1.243, where Bash(cat *) fired on unrelated commands containing $() or backticks. Two releases in a row have found the same class of problem in pattern matching against shell strings.

So what for TSD: Open every settings.json you maintain — global, per-repo for Bisque, Studio C, Sonderwerks, and anything the scheduled tasks run under — and grep for allow rules with a * ahead of the subcommand. Rewrite them so the wildcard only ever appears after the subcommand you actually meant to allow. Do this before updating, so you know what the startup warning is going to complain about.

Fix 2.1.246

Malformed commands with a dangling operator now always need approval

Bash permission checks now always require approval for a command that ends with a hanging && or ||. Previously the parser's handling of those was inconsistent enough that the check could be bypassed.

So what for TSD: Relevant to any unattended run using --dangerously-skip-permissions or a wide allowlist, which describes most of your scheduled jobs. Nothing to change on your side, but it is a reason to take the update rather than sit on 2.1.237.

New 2.1.246

Auto mode gets a tab in /permissions, and stops false-denying on big sessions

You can now view and edit auto mode classifier rules from a dedicated tab in /permissions. Alongside it, auto mode tool calls that were being denied as "temporarily unavailable" on very large sessions now work: the safety-check deadline scales with prompt size instead of using a fixed budget.

So what for TSD: The false denials hit exactly the sessions where auto mode earns its keep — long delivery sessions with a big loaded context. If you tried auto mode on a heavy Next.js refactor and it kept bailing, that was this bug, and it is worth retrying after the update.
Claude Code changelog — 2.1.246
Fix 2.1.246

A third-party gateway API key was being sent to Anthropic's telemetry endpoint

When ANTHROPIC_BASE_URL pointed at a third-party gateway, telemetry and metrics requests to Anthropic carried the key configured for that gateway. Credentials are now only sent to the host they belong to.

Two related credential fixes landed in the same release: apiKeyHelper setups returning short-lived JWTs now refresh an expired cached token before sending instead of showing an API error on the first prompt after idle, and 401/403 auth errors retry quietly.

So what for TSD: No action — you run against Anthropic directly, not through a gateway. Worth knowing if a client ever asks you to route Claude Code through their own proxy, because it is the kind of leak that shows up in a security questionnaire.

◆ Unattended and background runs

Fix 2.1.246

Two startup failure modes for background sessions

Background sessions failed to open after 45 seconds when Claude Code's starting directory had been deleted, when the machine had slept, or on a host slow to start processes. Separately they failed with "Couldn't start the background service … EACCES" when another Claude Code process happened to be reinstalling the npm package at that moment.

The sleep case is the interesting one for a laptop that runs scheduled work. A closed lid between the schedule firing and the session opening was enough.

So what for TSD: This is the failure mode for your scheduled tasks on the Mac — the daily changelog scout, the vault refresh, the loose-ends sweep. Any of them that silently produced nothing on a day the machine had been asleep is explained by this. Update and stop debugging the launchd side.
Claude Code changelog — 2.1.246
Fix 2.1.246

The background retention sweep removed git worktrees you created

Worktrees living under .claude/worktrees/ that you made yourself were deleted by the background retention sweep whenever an old background-session record pointed at that path. The sweep did not distinguish between a worktree it had created and one you had.

So what for TSD: Directly relevant to the loop pattern you build on, where each fix lands in an isolated worktree. Until you update, keep any worktree holding uncommitted work outside .claude/worktrees/, and commit or push loop branches rather than leaving them parked in a worktree overnight.
Claude Code changelog — 2.1.246
Improve 2.1.246

Non-interactive sessions continue through a cut-off response

-p, SDK, and cloud sessions now automatically continue a response cut off mid-stream by a server error, connection loss, or a stall. The previous behavior was to end the run with an error.

Two subagent behaviors improved alongside it. A subagent that hits its maxTurns limit now returns its output marked partial with a hint to continue it via SendMessage, instead of looking like it finished. And pressing ← or running /background during a dynamic workflow no longer silently restarts finished subagents — it asks first and tells you how many would restart.

So what for TSD: The maxTurns change matters most. Any pipeline of yours that reads a subagent's return value was being handed truncated output that looked complete, which is the worst kind of failure in an unattended job. After updating, check that anything consuming subagent results handles the partial marker.
Claude Code changelog — 2.1.246
Fix 2.1.246

Interrupted MCP tool calls were reported to the model as successful

In headless and remote sessions, an MCP tool call interrupted by an incoming message was reported to the model as "completed with no output" rather than as an interruption. The model had no way to tell a tool that returned nothing from a tool that never ran. The same release fixes MCP tool arguments being sent as JSON strings when the parameter schema is empty ({}) instead of their real type, and a command interrupted mid-run showing as "Ran 1 shell command" with no indication it was cut short.

So what for TSD: You lean on MCP heavily — Supabase, Vercel, Gmail, the vault tooling. In a headless run this bug could have an agent conclude a write succeeded when it was interrupted. If any scheduled job has ever reported a clean run against state that did not actually change, this is a candidate explanation.
Claude Code changelog — 2.1.246
Fix 2.1.246

Concurrent cloud launches from one repo could pick up each other's uncommitted changes

/ultrareview runs and cloud sessions started at the same time from a single repository — for example from several worktrees — sometimes began with another launch's uncommitted changes. Also fixed: the task progress count shown for background cloud sessions such as /autofix-pr occasionally dropped a task, and --strict-mcp-config sessions prompted to approve .mcp.json servers they would never load, which left background sessions stuck waiting at startup.

So what for TSD: The --strict-mcp-config hang is the one to note. A background session waiting on an approval prompt for a server it was never going to load looks identical to a hung job from the outside.

◆ Throughput in the editor

Improve 2.1.246

/cd now loads the new directory's whole configuration

After a /cd, the destination's project settings, hooks, .mcp.json servers (still behind the usual approval prompt), skills, and agents take effect immediately. Previously you had to resume the session for them to apply.

So what for TSD: This is the one quality-of-life win that fits how you actually work — one session, hopping between client repos. Moving from a Bisque repo to a Studio C repo now brings that project's skills and hooks with it instead of leaving you in the old project's config while sitting in the new project's files.
Claude Code changelog — 2.1.246
Fix 2.1.246

Long single lines and large file overwrites no longer wreck the session

A diff containing one very long line — a base64 string, a minified bundle, a lockfile blob — caused a severe transcript slowdown. Those lines now render truncated with a marker. The Write tool separately reported "Out of memory" or froze for a long stretch after overwriting a very large existing file, even though the write had already succeeded. Memory growth in the fullscreen and Ctrl+O transcript views is also fixed: each rendered row no longer holds a full copy of the transcript-wide tool lookups.

Bash tool latency improved as well, by replaying snapshot functions without spawning a base64 subshell per function.

So what for TSD: The long-line fix is the one you will feel. Any session that touches a build output, an inlined data URI, or a generated migration was paying for it in scroll lag.
