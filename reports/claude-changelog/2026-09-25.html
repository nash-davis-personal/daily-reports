◆ Long sessions keep their reasoning

Fix 2.1.282

Extended thinking survives resumes, --tools relaunches and mid-turn slash commands

Three separate paths were throwing away Claude's earlier thinking: continued or resumed sessions re-sending old messages in a changed form (more cases fixed), relaunching with a --tools list that omits a built-in tool used earlier, and running /model, /rename, /artifacts or another immediate slash command while Claude was working. Resuming very large sessions, including never-compacted ones, is also faster.

So what for TSD: This is how most multi-day client builds actually run: pick up yesterday's Bisque or Sonderwerks session with --resume, switch model partway. Before this, a resumed session could quietly reason worse than the original. Update, and if a resumed session felt dumber than it should have this month, this is the likely reason.
Claude Code Changelog — 2.1.282
Fix 2.1.282

Sessions that failed on every turn now self-recover

Two failure modes locked a session into erroring on every request. An "Invalid data in redacted_thinking block" error now makes Claude Code drop the conversation's thinking blocks and retry once. A 400 on every request, caused by web search results in history the API can't decrypt (for example from a turn answered through a third-party gateway), is fixed.

So what for TSD: If you've been abandoning sessions that start throwing the same API error on every message, update before doing that again. Research-heavy sessions (competitor scans for pitches, vendor docs lookups) are the ones that accumulate web search results.
Claude Code Changelog — 2.1.282
Fix 2.1.282

Compaction retries on a fallback model when the summarization request is refused

Compaction used to fail when the summarization request was refused. It now retries on a fallback model.

So what for TSD: Long unattended runs rely on compaction to keep going. One fewer way for a scheduled job or a long build session to stall at the context limit.

◆ Permissions, skills and settings — rules that now read differently

Fix 2.1.282

Bash permission rules with a mid-pattern :* now apply from settings files

Rules with :* in the middle of the pattern were skipped when they came from settings files, while --allowedTools honored them. They now work from every source, with a startup warning explaining how they match.

So what for TSD: A rule that was dead may now be live, so it can approve commands that used to prompt. The scout checked ~/.claude/settings.json and the project settings under ~/Documents and found no mid-pattern :* rules, so nothing changes on this Mac today. If you see the new startup warning in a client repo, read it before approving anything.
Claude Code Changelog — 2.1.282
Change 2.1.282

anthropic-skills and claude-ai are reserved for skills synced from claude.ai

Skill folders, command files and workflow commands in those namespaces no longer load. MCP servers named anthropic-skills or claude-ai list no skills or prompts (tools still work). Skill(anthropic-skills:*) and Skill(claude-ai:*) allow rules now cover only claude.ai-synced skills.

So what for TSD: The skills you call as anthropic-skills:the-humanizer or anthropic-skills:hormozi-analyst look like claude.ai-synced skills, and no local folder in ~/.claude/skills uses either name, so they should keep loading. If one of them goes missing after the update, this change is why. When you build a skill for a client repo, don't name it into those namespaces.
Claude Code Changelog — 2.1.282
Change 2.1.282

Auto mode uses the server-side classifier by default when telemetry is off

On a direct Anthropic API connection with telemetry off, auto mode now uses the server-side classifier by default. CLAUDE_CODE_AUTO_MODE_SERVER=0 opts out. Separately, project and local settings files can no longer turn on OpenTelemetry export, set its endpoint, or capture content.

So what for TSD: Only matters if you run auto mode on an API key with telemetry disabled. The OpenTelemetry change is a quiet security win for you: a cloned client or template repo can no longer ship a settings file that exports your session content somewhere.
