◆ Permission rules got stricter — audit your allowlists

Breaking 2.1.214

Single-segment dir/** rules now match only your project root

A rule like Edit(src/**) was auto-approving writes to a nested src/ anywhere in the tree instead of only <cwd>/src. That is now corrected. The same narrowing applies to hook if: conditions — write **/dir/** if you actually want any-depth matching. deny and ask rules keep their any-depth behavior, which is the right asymmetry: denials stay broad, approvals get tight.

Two related tightenings landed alongside it. file commands using -m/--magic-file or -f/--files-from now require permission instead of passing as read-only, and permission prompts on remote sessions can no longer proceed ahead of the local confirmation dialog.

So what for TSD: Open your global ~/.claude/settings.json and each client repo's .claude/settings.json and grep for allow rules of the form Tool(word/**). Anything that was quietly covering a nested folder in the Bisque or Sonderwerks monorepo layout will start prompting. Widen the ones you want with **/dir/** and leave the rest narrow — the prompts are telling you where your allowlist was broader than you thought.

Fix 2.1.214

Six Bash permission-check gaps now fail closed

The permission analyzer parses commands before deciding whether to auto-run them, and this release closes six places where its parse disagreed with the shell's. File-descriptor redirect forms that bash reads differently now fail closed. Commands over 10,000 characters always prompt instead of running automatically. Zsh variable subscripts and modifiers inside [[ ]] comparisons were treated as inert text and now prompt. Certain help and man invocations that could carry unsafe options, command substitutions, or backslash paths lost their auto-approval. A permission-check bypass affecting Windows PowerShell 5.1 sessions was also fixed.

The same release adds permission prompts for docker commands (including the Podman docker shim) carrying daemon-redirect flags — --url, --connection, --identity, and Podman's remote mode. Those point the client at a different daemon and previously ran with no prompt.

So what for TSD: Expect more prompts in auto mode, especially on long generated commands. That is the fix working. If a specific long command is a routine part of your Vercel or Supabase flow, wrap it in a short script with a stable name and allowlist the script rather than reaching for a broader Bash rule to make the prompt go away.

◆ Unattended automation gets more trustworthy

Fix 2.1.214

Scheduled tasks no longer refuse their own configured prompt

A fired scheduled task was treating the prompt you configured for it as untrusted input, which is exactly the wrong call — you wrote that prompt. The fired prompt is now delivered as the session's assigned task. Related: hooks returning exit code 2 now block as documented even when the hook's stdout JSON fails schema validation, and a hook's continue:false halt survives a tool failing mid-stream.

So what for TSD: This is the fix for your own cron-driven scouts and any nightly loop you have pointed at client repos. If a scheduled run has been mysteriously stalling or asking for confirmation with nobody there, update and re-run it before rewriting the task file — the bug was upstream of your prompt.

Feature 2.1.214

Progress heartbeat for long tool calls, effort level in the subagent statusline

Long-running tool calls that previously went silent now emit a periodic progress heartbeat. The subagentStatusLine payload also gained the reasoning effort level, so a custom agent row can render both model and effort.

So what for TSD: The heartbeat is the practical one — a ten-minute Next.js build and a hung process now look different on screen, so you stop killing sessions that were fine. If you maintain a custom statusline, add the effort field so you can see at a glance which background agents are burning the expensive tier.

New 2.1.214

EndConversation tool lets Claude end abusive sessions

Claude can now end a session with highly abusive users or jailbreak attempts, matching behavior that has been on claude.ai since 2025.

So what for TSD: No action for your own work. It matters if you ever put a Claude-backed chat surface in front of a client's public traffic — worth knowing the model can terminate a session on its own so you design the fallback UX rather than discovering it live.

◆ Memory, telemetry, and connection reliability

Fix 2.1.214

Memory frontmatter stopped being truncated at an inline #

Frontmatter values in memory files were silently truncated at an inline # when saved. Memory files also now carry an ISO modified timestamp in frontmatter. A related fix: the memory index over-limit warning had already been narrowed to measure only loaded content in the prior window.

So what for TSD: Directly relevant to your command vault. Any note whose description: line contained a # has been sitting there half-saved and half-useless for recall. Grep the vault's memory/ folder for # inside frontmatter, fix what got clipped, and let the new modified stamp do your staleness triage from here.
Claude Code changelog — 2.1.214
Improve 2.1.214

OpenTelemetry gains message-level correlation and tool provenance

Log events now carry message.uuid, client_request_id, and tool_source, so you can correlate at the message level and see which source a tool call came from. CLAUDE_CODE_OTEL_CONTENT_MAX_LENGTH configures the 60 KB truncation limit on content attributes. Session cost and token telemetry no longer double-count on streams that emit multiple cumulative message_delta frames.

So what for TSD: The double-count fix means any per-client cost figure you pulled from telemetry before today was inflated on streaming-heavy sessions. If you have quoted an AI-usage number to Bisque or Studio C off that data, re-measure before the next invoice conversation.
