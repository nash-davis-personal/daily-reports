◆ Code quality and supply chain

Improve 2.1.286

A skill named verify now runs right before commits

If your project or user skills include one named verify, Claude is now told to run it right before committing. The changelog lists two exceptions: docs-only and tests-only commits.

So what for TSD: This is a free pre-commit gate with no hook wiring. Write one user-level verify skill that runs typecheck, lint and next build (or vite build) and add a project-level one in the Bisque, Studio C and Sonderwerks repos where the checks differ. Broken builds then get caught before the push reaches Vercel.
Changelog 2.1.286
Changed 2.1.286

Plugin installs only accept registry packages

Plugin installs now refuse npm sources that are git repositories or folders, and plugin dependencies install only from registry packages. Plugin errors for a marketplace Claude Code refuses to load now say why and how to fix it instead of "not found".

So what for TSD: If any plugin you installed points at a git URL or a local folder through npm, its next install or update will fail. Run /plugin once on each Mac and confirm the ones you depend on (vercel, codex) still load.
Changelog 2.1.286

◆ Unattended and headless runs

Changed 2.1.286

--bare now means bare

Under --bare, Claude Code connects only the MCP servers named on the command line, sends the model no system reminders, and starts no background tasks. A shell command that reaches its timeout now stops instead of moving to the background.

So what for TSD: Check every launchd job and script that calls claude --bare. Any that relied on MCP servers from settings files will now run without them; name the servers on the command line. Long shell steps in those scripts need an explicit timeout that covers the full run.
Changelog 2.1.286
Changed 2.1.286

Retries capped at 14 requests per model call, plus a model fallback

One retry limit now covers a whole model call, so with default retry settings a failing call sends at most 14 requests. Separately, when the Anthropic API refuses the model your default or an alias resolves to, Claude Code retries once on the previous model of the same tier. Fallback retries that cannot run fast now run at standard speed with a one-time notice, and the fallback notice says when the context window dropped from 1M to 200K.

So what for TSD: Scheduled jobs fail faster and more predictably during an API incident, and a bad alias no longer kills every turn. If a nightly run comes back thinner than usual, look for the fallback notice in its log before blaming the prompt: it may have run on the older model with a 200K window.
Changelog 2.1.286
Fix 2.1.286

Crashed sessions, stalled workflows and phantom "Succeeded" runs

claude --resume and --continue no longer lose every turn after a batch of parallel tool calls when the earlier session crashed or was killed. Workflow tool subagents are no longer restarted from their original prompt when a connection stalls for a few minutes mid-response. Background jobs no longer show done while waiting for your approval. In cloud sessions, routine runs whose session never started now show as Failed where they used to show Succeeded, and a late run reads "Due" with its scheduled time.

So what for TSD: The Succeeded-but-never-ran bug matters most: if you have any cloud routines, scan last week's run history for green rows with no output and rerun them. Update both Macs to 2.1.286 before the next long multi-agent job so a dropped connection stops costing a full restart.

◆ Secrets and safety rails

Fix 2.1.286

Six secret-redaction leaks closed in logs, transcripts and MCP errors

MCP error messages no longer show a credential's value when "Bearer" or "Basic" came before its key name. Percent-encoded Bearer tokens are now fully masked. Redacted logs and transcripts no longer show a secret whose key name hides an invisible character, or part of a URL password containing punctuation such as ), quotes, & or a second @. The transcript in the /feedback zip is valid JSON again after redaction.

So what for TSD: Transcripts from before this release may contain client Supabase or Vercel credentials in plain text. Treat old session transcripts and /feedback zips as sensitive, keep them out of anything you share with Grant, Bishop or a client, and rotate any database URL password you know appeared in an MCP error.
Changelog 2.1.286
Fix 2.1.286

/compact, /clear and /rewind ask before hitting the wrong conversation

Typing those commands while viewing a background agent's or teammate's transcript used to act silently on the main conversation. A dialog now names the target and asks first. The permission prompt also shows a count such as "2 of 5" when several requests stack up.

So what for TSD: One less way to wipe the main thread of a long client session while checking on a subagent. No action needed beyond updating.
