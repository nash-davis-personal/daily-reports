2.1.307 stops HTTP MCP tool calls from firing twice

If an HTTP MCP connection dropped mid-call, Claude Code used to resend the call, which for a write tool meant doing it twice. That is fixed, and 2.1.309 also closes a sandbox gap and changes how bypass mode handles dangerous rm in the Desktop app, which is where your scheduled runs live.

◆ MCP and client-system safety

Fix 2.1.307

HTTP MCP tool calls were sent twice when the connection closed mid-call

The changelog says HTTP MCP tool calls could go out twice when the connection closed partway through. The fix limits automatic retries to read-only or idempotent tools. The same release fixes MCP servers reported as timed out (and left failed in headless runs) when a Mac slept while they were connecting, and servers showing "needs authentication" in claude -p while the macOS login keychain was locked.

2.1.310 adds a related change: when an MCP call times out in a non-interactive session because the server's elicitation went unanswered, Claude is now told no answer came and not to repeat the call.

So what for TSD: You run Square, Supabase, Vapi and Vercel through MCP. A doubled write there is a duplicate catalog item, a second outbound call or a repeated migration. Make sure both Macs are on 2.1.307 or later, and if anything odd showed up in a client system after a flaky-network session this month, check for duplicates.
Changelog: 2.1.307, 2.1.310
Fix 2.1.309

Sandboxed Bash ran shell startup files outside the sandbox

On macOS and Linux, sandboxed Bash commands ran the shell's startup files outside the sandbox before each command. 2.1.309 fixes that along with a cluster of related holes: sandboxed commands and auto-accepted edits could modify the file passed with --mcp-config; macOS denyWrite globs missed paths reached through a symlink; an Edit(path) deny rule could be bypassed with a Bash redirect inside a subshell; some compound cd-then-git commands skipped the prompt; and worktree isolation accepted some locale-prefixed and zsh arithmetic commands it should refuse.

So what for TSD: Your zsh startup files load real tokens and PATH tweaks, so this one matters on your machines specifically. Nothing to change in config; just update. If you rely on deny rules to keep agents away from client .env files, this release is what makes those rules hold.
Changelog: 2.1.309 bug fixes

◆ Unattended runs and agents

Changed 2.1.309

Bypass mode now denies dangerous rm at once, and sed -i is a plain Bash edit

In bypass permissions mode in the Desktop app and VS Code, the dangerous rm/rmdir prompt now denies the command immediately with a rewrite hint, "so unattended sessions keep going." Separately, sed -i now gets the standard Bash prompt and runs as written instead of a simulated file-edit preview, and like other Bash edits it is no longer restored by /rewind.

So what for TSD: Scheduled tasks like this one run in bypass mode in the Desktop app, so a stray rm -rf now gets refused and rephrased instead of hanging the run until you see it. The sed -i change cuts the other way: if you lean on /rewind to undo agent edits on a client repo, edits made with sed -i won't come back. Commit before letting an agent loose.
Changelog: 2.1.309 changed
Improved 2.1.307 · 2.1.310

Fewer turns lost to bad tool calls, fork mix-ups and compaction loops

2.1.307 retries an unparseable tool call up to twice before ending the turn, and tells each fork subagent launched together which launch is its own, so forks are "much less likely" to start each other's work. It also fixes some "Autocompact is thrashing" errors in turns that read many PDFs or images. 2.1.310 fixes compaction after a "Prompt is too long" error keeping too much dense text such as base64 or SVG, so the next request failed again.

So what for TSD: SVG-heavy site work and PDF-heavy client intake were the cases most likely to wedge a long session. Fan-out forks across Bisque, Studio C and Sonderwerks tasks should now stay in their lanes. No action beyond updating.
Changelog: 2.1.307 improvements, 2.1.310 fixes

◆ Building AI for clients

New 2.1.307 · 2.1.309

/claude-api can migrate code to API version 2026-10-21 and builds agent teams on multiagent_20261001

2.1.307 adds /claude-api api-version to move Claude API code to API version 2026-10-21. 2.1.309 changes the skill to build Managed Agents subagent teams on multiagent_20261001 with dynamic workflows on by default, replacing coordinator. It also now checks the live docs before calling a feature unsupported, and offers API tracing alongside SDK tracing for OpenTelemetry.

So what for TSD: Any client build that calls the Claude API (chat widgets, intake bots, the AI pieces of a modernization job) can be moved forward with one command; run it on a branch and read the diff. If you pitch a multi-agent back-office build, the scaffold the skill generates has changed, so old snippets in your notes may not match.
Changelog: 2.1.307 added, 2.1.309 changed
