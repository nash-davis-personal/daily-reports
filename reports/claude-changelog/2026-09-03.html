◆ Unattended runs and the permission wall

New 2.1.259

--permission-prompts none denies prompts instead of hanging the host

Headless hosts can pass --permission-prompts none: anything that would prompt is denied automatically while the active permission mode (including auto mode) keeps deciding. Same release adds managedMcpServers so orgs can ship HTTP/SSE MCP servers to every user, and changes allowedMcpServers so it only governs servers users add — a literal managed-mcp.json server that used to get filtered out now loads on upgrade unless you put it in deniedMcpServers.

So what for TSD: Put --permission-prompts none on any unattended loop that must never sit forever on a dialog. Pair it with a tight allowlist so a deny fails closed instead of improvising. If you ever pin managed MCP allowlists, re-read them after upgrade so a previously filtered managed server does not suddenly appear.
Claude Code changelog — 2.1.259
New 2.1.257

Containment Escape stops auto mode from approving cloud credential and egress tricks

Auto mode gains a Containment Escape rule: cloud metadata-credential fetches, egress evasion, and cross-tenant reach are no longer auto-approved unless the environment marks them expected. The same release adds a one-time prompt before the first file read outside the working directories, with permissions.blockReadsOutsideWorkingDirectories to hard-block those reads, and closes more Bash auto-approve holes around zsh-vs-bash [[ ]] conditionals and permissions.ask rules inside compound commands or subshells.

Also in 2.1.257: defaultMode: "bypassPermissions" in project .claude/settings.json or .claude/settings.local.json is ignored (same treatment as "auto"). Set it in user or managed settings, or pass --permission-mode.

So what for TSD: Auto mode on client repos just got less naive about credential and egress patterns — good. If any Bisque, Studio C, or Sonderwerks project relied on project-level bypassPermissions, that setting is now a no-op and the session will fall back to a stricter mode. Move the setting to user scope or pass the flag explicitly after you upgrade.
Claude Code changelog — 2.1.257
Fix 2.1.257 · 2.1.259

Read/Edit deny rules finally cover the paths agents actually use

2.1.259 extends Bash Read() deny rules to files given as option values (--ignore-revs-file=.env, -f.env, @file), git diff/git grep file operands, and cd DIR && cat FILE compounds; grep -r/cp -r over a directory holding a denied file now asks. 2.1.257 already closed redirects (< file) and readers like tac and egrep, and refused plugin component paths that are symlinks pointing outside the plugin directory.

2.1.259 also stops concurrent sessions from silently reverting each other's ~/.claude.json changes — workspace trust, MCP, and project state no longer get stomped when many sessions run at once.

So what for TSD: Deny rules on .env and secrets directories were leaky through ordinary agent command shapes. After upgrade, treat those rules as real again, and stop assuming two parallel Claude sessions will leave shared config alone — that race is fixed, but only on 2.1.259+.

◆ Loop reliability and models

Fix 2.1.257

Subagents keep going after sleep, disconnects, and mid-stream server errors

When a response was cut off mid-stream by computer sleep, a dropped connection, or a server error, subagents used to stop with an incomplete response. They now automatically continue. Related fixes in the same release: backgrounding a turn while a subagent ran no longer treats that tool as rejected; stopping a background subagent also stops its monitors; claude -p waits for an armed Monitor instead of exiting ~5 seconds after the final result; and worktree-isolated sessions stop refusing common Bash loops, $VAR reads, command substitutions, and heredocs that never touch git.

/fork keeps the original conversation's prompt cache in the new background session by delivering the worktree briefing as a message instead of a system-prompt change. CLAUDE_CODE_SUBAGENT_MODEL_FORCE forces the subagent model env (or the main model) onto every subagent, ignoring per-spawn and agent-definition overrides.

So what for TSD: Lid-close and Wi-Fi blips on this Air used to strand background workers mid-turn. After upgrade, expect those workers to resume instead of dying incomplete — and stop fighting worktree isolation over ordinary shell patterns that never leave the checkout.
Claude Code changelog — 2.1.257
Feature 2.1.257

Fable 5.1 ships as the default Fable model

claude-fable-5-1 is now the default Fable model: 1M context, $10/$50 per Mtok with $0.25/Mtok cache reads. Gateway sessions keep resolving aliases fable and best to Fable 5 for now, because gateways that are not yet configured for 5.1 reject it — pick Fable 5.1 explicitly in /model when you want it. Session-only effort changes land via s in /effort, matching /model.

So what for TSD: If you use Fable for long client digests or 1M-window reviews, plan for the new default and the cache-read price. If a gateway session quietly stays on Fable 5, that is intentional until the gateway is updated — switch in /model when you mean 5.1.
