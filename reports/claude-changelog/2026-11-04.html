Claude Code Changelog ◆Wednesday, November 4, 2026 ◆Release 2.1.318

2.1.318 warns headless runs before sign-in expires and hardens Mac sessions

Second big release in two days. Most of it is plumbing for unattended runs: a sign-in expiry warning in claude -p, a config file that stops getting rewritten on every headless run, and subagents that keep their prompt cache alive through long shell commands. Mac users also get a fix for sessions stalling under many Bash commands.

◆ Unattended runs and sign-in

New 2.1.318

A sign-in expiry date you can see, and a 10-day warning in claude -p

claude auth status now reports the date a stored claude.ai sign-in ends (loginExpiresAt), and claude -p JSON results carry it as credential_expires_at. Text-mode claude -p output gets a one-line stderr warning starting 10 days before that date. When a sign-in does hit its limit, the failure now says so, and in claude -p it names claude auth login and claude setup-token as the fix.

Related fixes: jobs no longer exit with "Not logged in" when another terminal or host signs in again to the same account on the same home, and claude plugin commands no longer exit before a slow token refresh is saved.

So what for TSD: Every scout, Fleet Steward and Nash OS job dies quietly the day the sign-in lapses. Add a claude auth status check to the Nash OS Machine page or the morning routine and surface the expiry date. Any launchd job that runs claude -p should log stderr so the 10-day warning lands somewhere you read.
Changelog, 2.1.318
Improved 2.1.318

~/.claude.json stops churning, and a damaged one is no longer overwritten

Unattended runs (claude -p, SDK apps) no longer rewrite ~/.claude.json on every run when nothing in it changed. A non-interactive launch that finds the file is invalid JSON now fails, says how to restore it, and leaves it alone instead of replacing it with defaults (anthropics/claude-code#87551). Retention cleanup also takes a fresh backup before deleting the last good one on a home that only runs claude -p.

A batch of related fixes targets shared network home directories: settings and the stored login are less often deleted or emptied on save, /logout and claude mcp remove no longer report success when the config could not be written, and claude mcp add now waits for the config lock or exits 1.

So what for TSD: Two Macs, one config each, a dozen scheduled jobs writing to it. Fewer rewrites means fewer chances two jobs stomp each other and drop an MCP server. If a headless run ever fails at start with a restore message, follow it instead of deleting the file; your MCP list and trusted folders live in there.
Changelog, 2.1.318
Fix 2.1.318

Headless sessions stop reporting success on cut-off replies and silent slash commands

claude -p and Agent SDK sessions were reporting success when an API error cut off a reply while a mod hooked turn.step; fixed. Custom slash commands that fail, or that only Claude can invoke, now print something in claude -p and SDK sessions instead of nothing. Workflows no longer re-run finished agents when resumed after a usage limit, and a duplicate notification no longer fires when Claude leaves the status field out of a PushNotification call.

So what for TSD: Your run log depends on exit codes telling the truth. The duplicate push fix matters on your phone: one Remote Control notification per event from now on.

◆ Subagents and throughput

Changed 2.1.318

Long shell commands in background subagents go to the background at 3 minutes

Background subagents now move a shell command to the background after 3 minutes on all providers, so the prompt cache does not expire while it runs. On Bedrock, Vertex, Foundry, or with telemetry off, a subagent's progress summary on a cold cache can now wait up to 5 minutes for the pending response.

Also changed: when "Switch models when a message is flagged" is set to "Ask each time", subagents now stop instead of switching models.

So what for TSD: A fanned-out subagent running a Next.js build or a long test suite used to burn its cache and re-pay the full context on the next turn. Now it keeps the cache. If you have subagents that wait on builds or Vercel deploys, expect lower cost per run and no code change needed.
Changelog, 2.1.318
New 2.1.318

Mods: $.model.fork takes an effort option

A mod's $.model.fork accepts an effort option, so a quick side job can run at low whatever effort the session uses; the result reports the effort sent. Claude Code also now records your answer when it asks to turn on the mods it writes in a session, and what a mod attaches at prompt.submit stays in the user's turn instead of going out as a system message.

So what for TSD: If you build a status-line or toast mod that asks the model a small question (summarize the diff, name the branch), fork it at low and stop paying session effort for a one-liner.
Changelog, 2.1.318

◆ Mac, desktop and Remote Control stability

Fix 2.1.318

Mac sessions stalling under many Bash commands, and git on /bin/bash

macOS sessions with many running Bash commands were stalling while memory grew; fixed. Git commits and pull request creation are more reliable when the Bash tool runs macOS's built-in /bin/bash. Permission prompts also no longer get answered by keys typed just after sending a message or before a slow prompt appeared.

Two session-continuity fixes: --continue sometimes lost the earlier conversation after a malformed tool call's retries ran out (a regression from 2.1.314), and idle compaction could replace a conversation with a reply that was not a summary. Both fixed.

So what for TSD: If a long Bisque or Sonderwerks session on the MacBook Air has been going sluggish after an hour of builds and dev servers, this is likely it. Update before the next heavy session. The accidental-approval fix means a stray Enter after a message no longer greenlights a prompt you did not read.
Changelog, 2.1.318
Fix 2.1.318

Version cleanup no longer breaks a running Remote Control host or daemon

claude remote-control hosts, the background daemon and self-hosted runners could fail to start new sessions with spawn ENOENT after an update or version cleanup removed the binary of a still-running process. A running process owned by another user (one left by sudo claude, for example) was also being treated as dead and could lose its binary. Both fixed. Remote sessions also reconnect faster after a pause or sleep, and a missing working folder now produces an error that names the folder.

So what for TSD: This is the failure where your phone says a session is available and nothing starts. If Remote Control has gone dead on the desk Mac after an auto-update, update both machines and restart the host once.
Changelog, 2.1.318

◆ Managed agents and carry-over

Changed 2.1.318

/claude-api managed-agents-onboard defaults new agents to the auto permission policy

Onboarding a new managed agent now gives its built-in tools, and a quickstart template's MCP tools, the auto permission policy ("Judge risky actions") by default, matching the Claude Console. Say "run without asking" to opt out.

So what for TSD: If you spin up a managed agent for a client (a Studio C booking helper, say), the default now judges risky calls instead of running everything. Keep the default for anything that touches a client's money or messages. Pair it with yesterday's onFailure: "block" on SDK hooks.
