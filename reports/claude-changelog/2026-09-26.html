◆ Config hygiene

New 2.1.283

A built-in audit for stale prompts in your CLAUDE.md, skills and agents

/doctor prompt-audit (also /checkup prompt-audit) scans CLAUDE.md files, skills, agents and commands for prompting patterns written for older models. The same release says stale paths, stale commands and contradicting instruction files now lead the report, and thinking keywords Claude Code documents are left alone.

So what for TSD: Your setup is exactly what this targets: a long global CLAUDE.md with dated rules, 60-plus skills, and two vaults of memory. Run it from an interactive claude terminal in ~/Documents, fix the contradictions it surfaces first, and treat the rest as a cleanup list. The advisor skills and the older client skills are the likeliest to carry dead phrasing.
Changelog 2.1.283
Fix 2.1.283

The claude-ai name reservation from 2.1.282 is reverted, and auto-memory edits from subdirectories work again

Skills, commands, workflows and MCP prompts named claude-ai load again, and Skill(claude-ai:*) rules go back to ordinary prefix rules. Separately, Claude's edits to its own auto-memory notes were being blocked as sensitive-file writes when Claude Code was started in a subdirectory of a git repo; that is fixed.

So what for TSD: If yesterday's briefing made you rename anything to dodge the reservation, you can leave it or revert it. The memory fix matters less for you since durable memory lives in the command vault, but sessions opened inside a client repo subfolder will stop throwing blocked-write prompts on memory.
Changelog 2.1.283

◆ MCP reliability

Fix 2.1.283

Remote MCP servers survive a redeploy blip, and background tool calls keep reporting progress

A brief HTTP 404 from a stateless remote MCP server, such as a proxy mid-redeploy, used to leave that server unusable for the rest of the session while still showing as connected. That is fixed. Progress notifications are no longer discarded once a long-running MCP call moves to the background, stdio servers are no longer left running when a session ends while they are starting, and claude mcp add/remove no longer report success when the config file could not be written.

So what for TSD: You run your own remote MCP servers (tsd-portal, nash-os) and redeploy them on Vercel. Before this, a deploy during a live session could leave Claude calling a server that looked connected but was dead. Update and that failure mode goes away. Orphaned stdio processes were also a plausible source of stray node processes on the Air.
Changelog 2.1.283
Improved 2.1.283

Images from MCP tools are saved to disk, and /context now counts MCP instructions

Images returned by MCP tools are now also written to a file so Bash, Read and other tools can open them. /context now shows MCP server instructions as their own row and counts them toward the total; before, they were not counted at all.

So what for TSD: Screenshots from chrome-devtools and Higgsfield or Canva outputs can now be piped straight into ffmpeg, the likeness-gate evidence step, or a commit without a manual save. And with a dozen-plus MCP servers connected, check /context once: the instruction blocks from Higgsfield, Calendly and others were invisible overhead until now.
Changelog 2.1.283

◆ Agents, automation and defaults

Behavior change 2.1.283

Sessions with telemetry off or on third-party providers now start in auto mode

Interactive sessions on third-party providers, or with telemetry off, now start in auto mode when no permission mode is configured. permissions.defaultMode still overrides it. Relatedly, Remote Control was unavailable on paid plans with DISABLE_TELEMETRY or DO_NOT_TRACK set; that is fixed.

So what for TSD: If any machine or client handoff box runs with telemetry off and no defaultMode, it will now act with less prompting than before. Set permissions.defaultMode explicitly anywhere you care, especially on anything touching the Bisque Vercel scope.
Changelog 2.1.283
Fix 2.1.283

Workflows retry the configured model after a fallback, and headless runs start faster

Dynamic workflows started during a model fallback used to run every agent on the fallback model; they now retry the configured model. claude -p and Claude Code Remote no longer load the interactive UI at startup, first-request latency reuses the preconnected API connection, and the weekly Fable limit now shows in /usage even with telemetry disabled.

So what for TSD: A workflow kicked off during a rough patch could have spent a whole fan-out on a weaker model without telling you. That is closed. The -p startup change trims a little off every headless and scheduled run, which adds up across the daily scouts and stewards.
Changelog 2.1.283
Fix 2.1.283

Cloud sessions stop redoing finished steps, and timed-out Code Reviews aren't billed

Cloud sessions could redo an already-finished step, such as posting a duplicate comment or push, after recovering from a server-side restart; fixed. A Code Review that hit its time limit with nothing verified now shows as incomplete, is not charged, and is retried once. "@claude review" requests that went silent when GitHub failed to return the PR are now retried once, with a comment if it still fails. New cloud routine schedules default to a few minutes past the hour, since on-the-hour routines can start several minutes late.

So what for TSD: Duplicate pushes from a cloud session are the kind of thing that triggers a second Vercel deploy on a client repo. If you've seen doubled comments or deploys from cloud runs, this is the likely cause. When you next schedule a cloud routine, take the off-the-hour default.
