◆ The model shift: Opus 5

New 2.1.219 · Jul 24

Claude Opus 5 ships as the default Opus model

The changelog lists claude-opus-5 as the new default Opus model, with a 1M context window and fast mode priced at $10/$50 per million tokens (input/output). It sits above Opus 4.8, which is still selectable. The bundled claude-api skill was updated to default to Opus 5 and carries a migration path from Opus 4.8.

This is a default-model change, so unless you pin a model explicitly, new sessions pick Opus 5 on the next update. Worth an eval pass on your real work before you assume parity — the model is different even if the workflow isn't.

So what for TSD: Run one Bisque or Studio C build session on Opus 5 and sanity-check output quality and cost before you let it become your everyday default. The 1M context matters most on your larger repos — you can hand it a whole Next.js app plus the Supabase schema in one shot. If you've pinned a model anywhere in a client project or a scheduled task, check whether you meant to.

Breaking 2.1.219 · Jul 24

Fast mode changes: Opus 4.7 out, Opus 5 in

Opus 4.7 was removed from fast mode. /fast now applies to Opus 5 and Opus 4.8. The /model picker now highlights only the newest model's name so the highlight marks the actual new release, and the merged Opus row now reads "Opus (1M context)" instead of a bare "Opus." A stale-cache bug that showed the Fable row as "Requires usage credits" on plans that include it was also fixed.

So what for TSD: If you were leaning on Opus 4.7 in fast mode, that path is gone — /fast is now an Opus 5 / 4.8 toggle. No action beyond knowing which two models your fast-mode key now flips between.

◆ Agents & workflows: deeper, but with brakes

Feature 2.1.219 · Jul 24

Nested subagents up to depth 3 by default

Subagents can now spawn nested subagents up to depth 3 by default — the old default was 1 (no nesting). Set CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1 to turn nesting back off. Alongside it, stream-json now forwards nested subagent text: agents spawned at depth 2+ show up when --forward-subagent-text is set, keyed by the spawning Agent's tool_use id.

This reverses the depth-1 default that landed only a few days ago in 2.1.217. The concurrency caps from that release (20 concurrent subagents, 200 per session) still stand.

So what for TSD: Your loop-engineering and workflow patterns can now decompose one more level without a flag — a discovery agent that itself spawns per-file fixers now works out of the box. If you'd deliberately relied on the flat depth-1 behavior in a steward loop to keep blast radius small, pin CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1 so this update doesn't quietly widen it.
Changelog 2.1.219
Breaking 2.1.219 · Jul 24

Dynamic workflows now default to a size guideline (<15 agents)

Dynamic workflows now default to a medium size guideline — aim for fewer than 15 agents. Pick another size, or unrestricted, via Dynamic workflow size in /config. There's a new workflowSizeGuideline settings key so the advisory can be set from any settings file (the /config row hides itself while one is set), and the running-workflow status line now shows the current default with a pointer to /config.

So what for TSD: This is advisory, not a hard cap, but it nudges the model toward smaller fan-outs. If you've built a genuinely large workflow — a big audit or migration sweep — set the guideline to a larger size or unrestricted in that project's settings so it doesn't get talked down to under 15 agents.

Fix 2.1.219 · Jul 24

claude -p no longer drops the answer on a mid-stream error

Headless claude -p text output was discarding the answer it had already produced when a turn died on a mid-stream API error. Now the produced text survives the failure.

So what for TSD: Direct reliability win for exactly the kind of unattended job that files these briefings and runs your scheduled tasks. Fewer silent empty outputs when the API hiccups mid-turn — you get partial work back instead of nothing.

◆ MCP, sandbox & headless plumbing

Improve 2.1.219 · Jul 24

MCP connection failures now surface HTTP status and errors

claude mcp list and /mcp now show the HTTP status and error text when a server fails to connect, plus a warning for MCP config values with hidden leading or trailing whitespace. Headless runs get the same signal: a new mcp_server_errors field in the stream-json init event lists --mcp-config entries skipped by config validation, and terminal runs print a startup warning.

So what for TSD: You run a lot of MCP servers — Supabase, Vercel, Notion, the tsd-portal, the higgsfield pair. Next time one goes dark, claude mcp list tells you whether it's a 401, a 500, or a stray space in a config value instead of a blank "not connected." Cuts real time out of debugging a broken connector.
Changelog 2.1.219
Feature 2.1.219 · Jul 24

Sandbox network hard-deny and a DirectoryAdded hook

New sandbox.network.strictAllowlist setting denies non-allowlisted hosts for sandboxed commands outright, with no prompt. And a new DirectoryAdded hook fires after /add-dir — or the SDK register_repo_root control request — registers a new working directory mid-session. One caveat for managed setups: managed MCP allowlist/denylist ${VAR} entries now resolve from the startup environment and managed-settings env instead of settings-file env.

So what for TSD: strictAllowlist is the setting you'd want on any sandboxed automation touching client data — it makes egress fail closed instead of pausing for a prompt nobody's there to answer. The DirectoryAdded hook is a clean spot to auto-load per-repo context when you pull a second project into a session mid-flow.
