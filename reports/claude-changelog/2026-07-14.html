Claude Code Changelog ◆Tuesday, July 14, 2026 ◆2.1.208–2.1.209 ◆ Jul 14

Freeze breaks: a big speed-and-stability drop for long-running agents

Nothing shipped for two days, then 2.1.208 dropped one of the largest fix batches in weeks and 2.1.209 patched a regression from it hours later. Almost all of it is plumbing — throughput, memory, and making the agent's own file tools stop returning silently-wrong results.

◆ Throughput & context cost

Improve 2.1.208

Tool rounds up to 7× faster in MCP-heavy headless sessions

Print and SDK sessions used to reassemble the whole tool pool on every call; that assembly is now cached, cutting per-tool-call CPU by up to 7× at high MCP-tool counts. A separate fix compiles permission deny/ask matchers once instead of per turn, killing the multi-second per-turn slowdowns that hit sessions carrying many rules.

So what for TSD: Every one of your headless jobs — this scout run, the vault refresh, the portal syncs — carries a big MCP surface. This is a wall-clock win with zero config; just update and the automations get quicker.
Claude Code changelog · 2.1.208
Fix 2.1.208

Release notes stop dumping the whole changelog into context

The "Show all" action in /release-notes was injecting the entire changelog into every subsequent request, silently inflating token cost for the rest of the session. It no longer does. In the same release, very large markdown tables (over 200 rows) that used to stall rendering now show the first 200 with a "… N more rows" notice.

So what for TSD: Cheaper turns and no mystery context bloat after you glance at what shipped. If you ever noticed a session get sluggish and expensive after opening release notes, that was this.
Claude Code changelog · 2.1.208

◆ The agent's own file tools stopped lying

Fix 2.1.208

Edit no longer dies when a file changes after it was read

If a file was modified after Claude read it but the target text still matched uniquely, the Edit tool used to fail outright. It now applies the edit.

So what for TSD: Fewer dead-ends mid-build when a formatter, Vite HMR, or a parallel agent rewrites a file you're editing on a Bisque or Studio C job. One less reason a run stalls and needs babysitting.
Claude Code changelog · 2.1.208
Fix 2.1.208

Grep, Read, and Glob stop returning silently-wrong results

Grep was returning "No files found" for an invalid regex, under-reporting totals in count mode when results paginated, Read was reporting empty files as "shorter than offset", and Glob crashed with an unclear error on a null byte in the pattern or path. All now return correct results or a clear error. The Agent tool also now fails with a named error when a subagent's tools list resolves to nothing, instead of launching with no tools.

So what for TSD: These are the tools your agents make decisions on. A silently-wrong grep count is more dangerous than a crash — the agent acts on the wrong number and you never see it. This closes that whole class.
Claude Code changelog · 2.1.208

◆ Long-running & background sessions

Improve 2.1.208

Memory leaks closed; edit-heavy transcripts shrink up to 79×

Several long-session leaks are fixed: MCP stdio server stderr accumulating up to 64 MB per server, LSP documents staying open forever (now LRU-capped at 50), async hook output retained after backgrounding, and unbounded growth in headless/SDK sessions from large tool-result payloads. Session transcript size drops up to 79× in edit-heavy sessions, and checkpoint disk usage is bounded by pruning superseded file-history backups.

So what for TSD: Your unattended loops run for hours and edit constantly. This is the difference between a loop that quietly OOMs or fills the disk overnight and one that finishes. Directly de-risks anything you leave running via claude agents or the scheduler.
Claude Code changelog · 2.1.208
Fix 2.1.208–.209

Background agents become dependable

Completed background agents now stay listed in /tasks until cleanup instead of vanishing the moment they finish; attaching to a stopped agent shows its transcript immediately rather than a blank "Session is starting" screen; a server closing an HTTP/2 connection with a GOAWAY mid-request no longer crashes supervised and background sessions; replies typed to a background agent survive a failed delivery and get sent on restart; and the false "100% context used" flash after an auto-update is gone. Then 2.1.209 un-blocked /model and other dialogs inside claude agents background sessions, reverting an overly broad guard from 2.1.208.

So what for TSD: Background agents are how you scale past a single terminal. This batch makes them stable enough to trust with real work — but note 2.1.209 was a same-day patch to 2.1.208, so update straight to .209 and skip .208.
Claude Code changelog · 2.1.208, 2.1.209

◆ Safety when running unattended

Fix 2.1.208

The rm -rf guard now fires inside $(…) and backticks

Catastrophic removals like rm -rf ~ wrapped in $(…), backticks, or <(…) now trigger the same confirmation prompt under --dangerously-skip-permissions and auto mode that the plain form already triggered. Previously the guard only matched the bare command, so a wrapped one slipped through.

So what for TSD: If you run any loop in auto mode, this is a real guardrail against a generated command nuking your home dir. It still only prompts — it does not hard-block — so keep destructive loops sandboxed to a worktree regardless.
Claude Code changelog · 2.1.208
