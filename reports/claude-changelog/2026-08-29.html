Claude Code Changelog ◆Saturday, August 29, 2026 ◆2.1.251

2.1.251 patches six permission escapes and finally lets background sessions edit the worktrees they create

Upgrade today. One release landed in this window and it carries 71 entries, ten of which tighten the permission and sandbox boundary. The one to read twice: file tools followed a symlink that was swapped inside the working directory after the permission check cleared, which could read or write outside the approved location. Separately, the bug that stopped background sessions from editing files in worktrees they had just created with git worktree add is fixed, which unblocks the isolated-worktree loop pattern.

◆ The permission boundary got ten patches

Fix 2.1.251

A symlink swapped after the permission check let file tools write outside the approved directory

The changelog describes it plainly: Read, Write and Edit followed "a symlink swapped inside the working directory after the permission check, which could read or write outside the approved location." That is a time-of-check-to-time-of-use gap, and it means an approval you granted for a path inside the project could land somewhere else on disk.

The same release fixed Grep and Glob not applying Read(...) deny rules to files reached through a symlinked search path, plugin commands declared in a marketplace entry being able to point outside the plugin directory, and the Workflow tool reading a scriptPath outside what the session may read before the permission check ran.

So what for TSD: Every one of these matters more to you than to someone typing in a foreground terminal, because your loops run unattended with wide permissions and no one watching the prompts. Upgrade before the next scheduled run fires, and treat any deny rules in your settings as having been advisory until now.
Claude Code changelog, 2.1.251
Fix 2.1.251

Bash auto-approved arithmetic assignments like OPTIND=1/0

Permission checks were auto-approving commands that assign an arithmetic expression to an integer shell variable. The changelog gives OPTIND=1/0 and RANDOM=2+2 as examples. These now prompt for approval. In the same batch, Bash command output files created in the sandbox were changed so a sandboxed command cannot redirect or replace them.

So what for TSD: Nothing to change on your side, but this is the second consecutive release where the interesting content is the auto-approve classifier being wrong. If you have been leaning on auto mode for client repos, keep the allowlist narrow and re-read yesterday's warning about wildcards before the subcommand in Bash(git * main) style rules.
Claude Code changelog, 2.1.251
Breaking 2.1.251

Project settings can no longer set CLAUDE_CONFIG_DIR or the temp dir

Project-level .claude/settings.json env no longer sets CLAUDE_CONFIG_DIR, CLAUDE_CODE_TMPDIR, or TMPDIR/TMP/TEMP. The changelog says to set them in your shell, user, or managed settings instead. Project settings also lost the ability to enable detailed beta tracing or raw API body logging. Server-managed settings that terminate sandbox TLS, route sandbox traffic through your own proxy, inject credentials, or weaken sandbox isolation now require approval before they apply, as does ANTHROPIC_CUSTOM_HEADERS from managed or project settings when it sets a credential, org, routing, or API-behavior header.

So what for TSD: Grep your client repos for a project-level env block setting any of those three variables. If one of your project .claude/settings.json files pins a temp dir, it silently stops working on this version and the failure will look like something unrelated. Move it to ~/.claude/settings.json or your shell profile.
Claude Code changelog, 2.1.251

◆ Unattended agents stopped tripping over themselves

Fix 2.1.251

Background sessions could not edit files in worktrees they created

Background sessions and their subagents were unable to edit files inside a git worktree they had created with git worktree add. Two related fixes landed alongside it: background sessions occasionally started with no plugin skills at all, and stayed that way, when another Claude Code process was refreshing the plugin marketplace at the same moment; and the one-time "make auto mode your default" offer was appearing in unattended sessions such as agent-team teammate panes, where a stray keypress could accept it unread.

So what for TSD: This is the fix that matters most for your loop work. Create-worktree-then-edit is the core move in the isolated-worktree pattern, and it was silently failing in exactly the background context loops run in. If you have a scheduled loop that has been producing empty or no-op cycles, this is a plausible cause. Re-run one cycle by hand after upgrading before you trust the schedule again.
Claude Code changelog, 2.1.251
Fix 2.1.251

Agent teams were losing the teammate's actual answer

A teammate's final answer was not reaching the team lead. It now arrives in the idle notification instead of a content-free "available" notice. Background subagents were also unable to reply to a message from an unnamed sibling or parent agent, because the from field carried the agent type rather than an address. TUI lag with many parallel subagents was fixed by having per-second progress ticks replace their predecessor instead of piling up in the transcript.

So what for TSD: If you tried agent teams and concluded the coordination was not worth it, the experiment was rigged. The lead was receiving a notification that a teammate finished without the work product attached. Worth one more test run on a real task before you write off the pattern.
Claude Code changelog, 2.1.251
Improve 2.1.251

ultrareview stops waiting 30 minutes on a dead cloud session

claude ultrareview and /ultrareview waited the full 30 minutes when the cloud session failed to start. They now stop early and report the reason. Session transcripts were also being silently overwritten when a directory change relocated a session onto an existing same-ID transcript.

So what for TSD: Small, but it removes a half-hour dead stop from the review step you run before client pushes. The transcript-overwrite fix is the one to note if you move between ~/Documents project folders mid-session, which you do constantly.
Claude Code changelog, 2.1.251

◆ Model and cost control

Fix 2.1.251

Opus 5 failed outright at xhigh or max effort with thinking turned off

Requests failed with "effort … is not supported when thinking is disabled" when effort was xhigh or max and thinking was off. Effort is now sent as high in that case. Related: /effort now saves your default effort level per model, so each model keeps its own setting when you switch, and a stale "switch to Opus 1M for 5x more context" tip stopped appearing for people already on a 1M-context Opus model.

So what for TSD: You run Opus 5 with the 1M context window. If you have ever hit that error mid-build and blamed your prompt, it was a config combination the API rejected. Per-model /effort memory is the practical win: set a cheap default on your fast model and a high one on Opus without re-toggling every switch.
Claude Code changelog, 2.1.251
Breaking 2.1.251

CLAUDE_CODE_SUBAGENT_MODEL is now a default instead of an override

The variable now sets the default subagent model. An agent definition's model: frontmatter and an explicit per-spawn model take precedence over it. Previously it overrode everything.

So what for TSD: Check this one. If you set that variable to hold subagent spend down on a cheap model, any agent definition carrying its own model: line now escapes the cap and your subagent bill moves. Either strip the model: frontmatter from agents you want capped, or accept the per-agent setting and drop the variable.
Claude Code changelog, 2.1.251
New 2.1.251

Model-switch hooks, and a prompt-cache readout in /cost

PreModelSwitch and PostModelSwitch hook events can block, confirm, or annotate a model switch. SessionStart resume hooks now receive session staleness and the estimated re-cache cost. /cost gained a per-session prompt-cache line covering hit ratio, misses, tokens re-cached, and warm or cold state, with a matching prompt_cache object exposed to status line scripts.

So what for TSD: The prompt_cache status line object is the useful half. Thursday's briefing covered an hourly cache miss quietly taxing long sessions, and until now you had no way to see it happening. Put hit ratio in your status line and you will know within a session whether a long client build is re-caching instead of reusing. The re-cache cost on SessionStart resume is the other half: it tells you whether resuming a stale session is cheaper than starting clean.
Claude Code changelog, 2.1.251
