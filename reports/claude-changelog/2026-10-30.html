◆ Guardrails for unattended runs

New 2.1.314

A write fence that holds even in bypass mode

The new permissions.blockWritesOutsideWorkingDirectories setting makes the Write, Edit and NotebookEdit tools refuse paths outside the session's working directories "in every permission mode." It pairs with the existing blockReadsOutsideWorkingDirectories. Note the scope: it covers Claude's file tools. Shell commands are a separate surface, so a sed -i or redirect through Bash falls under the sandbox and permission rules.

Same release: Claude's file tools now ask before editing the local copy of an organization's server-managed settings, and /permissions Recently blocked refuses to approve a call it can't show you in full.

So what for TSD: Your scheduled tasks run in bypass mode across several repos (daily-reports, client sites, the vaults). Turn this on in the project settings of each client repo, Bisque first, so a confused run in one checkout can't edit another client's files with the file tools. Run it on one scheduled task for a week before rolling it out, since tasks that write to the command vault from another repo's session will start getting refused.
Changelog 2.1.314
Fix 2.1.314

claude -p stops failing silently

When startup failed, claude -p used to exit 0 with no output. It now prints the error and exits 1. Related: 2.1.312 fixed one command with an invalid name stopping every command from loading, which "could leave claude -p with no output," and 2.1.314 fixed "Continue automatically at usage limit" continuing more than three times when a task restarted itself between waits.

So what for TSD: Any shell or launchd wrapper you have around claude -p that treats exit 0 as success was previously logging green on empty runs. Check those wrappers check the exit code now, and look back at any Nash OS run log entries that reported OK with empty output.
Changelog 2.1.312 and 2.1.314
Fix 2.1.311 / 2.1.312

Big CLAUDE.md and memory files no longer get clobbered or go stale

2.1.312 fixed Claude "overwriting a very large CLAUDE.md, rules file or @-included file in a subdirectory after seeing only its start." Write now tells Claude to read the whole file or edit in place. 2.1.311 fixed Claude seeing stale MEMORY.md and CLAUDE.md content right after automatic compaction, and long freezes when a CLAUDE.md holds a very long list item.

So what for TSD: Your vault notes and INDEX.md grow past the point where a partial read is likely, and your rule is to update a note's Current state block once it passes about 30 KB. These fixes cut the main way an agent could truncate one. Update before the next vault-heavy session; no config change needed.

◆ Long sessions and effort

Feature 2.1.314

Idle compaction comes to the Desktop Code tab

In VS Code and Claude Desktop's Code tab, a conversation over 200K tokens that sits idle is summarized in the background, and that summary is used on your next message if the prompt cache has expired. It now also runs with telemetry off and, once the one-hour prompt cache is on, on Bedrock, Vertex, Foundry and LLM gateways.

Related: 2.1.311 fixed standard-context sessions stopping with "Usage credits required for 1M context" past 200K tokens (they now compact and continue), and 2.1.314 cut memory use in long headless turns that run many subagents.

So what for TSD: Most of your build sessions live in Desktop and get left open across client calls. Coming back to a big Bisque or Sonderwerks session after an hour should now pick up from a ready summary, which is cheaper than re-reading the whole history on a cold cache. If a resumed session seems to have forgotten detail, this is why; keep decisions in the repo or vault where they survive a summary.
Changelog 2.1.314
Changed 2.1.311

ultrathink now maps to xhigh effort

In the interactive terminal, ultrathink runs its turn at xhigh effort on Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1 through Anthropic's API. Typed while Claude is working, it raises the rest of that turn. The rainbow highlight now only shows where the keyword can actually raise effort. 2.1.312 also made the effort indicator say when a mid-task change will wait for your next message.

So what for TSD: You get a per-turn effort bump without touching /effort or breaking the cache for the whole session. Use it on the one hard turn in a build (a Supabase schema change, an auth flow) and leave the session at its normal level. The changelog says interactive terminal; don't assume it applies in the Desktop app until you see the rainbow there.

◆ Cloud routines and scheduled tasks

Feature 2.1.312 / 2.1.314

Cloud routines pick an effort level and load your plugins

2.1.312 added an effort level to the model picker when you create or edit a cloud routine, plus a proper Bash editor for cloud environment setup scripts. 2.1.314 made scheduled runs in Anthropic's cloud load the plugins enabled on your claude.ai account, and cloud sessions now start even when the setup script exits with an error. 2.1.312 also fixed resending an unchanged message after a failed send sometimes running it twice.

So what for TSD: Your daily scouts run as local Desktop scheduled tasks on this Mac, so they stop when the laptop sleeps. Cloud routines now carry plugins and effort settings, which removes two reasons not to move a scout like this one to the cloud. Worth a test move for one low-stakes routine; the catch is it needs git push access from the cloud environment and can't reach local-only tools like Nash OS's report script.
