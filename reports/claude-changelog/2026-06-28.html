◆ Hooks & plugins — two behavior changes worth a config pass

Breaking 2.1.195

Hook matchers exact-match instead of substring-matching

Hook matchers with hyphenated identifiers were accidentally substring-matching. They now exact-match. The changelog calls out code-reviewer and mcp__brave-search as examples, and tells you to write mcp__brave-search__.* to match every tool from a hyphenated MCP server.

This fails silently. A matcher that used to fire on a partial name will simply stop firing — no error, no warning. If a hook was your guardrail, the guardrail is just gone after the upgrade.

So what for TSD: Grep your settings.json and any loop/Fleet-Steward hook configs for hyphenated matchers before you let auto-update run. Anything pointed at a hyphenated MCP server or a named agent needs to become a regex (name__.*). The loops run unattended, so a hook that quietly stops firing is exactly the failure you won't notice until something it was supposed to catch slips through.

Fix 2.1.195

Plugins enabled only by project settings now require explicit install consent

External plugins switched on solely through a project's .claude/settings.json previously skipped the install-consent step on some loader paths. Now they require explicit consent on every path. A second /plugin fix lands alongside it: Enable/Disable now works when a plugin's plugin.json name differs from its marketplace entry name.

So what for TSD: Cloning a client repo or a template that ships a .claude/settings.json can no longer auto-enable a plugin behind your back — you get prompted. Good default. Just expect a consent prompt the first time you open repos that bundle plugin config.

◆ Background agents & remote sessions hold together better

Fix 2.1.195

Background-job durability across version upgrades

Three reliability fixes land in the same area. Background jobs no longer disappear from claude agents or lose data when they were written by a newer Claude Code version. Background agent daemons no longer run unreachable when the control socket fails to start, which had been blocking restarts entirely. And reopening a crashed background task now shows its restart instead of a blank screen for up to five seconds.

So what for TSD: This is the release for anyone leaning on background agents and scheduled loops. The cross-version data-loss and unreachable-daemon bugs are the kind that bite unattended automation specifically. Worth upgrading the machine that runs your loops, then confirming the daemons come back cleanly.

Improve 2.1.195

Agents list and Remote startup get small polish

The claude agents completed list now fills available vertical space, and on short terminals the header compacts so live sessions stay visible. Remote session startup shows a provisioning checklist while the container spins up.

So what for TSD: Cosmetic, no action needed. The provisioning checklist makes Remote startup feel less like a hang, which matters if you ever demo Remote sessions to a client.

◆ Voice dictation

Fix 2.1.195

Three dictation fixes across macOS, Linux, and non-spaced languages

On macOS, voice dictation stopped capturing silence in long sessions after the default input device changes. Auto-submit now fires for languages written without spaces (Japanese, Chinese, Thai). On Linux, voice mode now distinguishes "no microphone" from "SoX not installed" when SoX is present but there's no capture device.

So what for TSD: Only relevant if you dictate. The macOS device-switch fix is the useful one — swapping between AirPods and a desk mic mid-session no longer silently breaks dictation.
