◆ Reviews & workflows

Behavior change 2.1.202

/review is a fast single pass again — /code-review keeps the multi-agent path

The changelog reverts /review <pr> to "a fast single-pass review" and says to use /code-review <level> <pr#> for "the multi-agent review at a chosen effort level." Two commands, two jobs: quick gut-check versus the thorough sweep you pick the depth on.

So what for TSD: Retrain the muscle memory. For a fast look at a client PR, /review. When you want the real audit before a Bisque or Studio C push, reach for /code-review high (or ultra for the cloud multi-agent pass). Don't expect a bare /review to do the deep work anymore.

Changelog — 2.1.202
Feature 2.1.202

"Dynamic workflow size" setting lands in /config

A new /config setting controls how large Claude generally makes dynamic workflows — small, medium, or large agent counts. The changelog is explicit that it is "an advisory guideline, not an enforced cap," so it nudges default fan-out without hard-limiting a run that genuinely needs more agents.

So what for TSD: You run a lot of loop and workflow automation. Set this to "small" for the cheap propose-only heartbeats (the sales and site loops) so they don't over-spawn, and bump it up only for the occasional deep audit. Cheap governance on token spend without rewriting any loop specs.

Changelog — 2.1.202
Fix 2.1.202

Workflow scripts stop getting corrupted by unicode quotes; parse errors point at the line

Workflow scripts with unicode quote escapes in strings were being mangled before parsing. That's fixed, and workflow parse errors now show the offending line instead of always blaming TypeScript. The /workflows agent list also got a cleaner layout: wider titles, a dedicated time column, shorter model names, no per-row tool-call counts.

So what for TSD: If you hand-author a Workflow script and it choked before, the fix plus the pointed error message means faster debugging. Minor, but it removes a papercut from the one area where you write agent orchestration by hand.

Changelog — 2.1.202

◆ Remote Control from your phone

Fix 2.1.202

Three Remote Control bugs squashed: dropped commands, dropped files, wrong permission mode

Three separate fixes for the mobile/web Remote Control app: commands sent into an interactive session no longer fail with "Unknown command"; images and files sent without a caption are no longer silently dropped; and /remote-control sessions no longer show the wrong permission mode in the mobile and web apps.

So what for TSD: This is your desk-Mac-from-phone setup directly. The silent file-drop and wrong-permission-mode bugs were the kind that quietly bite when you're driving the headless host from the road. Update the desk Mac's Claude Code to 2.1.202 so the phone workflow is trustworthy again — the wrong-permission-mode display especially matters given your workspace-scoped trade-confirm gate.

◆ Sessions, skills, and context

Fix 2.1.202

Resuming sessions in worktree-heavy repos is fast again

Resuming a session by name, or opening the resume picker, was "taking minutes and using a large amount of memory in repositories with many git worktrees." Fixed.

So what for TSD: Your loops fix things in isolated worktrees, so your active repos accumulate them. If session resume had gotten sluggish on the TSD app or vault repos, this is why — and it's gone in 2.1.202.

Changelog — 2.1.202
Fix 2.1.202

Re-invoking a loaded skill no longer duplicates its instructions in context

Calling a skill that was already loaded appended a second copy of its instructions to the context window. That's fixed — the instructions load once. Related: the earlier stacked-skill support (2.1.199) means /skill-a /skill-b loads up to five leading skills, so this cleanup matters more when you chain them.

So what for TSD: You stack skills constantly — sales-psychology chaining the-humanizer, the advisor skills, refresh-vault. Duplicate instruction blocks were quietly eating context budget and could muddy behavior. Cleaner context per session for free after the update.

Changelog — 2.1.202
Fix 2.1.202

Background-session naming and open-chat crash loops fixed

Two background-agent fixes: /rename on a background session no longer gets reverted when the job restarts (so you can still address the session by its new name), and opening a chat from claude agents no longer sometimes fails with "currently running as a background agent" followed by a worker crash/respawn loop.

So what for TSD: Your scheduled loops and stewards run as background agents. The crash/respawn loop was a reliability hole in exactly that surface — worth the update on both Macs if you drive background jobs from the agents view.
