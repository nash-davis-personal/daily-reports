◆ The model swap

New 2.1.197 · June 30

Claude Sonnet 5 becomes the default model

Sonnet 5 ships as Claude Code's default model with a native 1M-token context window, and promotional pricing of $2/$10 per Mtok (input/output) running through August 31. You get it by updating to 2.1.197. This session is on Opus 4.8 with 1M context; the point of the change is that the everyday default now carries the big window without you reaching for Opus.

So what for TSD: Cheaper token economics on the model you'll hit most, plus a 1M window means you can drop whole client repos (Bisque, Studio C) into context without pruning. Try Sonnet 5 as the default for routine build work and keep Opus for the gnarly reasoning passes. Reassess before Aug 31, when promo pricing ends.

◆ Unattended runs got sturdier

Improve 2.1.196 · June 29

Background sessions survive a stop, restart, or update

Long-running commands and workflows now keep going when the session's process is stopped, restarted, or updated — including on Windows, where background shells are handed off instead of killed. Separately, background-agent workers killed by a daemon restart auto-resume from where they left off the next time you open the agents view.

So what for TSD: Your nightly loops (TSD site loop, sales loop, Fleet Steward, the daily scout that files this report) are exactly the workloads a mid-run auto-update used to kill. This makes unattended cadence more reliable without you babysitting the daemon.
Changelog — 2.1.196
Improve 2.1.196 · June 29

Streaming idle watchdog is on by default

The watchdog that aborts and retries when a response stream produces no events for 5 minutes is now enabled for all providers, not just an opt-in. Set CLAUDE_ENABLE_STREAM_WATCHDOG=0 to turn it off.

So what for TSD: A hung stream on an overnight run used to sit dead until you noticed the next morning. Now it self-heals. No action needed; just know the retry is happening for you.
Changelog — 2.1.196
Fix 2.1.196 · June 29

Waking a background job no longer deletes its conversation

A bug where waking a background job could permanently delete its conversation and silently re-run the original prompt — triggered when a transcript probe misread a real transcript — is fixed. The transcript file is now set aside instead of deleted, and mid-turn crash recovery for Remote sessions auto-resumes on the next worker.

So what for TSD: This is the kind of silent data-loss bug that eats a night's work with no error message. If you lean on background jobs and Remote Control (Desk Mac), take the update for this fix alone.
Changelog — 2.1.196

◆ Security & workflow economics

Security 2.1.196 · June 29

Cloned repos can no longer self-approve their MCP servers

claude mcp list and claude mcp get no longer spawn .mcp.json servers that a repo self-approved via a committed .claude/settings.json. In untrusted workspaces those servers now show ⏸ Pending approval until you say yes.

So what for TSD: You clone client and prospect repos constantly. This closes a path where a repo could quietly stand up an MCP server just by you listing its config. Treat every fresh clone as untrusted and let the pending-approval gate do its job.
Changelog — 2.1.196
Improve 2.1.196 · June 29

/code-review uses roughly 25% fewer tokens

The review workflow merged five separate cleanup finders into one, cutting token usage by about a quarter. A companion fix corrected /deep-research misreporting verifier failures as "all claims refuted" when the right label was unverified.

So what for TSD: You run /code-review on nearly every loop cycle and PR. A 25% cut compounds fast across a week of automated reviews. The deep-research fix matters too — you use that skill for prospect and market work, and a false "all refuted" verdict could have you tossing good sources.
