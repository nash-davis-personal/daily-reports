Claude Code Changelog ◆Thursday, September 17, 2026 ◆1 release in window

The endless retry loop on corrupted transcripts is fixed, and background tasks stop burning a model call each

2.1.274 (Sep 17) closes a session-killing bug: a corrupted transcript used to trigger an endless "unexpected tool_use_id" 400-error retry loop with no way out. It now self-heals where possible, or ends the loop with a clear error and a /rewind hint. Also in: headless/SDK sessions stop making a separate model call for every background task that finishes, a resumed background agent no longer drops half an interrupted tool batch, /code-review gets leaner and cheaper on models without tuned settings, and VS Code adds dedicated Memory and Instructions panels.

◆ Automation & agent reliability

Fixed 2.1.274

A corrupted transcript no longer strands a session in an infinite retry loop

Sessions could get stuck endlessly retrying "unexpected tool_use_id" 400 errors with no exit. Corrupted transcripts now self-heal where that's possible; when it isn't, the session stops with a clear error and a pointer to /rewind instead of spinning forever.

So what for TSD: This is the kind of bug that silently eats a background run's whole time budget — you'd come back to an unattended job that never actually finished. Worth knowing about if a scheduled or background session on client work ever seemed to hang for no reason; it should now fail loud instead of quiet.
Claude Code changelog — 2.1.274
Fixed 2.1.274

Background task completions no longer cost a separate model call each

Headless and SDK sessions were making one model call per finished background task. Completions already queued up are now answered by a single call instead.

So what for TSD: Directly relevant to how this scout job and any other unattended/background automation you run gets billed — fewer redundant model calls means lower token spend on the same automation work, with no behavior change to chase down.
Claude Code changelog — 2.1.274
Fixed 2.1.274

Resumed background agents stopped dropping half an interrupted tool batch

When one call in a batch of tool calls had been approved with a message, resuming a background agent afterward kept only half of that interrupted batch instead of all of it.

So what for TSD: If you approve a background agent's tool call with a note attached and then resume it later, you were at risk of silently losing part of the work it had queued. Fixed now — no workaround needed, but good to know if you noticed a background agent seeming to "forget" a step recently.
Claude Code changelog — 2.1.274

◆ Code Review & editor

Changed 2.1.274

/code-review drops the subagent swarm for models without tuned settings

Any model that doesn't have its own tuned review configuration now gets leaner inline review prompts, instead of Claude spawning many separate review subagents for that pass.

So what for TSD: If you're running /code-review against a non-default model on a client PR (Bisque, Studio C, Sonderwerks), this should mean a faster, cheaper review pass with the same coverage — worth a quick before/after check if you're billing review time or tokens on a project.
Claude Code changelog — 2.1.274
New 2.1.274

VS Code Customize menu adds dedicated Memory and Instructions entries

Memory now shows the auto-memory toggles, your saved memories, and the folders they live in. Instructions is a direct path to editing your CLAUDE.md files. Both were previously buried in general settings.

So what for TSD: You lean on memory across sessions to keep context on Bisque/Studio C/Sonderwerks work straight — this makes reviewing or pruning what's actually been saved (and fixing CLAUDE.md) a couple clicks instead of a settings hunt, if you're working from the VS Code extension.
Claude Code changelog — 2.1.274
