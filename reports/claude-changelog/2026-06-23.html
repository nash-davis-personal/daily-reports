◆ Behavior changes you'll feel immediately

Behavior change 2.1.186

! bash commands now make Claude respond to the output

Until now, a ! shell command dropped its output into context silently and waited for your next prompt. As of 2.1.186 the agent reads that output and answers automatically. If you lean on ! to stage files or check state without triggering a turn, flip "respondToBashCommands": false in settings.json to get the old quiet behavior back.

So what for TSD: Decide now, before it surprises you mid-build. If you run !git status or !ls as a quick glance during a Bisque or Studio C session, you probably want it off. If you'd rather Claude react to a failing build or a diff on its own, leave it on.
Changelog · 2.1.186
Improve 2.1.186

Background subagents surface permission prompts instead of auto-denying

Previously a background subagent that hit a blocked action got auto-denied and quietly stalled. Now the prompt routes up to the main session, shows which agent is asking, and Esc denies just that one tool. A related fix stops Esc and Ctrl+C from going unresponsive while background agents are still running after the main turn ends.

So what for TSD: This makes your overnight and multi-agent runs less of a black box. The scheduled scout and daily-report jobs that spawn agents will now ask rather than silently fail a step — worth watching the first few runs to see what they surface.

◆ Build & delivery tooling

Feature 2.1.186

Authenticate MCP servers from the command line

New claude mcp login <name> and claude mcp logout <name> commands let you authenticate or sign out of an MCP server without opening the interactive /mcp menu. --no-browser redirects the flow over stdin so you can complete it on a headless box or over SSH.

So what for TSD: You run a stack of connected MCP servers — Supabase, Vercel, Notion, Robinhood, the scheduled-task daemon. Scripting claude mcp login means you can re-auth a flaky connector in a setup script or on a remote machine instead of clicking through the menu each time a token expires.
Changelog · 2.1.186
Improve 2.1.186

/review <pr> now runs the same engine as /code-review medium

/review <pr> was a lighter pass than the dedicated review command. It now uses the /code-review medium engine, so a PR review and a local diff review apply the same depth.

So what for TSD: When you push client work to a PR — the State Farm funnels, Cohors, GrantWell — running /review on it now gives you the real medium-depth pass instead of a skim. One fewer reason to context-switch into a separate command.
Changelog · 2.1.186

◆ Agents, workflows & unattended runs

Fix 2.1.186

Workflow and named-subagent guardrails got real

Two reliability fixes for anyone running multi-agent work. Workflow agent({schema}) subagents that kept failing schema validation used to loop forever; they now abort after 5 attempts. And Agent(type) deny rules plus Agent(x,y) allowed-types restrictions are now actually enforced on named subagent spawns, closing a gap where a blocked agent type could still launch.

So what for TSD: Your multi-agent "company" workflows (the Cohors build, the 66-agent Macroscope run) are exactly the shape that hit the infinite-loop bug. This caps the blast radius of a bad schema. The permission fix matters if you ever lock down which agent models or types a run is allowed to spawn.
Changelog · 2.1.186
Improve 2.1.186

Retry cap, watchdog, and a memory-compaction nudge

CLAUDE_CODE_MAX_RETRIES now caps at 15; for unattended sessions the changelog points you at CLAUDE_CODE_RETRY_WATCHDOG instead. Separately, the agent now gets reminded to compact its MEMORY.md index when it nears the size limit.

So what for TSD: Both land on your scheduled tasks. If a daily job wedges on a degraded network, the watchdog is the lever now, not a giant retry count. And your MEMORY.md index is large and growing — the compaction reminder is a built-in cue to run a consolidation pass before it gets unwieldy.
