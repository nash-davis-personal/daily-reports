◆ The one release

Fix 2.1.227

Every Bash command failed under claude-code-action on GitHub-hosted runners

The changelog line is specific: every Bash command failing under claude-code-action with allowed_non_write_users on GitHub-hosted runners. Bash carries almost everything an agent does in CI — installs, builds, tests, git — so a workflow hitting this did not degrade, it stopped working.

The failure was scoped to that one setting on GitHub's own runners, which is exactly the kind of bug that looks like a flaky pipeline for days before anyone reads the release notes.

So what for TSD: If you have claude-code-action wired into any client repo — Bisque, Studio C, Sonderwerks — check whether it sets allowed_non_write_users, and pin the action to a version carrying 2.1.227 before you debug the workflow further. If you have been ignoring red runs on a Claude-driven job for the last few days, re-run one before you go hunting for a cause in your own YAML.

Fix 2.1.227

Expired login tokens made Max plan users look like they needed to buy credits

When a session started with an expired login token, feature flags were evaluated without the user's subscription tier attached. The visible symptom was a prompt telling Max plan users to enable usage credits for Fable — a paid-usage nudge aimed at people whose plan already covered them.

The interesting part is the mechanism rather than the prompt. A stale token silently downgraded what the client believed about the account, and the entitlement check ran on that wrong picture.

So what for TSD: If you enabled usage credits in the last week because a prompt told you to, go look at your billing settings and confirm that was a decision rather than a bug. This also joins the run of stale-token bugs from 2.1.224 and 2.1.225 — when Claude Code starts behaving as though you are on a different plan or a different auth state, re-login first and debug second.

◆ Polish on the input path

Improve 2.1.227

Fewer event-loop stalls on file suggestions and at-mention checks

The release cites performance work in two specific places: file-not-found suggestions, and at-mention size checks. Both run while you are typing, and both block the event loop when they run slowly, which is the class of lag that reads as the whole terminal hitching rather than as one feature being slow.

The slash-command menu also got a rendering pass in the same release — blue now marks only the selected row, matched characters are bolded instead of recolored, and emoji or accented command names keep their glyphs.

So what for TSD: Nothing to do here. Worth knowing only because you drive Claude Code with @ file references across large Next.js repos all day, and if the input has felt sticky in big projects, this release is the plausible cause of it feeling better rather than something you changed.
