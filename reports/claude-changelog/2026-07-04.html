◆ Two defaults that touch your scheduled fleet

Breaking default 2.1.200

AskUserQuestion dialogs no longer auto-continue

Previously an AskUserQuestion dialog would auto-continue on its own after a wait. As of 2.1.200 it doesn't — it sits and waits for a real answer unless you opt into an idle timeout through /config. In an interactive session that's fine. In an unattended run it means a session that pops one of these dialogs can hang until it hits the OS timeout instead of picking a default and moving on.

So what for TSD: Your scheduled loops run headless with no one to answer a dialog — the nightly Sales Loop, the site loop, the Grant lead-scout, the daily-reports scout, the agentic-account steward. If any of their prompts or skills can surface an AskUserQuestion, set an idle timeout in /config so an unattended run auto-advances instead of stalling to the hard OS-timeout brake. Worth a one-time /config pass on the desk Mac that hosts the Remote Control fleet.

Changelog · 2.1.200
Rename 2.1.200

The "default" permission mode is now called "Manual"

The permission mode formerly shown as "default" is now labeled "Manual" everywhere — the CLI, --help output, VS Code, and JetBrains. Both --permission-mode manual and "defaultMode": "manual" are now accepted, and the old default spelling still works alongside them. This is a naming clarification, so existing configs and scripts keep running untouched.

So what for TSD: Nothing to fix. When you next read --help or a settings doc and see "Manual" where you expected "default," it's the same mode. If you ever standardize the fleet's settings.json, "manual" is now the clearer canonical spelling to write.

◆ Background-agent reliability — the unattended stack

Fix 2.1.200

Sleep/wake and stalled-session stalls fixed

Two related bugs: background sessions could silently stop mid-turn after the machine slept and woke or when a stalled session was reopened, and a session that respawned after a stall could re-run a turn you had already cancelled with Esc. Both are fixed in 2.1.200.

So what for TSD: Direct hit on the always-on desk Mac. caffeinate keeps it awake, but any sleep/wake edge — laptop lid, power blip — could previously drop a background turn on the floor. Update the desk Mac to 2.1.200+ so the Remote Control host survives wake events without eating a run.

Changelog · 2.1.200
Fix 2.1.200

Stale daemon.lock and roster hardening

A crash could leave a stale daemon.lock whose PID the OS had since reused, which stopped background agents from ever starting again. Alongside it: daemon handover now judges build recency by an embedded build timestamp so a reinstalled older build can't seize the daemon, and a batch of roster bugs are fixed — transient corruption permanently disabling orphan cleanup, older binaries clobbering fields newer versions wrote, and socket auth tokens being stripped on daemon restart.

So what for TSD: The whole point of your scheduled fleet is that it recovers on its own overnight. A stale lock that silently bricks the daemon is the exact failure that turns a "propose-only heartbeat" into a dead loop you don't notice for days. This closes it — worth the update on every Mac running launchd-scheduled agents.

Changelog · 2.1.200
Fix 2.1.200

Rate-limited subagents return real errors, not empty results

A subagent cut off by a rate limit before it produced any text output used to return an empty result, which reads to the parent as a clean-but-blank success. Now it fails cleanly. This is the same class of bug the 2.1.199 pass targeted — subagents laundering API errors into false successes.

So what for TSD: Your Workflow fan-outs and parallel-agent reviews trust what subagents hand back. A blank "success" from a rate-limited agent means a silently skipped file in a code review or a missing lead in a scout batch. With this fix the parent sees the failure and you can retry, instead of shipping on incomplete coverage.

◆ Sonnet 5 harness + startup

Improve 2.1.201

Sonnet 5 drops the mid-conversation system role for harness reminders

Claude Sonnet 5 sessions no longer inject harness reminders using the mid-conversation system role. This is an internal prompt-plumbing change aimed at how reminders land inside a Sonnet 5 conversation.

So what for TSD: Marginal for you day-to-day — you run Opus on the important builds. But Sonnet 5's promo pricing ($2/$10 per Mtok through Aug 31) makes it the right model for the high-volume, low-stakes loop work, and cleaner reminder handling means fewer odd mid-run behaviors when you point a scout or a lead-scout batch at Sonnet 5.

Changelog · 2.1.201
Fix 2.1.200

Startup no longer crashes on a malformed MCP-server config

Setting disabledMcpServers or enabledMcpServers in .claude.json to a non-array value (a string or object instead of a list) used to crash Claude Code at startup. It now handles the bad value gracefully.

So what for TSD: You hand-edit .claude.json and the git-synced ~/.claude config across two Macs. A fat-fingered non-array in an MCP toggle used to brick startup silently; now it won't take the whole CLI down with it.
