◆ Your automations

Fix 2.1.331

Four fixes aimed at work that runs with nobody watching

MCP tool calls no longer hang for up to 30 minutes on some malformed replies from a local or WebSocket server. PushNotification now tells a headless run, such as a scheduled one, whether a mobile push was requested, where before it claimed the terminal was active during the first minute. Auto mode no longer refuses Claude's call to stop a /loop, a bug that let the next wake-up fire anyway. A Workflow agent's background shells and MCP servers no longer get left running after it hands back its report.

Two related fixes: turns and subagents that went silent while thinking now retry once, and an interrupted plugin update no longer leaves a half-installed plugin that later loads with skills missing.

So what for TSD: All 28 scheduled tasks run headless and end with a Nash OS log line, and many of them push to your phone, so these fixes land directly on that fleet. Update the terminal claude from 2.1.316 this week, then check the Machine page the next morning for any task that stopped logging. If a task has gone missing pushes before, the PushNotification bug is a likely cause.

New 2.1.331

claude doctor now says whether the API can be reached

An API connectivity section reports reachability with the HTTP status or the error, or says why it skipped the test.

So what for TSD: When an overnight task fails with no clear reason, run claude doctor first. It separates a network or auth problem from a bug in the task itself in one command.

◆ Build sessions

Fix 2.1.331

Code Mode, compaction and rewind stop dropping work

Code Mode used to lose the middle of a long script output; Claude now gets a path to the uncut text (#111373). Code Mode sessions resumed in a different permission mode no longer lose thinking and the prompt cache. /compact and auto-compact no longer drop part of the summary when it quotes certain XML tags. A rewind no longer deletes files after a restore has failed.

Also fixed: @file#10-12 mentions attached the whole file instead of those lines.

So what for TSD: A long next build or Vite log is the kind of output that could lose its middle, so a failing Bisque or Sonderwerks build may have been diagnosed from a partial log. After updating, use line-range mentions on large components to keep context lean.

New 2.1.331

VS Code gets one-click fixes for errors, failing tests and merge conflicts

The extension adds "Fix with Claude Code" as a quick fix on errors, warnings and failed tests, "Resolve Merge Conflicts" on conflicted files, "Add to Chat" on changed files in Source Control, and "Add Cell to Chat" for notebooks. Most of the release's improvements and about 60 of its fixes are for the extension.

So what for TSD: The Claude Code extension isn't installed on this Mac, so none of this applies today. Skip it unless you start reviewing client diffs in VS Code.
