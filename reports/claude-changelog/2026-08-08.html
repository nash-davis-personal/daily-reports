Yesterday's release was the feature drop. Today's is the cleanup pass behind it, and most of it lands on unattended work. The headline fix: a single transient 401 could cause Claude Code to replace a long-lived CLAUDE_CODE_OAUTH_TOKEN with a stored login's short-lived token, and every headless session stayed broken until the process restarted. ◆ Unattended sessions stop breaking themselves

Fix 2.1.225

A transient 401 replaced a long-lived CLAUDE_CODE_OAUTH_TOKEN with a short-lived one

One transient 401 was enough to make Claude Code swap the long-lived CLAUDE_CODE_OAUTH_TOKEN for a stored login's short-lived token. Headless sessions then stayed broken until the process restarted, because the replacement token expired and nothing put the original back.

The failure shape is what makes this worth reading twice: the trigger is intermittent, the damage persists, and a restart clears it. That is a bug that looks like flakiness in whatever wraps it.

So what for TSD: If any of your scheduled or cron-driven runs authenticate with CLAUDE_CODE_OAUTH_TOKEN, update before the next cadence. Then go re-read the failures you wrote off as network flakiness over the last stretch, because an auth error mid-run followed by every later turn failing is exactly this. Long-lived unattended processes were the ones exposed, and short interactive sessions mostly would not have noticed.
Changelog · 2.1.225
Fix 2.1.225

Auto mode counted a safety-filter refusal of its own permission check toward the block limit

When the safety filter refused auto mode's own permission check, that refusal was counted against the consecutive-block limit that stops a runaway session. The action is still denied. The difference is that the model is now told to move on rather than retry, so the refusal no longer walks the session toward a hard stop.

So what for TSD: This is the fix for an unattended run that dies partway through for no visible reason. If you have a loop in auto mode that touches anything the filter is twitchy about, it was capable of burning its block budget on its own permission plumbing and then quitting with work left. Worth re-running any loop you disabled for unexplained early exits.

Fix 2.1.225

Cross-session messages stayed parked in headless sessions with no notice and no expiry

Messages sent to a headless session, or to any session still starting up, sat queued indefinitely. No notice that something was waiting, and no expiry to clear it out. This is a one-day-old fix on a one-day-old feature.

So what for TSD: If yesterday's briefing prompted you to wire a handoff between two scheduled sessions, this is why it did nothing. Your scheduled runs are headless by definition, so they were the exact case that swallowed the message. Update first, then test the pair with a message you can confirm arrived rather than trusting the send.

Fix 2.1.225

MCP OAuth servers on macOS threw a burst of 401s after a keychain read timed out

When a keychain read timed out on macOS, OAuth-authenticated MCP servers intermittently failed with a burst of 401 errors, presenting as though they had never been authenticated at all.

So what for TSD: You run a long list of OAuth MCP servers on this Mac. The next time one reports itself as unauthenticated, check the version before you re-run an OAuth flow, because on 2.1.224 and earlier a keychain hiccup produced the same symptom as an expired grant. Two useless minutes each time, and it teaches you to distrust a connector that was fine.

◆ Cross-session messaging gets its initiator

New 2.1.225

SendMessage can open a conversation with a Remote Control session by name

Yesterday's cross-session messaging could only reply to a Remote Control session on another machine after that session messaged you first. Now a session can start the conversation by name, and ListAgents shows the reachable ones as name [ref].

The paired safety fix: a Remote Control recipient you have already confirmed is never silently swapped for a same-named session on the local machine when the remote list could not be checked.

So what for TSD: This is what makes a two-machine handoff actually schedulable. Until now the far side had to speak first, which no cron job does. The naming fix is the one to respect: if you name a session the same thing on the laptop and the desk Mac, you were one failed list lookup away from a message landing on the wrong box. Give them distinct names now, while you only have a couple.

◆ Spend caps and workspace trust

New 2.1.225

The usage warning now names the gateway spend limit, its reset time, and the operator's message

Claude Code's usage warning understands gateway spend limits. When the limit is reached, the message states the cap, when it resets, and whatever message the operator attached. The gateway itself has to be on 2.1.225 for this.

So what for TSD: Not actionable today unless you put a gateway in front of your own usage, and it is worth knowing as a sellable pattern. A client who wants AI features with a hard monthly ceiling gets a cap that explains itself when hit, including your own message about what to do next. That is a cleaner answer than "it stopped working" the first time a Studio C or Sonderwerks build runs into the ceiling.
Changelog · 2.1.225
New 2.1.225

claude agents now prompts for workspace trust on untrusted directories

The trust prompt that claude shows for an untrusted directory now also appears in claude agents. The two entry points behave the same way.

So what for TSD: Small, and it closes a real gap. claude agents was a way to start work in a directory that never got the trust check, which matters the day you clone a client's existing codebase to quote a modernization job. Expect one extra prompt the first time you open an unfamiliar repo that way.

◆ Remote Control and web session reliability

Fix 2.1.225

Resuming a Remote Control session broke its history after a large conversation was compacted

Conversation history broke on Remote Control session resume once a very large conversation had been compacted. Alongside it, Claude Code on the web had sessions misreported as stuck while re-sending a growing event backlog on every reconnect.

So what for TSD: Both of these bite the same habit: leaving a long build running and checking in from the phone or the web. The growing-backlog one is the worse of the two, because a session that looks stuck is a session you kill and restart, and you lose the run rather than the display.

Improve 2.1.225

Photos attached from the Claude app go straight to the model

A photo attached from the Claude app during Remote Control is now shown to Claude directly, in place of being read off disk with a separate tool call.

So what for TSD: This is the phone-to-agent loop for visual feedback. Screenshot a broken layout on the Bisque site, send it into the running session, and it lands as an image rather than a filesystem round trip. Cheap throughput win for reviewing a client build while away from the desk.
