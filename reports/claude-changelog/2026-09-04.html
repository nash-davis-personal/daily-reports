◆ Permission wall: revert + real sandbox holes

Fix 2.1.260

2.1.259 Read-deny-on-Bash-args change is reverted

Yesterday's extension of Read() deny rules to Bash arguments is gone. That change denied npm run build under a Read(./**/build/**) rule in every mode and made cd … && grep prompt even in auto mode. The Sep 3 briefing called the wider deny coverage a win; the ship broke ordinary build loops, so it came back out.

So what for TSD: After you upgrade past 2.1.259, Vite/Next build scripts stop false-denying against build-output deny rules. Keep the deny rules — they still apply to Read/Edit/Write and the older Bash shapes — but do not expect the 2.1.259 Bash-arg coverage to stick.
Claude Code changelog — 2.1.260
Fix 2.1.260

Parentheses in paths and uncompilable deny patterns left folders writable or broke every edit

Edit/Write/Read permission rules whose path contains parentheses were dropped as invalid or ignored by the Bash sandbox, which left "read-only" folders writable. A single file permission rule with an uncompilable pattern (e.g. an unclosed [) made every file edit fail with Invalid regular expression; such a deny rule now guards the literal path it spells. Bash permission checks also stop auto-approving zsh commands that hide a command substitution inside a REPORTTIME, REPORTMEMORY, or DIRSTACKSIZE assignment — those now prompt.

So what for TSD: Audit any deny/allow rules that name folders with () in the path (common on Mac project trees). After upgrade, those rules actually enforce. A typo'd pattern no longer takes down the whole edit surface — it falls back to a literal match. zsh users: REPORTTIME-style assignments can no longer smuggle a substitution past auto mode.

◆ Agent teams, rewind, and headless surface

Fix 2.1.260

Transcript loss, wrong SendMessage wakeups, phantom ListAgents twins, and false rewind success

Agent teams: an in-process teammate's transcript no longer loses messages (or goes blank) during long API retry waits under CLAUDE_CODE_RETRY_WATCHDOG. A subagent that resumed another agent via SendMessage was never woken by that agent's completion — the notification went to the main conversation; fixed. A session moved to the background appeared twice in ListAgents (phantom "interactive" twin) and received SendMessage deliveries in the viewer; fixed. /rewind and --rewind-files reported success when checkpoint backups were missing and nothing was restored; they also left stale file-read tracking that caused "File unchanged since last read" stubs. Intermittent "task output swap refused" when many sessions share a project directory is fixed.

So what for TSD: Multi-agent client builds stop dropping teammate context during retries. Do not trust a pre-2.1.260 rewind success line — verify the files. Parallel sessions on one Next.js repo should hit fewer Mac "task output swap refused" failures (the 2.1.252 fix left residual cases).

New 2.1.260

/reload-plugins in headless, text /advisor, and ! bash-mode outside strict sandbox

/reload-plugins is available in headless sessions (Desktop and SDK command lists). A text form of /advisor (/advisor, /advisor <name>, /advisor off) works in the desktop app, Remote Control, and other headless (-p / Agent SDK) sessions. Commands typed at the ! bash-mode prompt now run outside the sandbox even when strict sandbox mode (sandbox.allowUnsandboxedCommands: false) is on — same as typing into your own terminal.

So what for TSD: Headless loops and Desktop sessions can reload plugins and drive advisor without an interactive TUI. Treat ! as an intentional sandbox escape under strict mode — useful for local diagnostics, dangerous if you assume every shell line is sandboxed.
