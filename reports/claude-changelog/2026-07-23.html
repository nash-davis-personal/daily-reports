Claude Code Changelog ◆Thursday, July 23, 2026 ◆Window: v2.1.218, released July 22, 2026

Code review moves out of your conversation, and Claude stops auto-launching its expensive skills

v2.1.218 is a big single release. /code-review now runs as a background subagent so review output no longer buries your working conversation, /deep-research only starts when you type it, and skills declared context: fork now run in the background by default. It also cleans up the two ultrareview bugs that were silently doing the wrong thing.

◆ Review and research change how they run

Improve v2.1.218

/code-review now runs as a background subagent

Review output no longer fills up your main conversation. It runs off to the side as a subagent, and it keeps any slash commands you stacked as the thing it reviews. This pairs with the July 19 change (v2.1.215) that already stopped Claude from firing /code-review and /verify on its own.

So what for TSD: On a Bisque or Sonderwerks feature branch you can kick a review and keep coding in the same session without the review's findings shoving your work off-screen or eating context. Make /code-review a standing pre-merge step, not a "clear the deck first" ritual.
Claude Code changelog, v2.1.218
Behavior v2.1.218

/deep-research only starts when you ask for it

Claude no longer launches deep research on its own initiative. You have to invoke /deep-research yourself. Deep research is one of the more token-heavy things the tool can do, so this removes a class of unprompted spend.

So what for TSD: Fewer surprise bills on solo work. If you were relying on Claude to reach for research automatically, you now have to trigger it — worth a note in any skill or loop prompt that expected the old behavior.
Claude Code changelog, v2.1.218
Fix v2.1.218

ultrareview stops failing on descriptive arguments and silent downgrades

Two fixes. /ultrareview given a plain-English argument like "review my auth changes" used to fail; it now reviews your current branch and applies the text as a note on the findings. Separately, /code-review ultra was silently running a cheap local review inside non-interactive sessions instead of launching the paid cloud review — it now launches the cloud review as intended. Error feedback also improved so a bad argument gets corrected instead of retried unchanged.

So what for TSD: Your ultrareview muscle memory works again — you can describe what you changed instead of remembering exact syntax. And if you ever wire ultrareview into a scripted or scheduled run, it'll now actually do the cloud review you're paying for rather than quietly stubbing it out.
Claude Code changelog, v2.1.218

◆ Automation, skills, and auto mode

Improve v2.1.218

Fork skills run in the background by default

Skills declared with context: fork now run in the background unless you explicitly set background: false in the skill's frontmatter. Frontmatter booleans also got more forgiving this release — yes/no/on/off/1/0 are now accepted alongside true/false.

So what for TSD: Directly touches your loop and skill work. If a fork skill was assuming it ran inline and blocked the session, that assumption just flipped — audit any loop-engineering skill you built that reads results right after a fork call, and pin background: false where you need synchronous behavior.
Claude Code changelog, v2.1.218
Improve v2.1.218

Auto mode and plan mode stop over-prompting

In auto mode, the dangerous-rm, background-&, and suspicious-Windows-path checks no longer open a permission dialog — the auto-mode classifier decides them instead. Plan mode with auto also stops prompting for Bash commands the static analyzer can't prove read-only; the classifier judges those too.

So what for TSD: Less interruption when you're moving fast in auto mode on your own machine. The tradeoff is that a model classifier, not a hard rule, now gates those edge cases — fine for your solo builds, worth knowing before you lean on auto mode for anything destructive.
Claude Code changelog, v2.1.218
Security v2.1.218

Agent frontmatter hooks now require workspace trust

Agent frontmatter hooks were running from untrusted folders. Now the agent file's own folder has to have accepted workspace trust before its hooks fire. This is the latest in a run of isolation and trust-boundary fixes across recent releases.

So what for TSD: If you clone or copy an agent definition from anywhere you didn't write yourself, its hooks won't execute until you trust that folder. Good default. Keep your own reusable agents in trusted, git-tracked locations so this never trips your own work.
Claude Code changelog, v2.1.218

◆ Reliability and cost fixes worth knowing

Fix v2.1.218

Runaway retry loop after context overflow is stopped

A retry loop was re-sending identical, doomed requests after a context-overflow error when the thinking budget was large — quietly burning tokens on requests that could never succeed. Fixed. Ctrl+B backgrounding now also applies the same background-shell caps as other paths.

So what for TSD: One of the cheaper-to-ignore, expensive-in-practice bugs. On long AI-build sessions with big thinking budgets, you're no longer at risk of a silent token drain when context blows past the limit.
Claude Code changelog, v2.1.218
Fix v2.1.218

Left arrow no longer silently discards your conversation

Pressing the left arrow right after editing used to discard the conversation with no undo. Now those presses ask you to confirm, and Esc in the agent view returns you to the conversation it backgrounded instead of losing it.

So what for TSD: Straight quality-of-life. Fewer "where did my session go" moments during a long delivery day.
Claude Code changelog, v2.1.218
