Claude Code Changelog ◆Saturday, September 19, 2026 ◆2 releases in window

AGENTS.md support lands, auto mode's classifier stops billing overhead on the API, and three separate bugs that were quietly breaking prompt cache hits all get fixed

2.1.277 (Sep 18) adds AGENTS.md support, walls subagent and workflow-agent output off from being read as the session's own instructions, and fixes three unrelated bugs that were each silently busting prompt cache hits on resume. 2.1.278 (Sep 19) carries the same set forward and adds a billing change: auto mode's classifier now runs free on the server for API, Enterprise, Bedrock, Vertex, Foundry and gateway usage.

◆ Interop & cost

New 2.1.277

AGENTS.md support: a project with no CLAUDE.md now reads AGENTS.md instead

AGENTS.md is the emerging cross-tool convention other coding assistants already write. Claude Code now falls back to it when a project has no CLAUDE.md, and the choice is configurable under "Project instructions" in /config. Not yet supported on Bedrock, Vertex or Foundry.

So what for TSD: If a client repo already has an AGENTS.md from another tool in the stack, Claude Code now picks it up without you writing a duplicate CLAUDE.md. Worth checking any repo where you've used a second AI coding tool alongside Claude Code — you may be able to delete a redundant instructions file instead of maintaining two.
Claude Code changelog — 2.1.277
Changed 2.1.278

Auto mode's classifier no longer bills for its own overhead on the API

Auto mode for Claude API and Enterprise users, and on Bedrock, Vertex, Foundry and gateways, now defaults to a server-side classifier that isn't charged as extra tokens; CLAUDE_CODE_AUTO_MODE_SERVER=0 opts out on Bedrock/Vertex/Foundry/gateways, and Claude Code warns if it falls back to a billed classifier. A new "Auto mode server" row in /status shows which one a session is using.

So what for TSD: This only matters if you're calling Claude through the API or a gateway rather than a Pro/Max subscription — for example if you're metering Claude usage inside a client-facing AI feature you built. If any TSD build uses Auto mode over the API, check /status for the new "Auto mode server" row to confirm you're getting the free classifier, not the billed fallback.

◆ Cost & reliability

Fixed 2.1.277

Three separate bugs were each quietly breaking prompt cache hits

Sessions continued after /clear (restart, --continue, --resume) were missing part of their first message when a SessionStart hook printed output, causing a full cache miss. Resumed subagents and teammates were re-rendering the MCP tool definitions they'd already loaded, breaking cache for that agent. And attachments recorded earlier in a conversation were being re-rendered after a resume or relaunch, which dropped extended thinking and missed the cache too. All three are fixed.

So what for TSD: Same theme as yesterday's memory-file cache fix — three more independent leaks in the same area, all plugging silent cost. If you run hooks on session start, resume subagents/teammates in workflows, or work in long sessions with attached files or images, this should show up as lower spend on resumed work without you changing anything.
Claude Code changelog — 2.1.277
Fixed 2.1.277

Messages typed while Claude is still working were sometimes ignored

Messages sent mid-turn could be dropped by the model instead of being queued and processed. Fixed.

So what for TSD: If you've had a follow-up instruction silently vanish while Claude was mid-task on a client build, this was a live cause, not you mistyping or the UI eating it. No action needed.
Claude Code changelog — 2.1.277

◆ Agent & workflow security

Changed 2.1.277

Subagent and workflow output can no longer pass as the session's own instructions

Subagent results now reach the main agent under a header marking them explicitly as subagent output, with the result indented. Separately, workflow scripts' computed agent() prompts reach the subagent framed as script-authored text, so the safety classifier doesn't mistake them for the user talking.

So what for TSD: Direct relevance if you're delegating research or fan-out work to subagents or Workflow scripts that touch untrusted content — a scraped page, a client's ticket text, a PR description. Previously, text in that content designed to look like an instruction had more room to slip through as if it came from you; this closes part of that path. No workflow changes needed on your end.
Claude Code changelog — 2.1.277
Changed 2.1.277

/ultrareview gives clearer guidance and now fully reviews a new repo's first commit

When there's nothing to review, /ultrareview now says which case you're in and offers a command that reviews your latest commit instead of a vague message. A brand-new repository's first commit gets a full review rather than being skipped. Separately, non-interactive sessions now refuse to run /ultrareview when the repository has no base branch or shared history.

So what for TSD: Relevant the next time you spin up a fresh client repo (a new Sonderwerks build, say) and want a review pass on day one — the first commit no longer gets silently skipped. If you ever script /ultrareview into an automated or headless run, know it will now refuse cleanly instead of erroring on a repo with no history yet.
Claude Code changelog — 2.1.277
