◆ Throughput: the long-session tax got cheaper

Fix v2.1.216

Quadratic message normalization was making long sessions crawl

In long sessions the cost of normalizing messages grew quadratically with the number of turns. The symptom was multi-second stalls and slow resumes on big conversations. That is now fixed.

Two smaller companions landed alongside it: /context now warns explicitly when the conversation has exceeded the context window, and a failed /compact displays as an error instead of quietly doing nothing.

So what for TSD: If you have been reflexively running /clear on the Bisque or Sonderwerks build sessions because they got sluggish after an hour, stop doing that. Update, then let a session run its full length. The stall you were working around was a bug, and you were paying for it in re-explaining context.
Changelog ◆ v2.1.216
Improve v2.1.216

Skills and commands edited mid-session now appear without a restart

Previously a skill or slash command you changed during a session stayed invisible to the slash menu until you restarted Claude Code. Now the change lands live. Plugin skills that declare a name in frontmatter also stopped losing their plugin prefix in autocomplete.

So what for TSD: This is the write-test-write loop you actually use when authoring skills. Editing a skill and immediately invoking it in the same session is one step now instead of three, which makes it cheap to keep tightening the scout, sales, and vault routines rather than leaving them at v1.

◆ Isolation: three ways an agent could write where it shouldn't

Fix v2.1.216

Worktree-isolated subagents could redirect git back into the shared checkout

A subagent running with worktree isolation could point git at the main checkout using git -C, --git-dir, or the GIT_DIR and GIT_WORK_TREE environment variables. Isolation held for ordinary file writes and leaked on git operations. Two related fixes shipped with it: worktree sessions could land in another project's leftover worktree when the working directory did not match the selected project, and background sessions whose worktree had no git repository were undeletable.

This is the second pass at the same class of bug. v2.1.210 fixed isolated subagents running git-mutating commands against the main checkout; 2.1.216 closes the flag and environment-variable routes.

So what for TSD: Worktree isolation is the entire safety argument for letting a loop run unattended against a client repo. Until you are on 2.1.216, treat any parallel-agent run on Bisque or Studio C as capable of touching the main checkout. Update before the next unattended sweep, then confirm with git -C <repo> status that the main checkout is clean when a run finishes.
Changelog ◆ v2.1.216
Fix v2.1.216

Workflow saves and scheduled-task writes followed a symlinked .claude out of the project

If .claude was a symlink, workflow saves and scheduled-task writes followed it and could land outside the project directory. /rewind got the same treatment separately: it no longer restores or deletes files through symlinks or hard links at tracked paths, and it reports how many paths it skipped.

So what for TSD: You run scheduled tasks daily, including this briefing. Any repo where .claude is symlinked to share config across projects was a write-redirect waiting to happen. Worth running find ~/Documents -maxdepth 3 -name .claude -type l once to see whether you have any.
Changelog ◆ v2.1.216
New v2.1.216

sandbox.filesystem.disabled separates filesystem isolation from network egress control

New setting: sandbox.filesystem.disabled skips filesystem isolation while keeping network egress control in place.

So what for TSD: Useful for builds that legitimately need to write across the filesystem (Vercel CLI cache, pnpm store, Supabase local stack) while you still want egress restricted. Reach for this before you disable the sandbox entirely, which is the move you would otherwise make the first time a build fails inside it.

◆ Unattended and background sessions

Fix v2.1.216

Token rotation and resume no longer break running agents

Three failures in the same area got fixed. Auto mode was denying commands with "HTTP 401" classifier errors after the OAuth token expired or rotated mid-session. Resumed background agent sessions were reverting to the default agent, losing the agent's own prompt and tool restrictions; both are restored now. And background subagents were being cancelled when a high-priority message arrived during their startup window.

On the cloud side, sessions that dropped their in-flight message when the container restarted mid-turn now re-run the interrupted turn on resume instead of going unresponsive, and Claude Code on the web stopped re-asking the same question and discarding your answer after a few idle minutes.

So what for TSD: The reverting-to-default-agent bug is the one that quietly cost you work. A resumed background agent that lost its tool restrictions was doing a different job than the one you dispatched. If any background run from the past week produced output that looked off-brief, that is a plausible cause worth checking before you blame the prompt.
Changelog ◆ v2.1.216
Improve v2.1.216

Blocked background sessions surface what they need instead of hanging

/mcp and /install-github-app in a background session now park a "needs input" request in the agent view when no client is attached. MCP re-authentication stopped revoking working credentials before the new sign-in succeeds. AskUserQuestion no longer tells Claude to continue when your free-text answer asked it to wait or explain first.

So what for TSD: The MCP re-auth fix matters most here. Re-authenticating Supabase or a client MCP server could previously leave you with no working credentials if the new sign-in failed, in the middle of a build. That failure mode is gone.
