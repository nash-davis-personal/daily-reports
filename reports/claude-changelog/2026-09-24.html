2.1.281 fixes the failure modes that break scheduled and headless Claude Code jobs

The day after Opus 5.5 landed, 2.1.281 ships as a large maintenance release almost entirely about the mechanics of unattended work: wakeup delivery failures that could kill a session, a --max-turns guard that could be silently ignored, and settings restrictions that weren't reaching spawned subagents. It also gives auto mode a report card and closes a rm -rf "$(pwd)"-shaped hole in the dangerous-command guard.

◆ Scheduled & headless job reliability — the class of bug that kills runs like this one

Fix 2.1.281

Scheduled tasks and /loop wakeups firing every second on a failed delivery could end the session

When a scheduled task or a /loop wakeup failed to deliver, it used to retry immediately and repeatedly instead of backing off — and that spin could make Claude Code exit at the end of a turn.

So what for TSD: This scout job runs unattended off a schedule, and the loop/wakeup mechanism is exactly the kind this bug hit. If a past scheduled run ever vanished with no filed report and no visible error, this is a plausible cause — nothing to change now, just don't rule it out when auditing old runs.
Claude Code Changelog — 2.1.281
Fix 2.1.281

Scheduled routine and notification turns in remote sessions acted before getting turn-start context

Newly available tools, MCP changes, the current date, and todos are normally sent to the model at the start of a turn. In remote sessions, scheduled routine and notification turns weren't getting that context until after the first tool call already ran.

So what for TSD: This is scoped to remote/cloud sessions, not this local-clone job — but if any TSD automation ever moves to Claude Code on the web or a hosted routine, this closes a case where the first action of a scheduled run could fire without the model knowing today's date.
Claude Code Changelog — 2.1.281
Fix 2.1.281

--max-turns could be ignored while a turn retried indefinitely

When the model alternated between unparseable tool calls and output-limit truncation, a turn could keep retrying forever — ignoring the --max-turns cap that's supposed to be the hard stop.

So what for TSD: If any headless job (this one included, or anything run via -p) relies on --max-turns as a runaway-cost guard, that guard could have silently failed. Worth trusting it as a real ceiling again — and worth double-checking token spend on any old run that looked unusually long.
Claude Code Changelog — 2.1.281
Fix 2.1.281

--setting-sources restrictions weren't forwarded to spawned sessions

A parent session's --setting-sources restriction (or the SDK's settingSources) wasn't being passed down to teammates, /bg sessions, claude agents sessions, or --worktree --tmux sessions — they started with no restriction at all.

So what for TSD: Relevant to any TSD tooling that spawns subagents or background sessions from a locked-down parent — a restriction you thought applied everywhere wasn't actually inherited. No action needed now that it's fixed, but a good reminder that inheritance across spawned sessions isn't something to assume without checking.
Claude Code Changelog — 2.1.281

◆ Auto mode — safer, and now measurable

New 2.1.281

/insights adds an auto mode recommendation

/insights now estimates how many permission prompts auto mode could have handled in your recent sessions, turning "should I turn this on" into a number instead of a guess.

So what for TSD: Run /insights before deciding whether to flip auto mode on for lower-stakes, repetitive work — bulk content or styling passes for Bisque or Studio C — versus keeping prompts on for anything touching Supabase schema, auth, or payment code on Sonderwerks or client-facing builds.
Claude Code Changelog — 2.1.281
Fix 2.1.281

A command-substitution rm -rf could run unprompted under auto mode

A recursive rm whose target is entirely command-substitution output — rm -rf "$(pwd)" is the example given — was running without a prompt in auto mode and --dangerously-skip-permissions mode. It now asks even with a Bash allow rule, unless overridden with CLAUDE_CODE_DISABLE_SUBSTITUTION_RM_PROMPT=1.

So what for TSD: If any TSD automation runs with auto mode or skip-permissions enabled, this closes a real gap in the safety net. The broader takeaway: keep those modes scoped to directories that are backed up or disposable, since edge cases in the dangerous-command guard are still being found.
