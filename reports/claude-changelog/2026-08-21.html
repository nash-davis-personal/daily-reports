Claude Code Changelog ◆Friday, August 21, 2026 ◆1 release ◆ 2.1.238

2.1.238 is a 39-entry repair release, and three of its fixes are for failures you would never have seen happen.

The headline item is a memory leak: long interactive sessions grew without bound because subagent tool results were never released, and they now get dropped once they scroll out of the recent display window. Underneath that sit two silent-failure fixes in cross-session messaging and one bug where custom output styles drifted back to the default voice partway through a session.

◆ Top signals — read these first
01

Long sessions were leaking memory on every subagent call

Subagent tool results are now released once they leave the recent display window. Before this, a long session that fanned out to subagents grew without bound for the life of the process.

02

Custom output styles were drifting back to the default voice mid-session

Custom, project and plugin output styles all had this bug. If you set a house voice and it seemed to stop holding halfway through a session, that was real.

03

Cross-session messages could disappear without telling the sender

A refusing inbox reported a silent success, and a session that dropped messages to a rate limit or a full queue said nothing at all. Both now report back.

04

Plugin marketplaces can now mint their own auth headers

headersHelper runs a command that produces HTTP headers — a short-lived token, for instance — for catalog and same-origin archive fetches. Private marketplaces behind auth become practical.

05

Remote Control got a thirteen-entry reliability pass

Messages sent mid-turn no longer vanish from the transcript, phone model picks now reach the terminal, and a brief network hiccup no longer disconnects you with "login expired".

06

The double-press Ctrl+L shortcut for /clear was removed

Ctrl+L and Cmd+K in fullscreen now always just repaint. If you had muscle memory for the double press, it is gone — and 1-row nvim terminals stop triggering automatic /clear loops.

◆ Failures you could not see

Fix 2.1.238

Unbounded memory growth in long interactive sessions

The entry is specific about the cause: subagent tool results were being held for the life of the session, and they are now released once they leave the recent display window. The more you fan out to subagents, the faster the session grew.

This is the profile of a session that gets sluggish after a few hours of heavy work and comes back fine after a restart. That symptom had a real cause, and this release removes it.

So what for TSD: Take the update before your next long build session. Your Explore-and-fan-out pattern on client work is exactly the shape that triggered this, and if you have been restarting Claude Code mid-afternoon to get responsiveness back, stop budgeting for that.
Claude Code changelog — 2.1.238
Fix 2.1.238

Cross-session messaging now admits when a message did not land

Two separate entries. Sending to a session on this machine that refuses inbound messages — one running crossSessionInbound: "refuse", for example — reported a silent success to the sender; it now reports "refused". And a session whose inbox drops messages to a rate limit or a full queue now tells the sending session, where before the messages simply vanished.

Both are the worst class of bug for automation. A coordinating session had no way to distinguish "delivered and being worked" from "gone", so it waited on a reply that was never coming.

So what for TSD: This is a direct fix for your loop and steward designs. Any handoff where one session messages another and waits was previously trusting a success signal that could be fiction. After the update, add explicit handling for a "refused" result on those sends, since it is now a state you can actually observe.
Claude Code changelog — 2.1.238
Fix 2.1.238

Output styles stopped holding partway through a session

Custom, project and plugin output styles were drifting back to the default voice mid-session. The style stayed selected; the behavior reverted underneath it.

Worth reading against yesterday's 2.1.237, which shipped the built-in "Concise" style. A style setting is only worth adopting if it survives the whole session, and until this release it did not reliably do that.

So what for TSD: If you tried a custom output style, decided it was not sticking, and went back to carrying voice rules in ~/.claude/CLAUDE.md, re-test that decision on this build. Moving the durable voice rules into a style frees room in your global instructions for actual client context.

◆ Plugins, MCP, and the trust boundary

New 2.1.238

headersHelper puts plugin marketplaces behind real auth

On a url marketplace or a catalog entry, headersHelper runs a command that mints HTTP headers — the changelog gives a short-lived token as the example — for catalog and same-origin archive fetches. A catalog entry's helper runs only when you install or update that plugin, after its command is shown to you, and claude plugin install/update prompt [y/N] unless you pass -y.

The confirmation design matters as much as the capability. You see the command before it runs, and it runs on install and update rather than on every catalog read.

So what for TSD: This makes a private TSD plugin marketplace worth building. Your skills, subagents and delivery conventions could ship as versioned plugins from an authenticated endpoint instead of being copied between machines by hand. That is also the mechanism you would need if you ever package tooling for a client to install on their own.
Claude Code changelog — 2.1.238
Improve 2.1.238

Header helpers from untrusted folders now need the trust dialog, and lose your credentials

Two hardening entries land alongside the new capability. An MCP headersHelper in a project .mcp.json, and inline MCP servers in project or --add-dir agent files, now require that folder's trust dialog to have been accepted — including under claude -p. And a headersHelper coming from a project .mcp.json, a plugin, or an agent file runs without inherited credential environment variables, while user, managed and claude.ai-scope helpers run from the Claude config dir.

Read plainly: a repo you cloned can no longer define a command that runs with your API keys in its environment just because you opened the folder.

So what for TSD: Check whether any of your project-level .mcp.json files rely on inheriting credentials from your shell, because those will now come up empty. If a helper genuinely needs a secret, it has to source it itself. Also expect a trust prompt on claude -p runs in folders you had not explicitly trusted, which is worth knowing before it surprises a scheduled task.
Claude Code changelog — 2.1.238
Fix 2.1.238

Lazy stdio MCP servers stopped being woken on every session open

Stdio MCP servers were receiving a server/discover request before initialize, which forced lazy servers to start their backend every time a session opened. Separately, claude mcp list and claude mcp get now show disabled servers as ⊘ Disabled instead of connecting to them for a health check.

So what for TSD: You run a long list of MCP servers. Both changes cut startup work you were paying on every single session open, and the disabled-server change means the ones you switched off stop costing you a connection attempt.

◆ Remote Control, thirteen entries deep

Fix 2.1.238

Phone and web sessions now stay in sync with the terminal

The cluster worth knowing: messages sent from web or Desktop while Claude was mid-turn disappeared from the transcript once the turn finished; model picks made on a phone or web did not update the model shown in the terminal; a session whose process crashed stayed unavailable until claude remote-control was restarted, and can now be reused when you next message it. Per-task Stop from the tasks panel did nothing on CLI-hosted sessions.

Connection handling improved too. A brief network delay in renewing your sign-in was disconnecting you with "login expired" and now retries, brief HTTP 403 refusals from a network edge, VPN or proxy are tolerated for up to three minutes with the refusing party named when a block persists, and signing out now ends the session with a clear message.

So what for TSD: Remote Control becomes trustworthy enough to actually use for checking a long build from your phone between classes. The mid-turn message fix is the one that mattered most, since a queued instruction that silently evaporated meant you thought you had redirected a run and had not.
Claude Code changelog — 2.1.238
Fix 2.1.238

ListAgents and SendMessage work from server-mode and Desktop hosts

Both tools were reporting "Remote Control is not connected" in sessions run by claude remote-control in server mode, or by Desktop and IDE hosts, and now list and reach Remote Control peers properly. A second entry stops them exposing the idle worker that the agent view pre-warms for your next background session; it appears only once a task claims it.

So what for TSD: If you tried to wire session-to-session coordination from the Desktop app and concluded it was not supported, that was a bug. The pre-warmed worker fix also removes a phantom peer that any "message every idle session" logic would have picked up and tried to talk to.

◆ Terminal behavior worth knowing about

Changed 2.1.238

Ctrl+L and Cmd+K always just repaint now

The double-press shortcut for /clear was removed, and 1-row nvim terminals no longer trigger automatic /clear loops. Alongside it, a new keybindingFlavor setting takes "readline" to make Ctrl+W delete back to the previous whitespace as in Bash; the default "classic" is unchanged.

The Ctrl+L change is the only item in this release that removes behavior you might be relying on. Clearing context is now an explicit /clear.

So what for TSD: Low stakes, but it will feel wrong for a day. If you live in Bash keybindings elsewhere, set keybindingFlavor to "readline" and stop losing whole paths every time you reach for Ctrl+W.
Claude Code changelog — 2.1.238
Improve 2.1.238

Startup got out of its own way

Bare claude starts sooner on macOS, and the automatic update check now runs about ten seconds after launch instead of competing with startup for CPU.

So what for TSD: Nothing to do. It compounds quietly given how many times a day you open a session across the client repos.
