◆ Fixes that touch how you actually run Claude Code

Fix 2.1.176 · Jun 12

Hook if conditions for Read/Edit/Write paths now match the documented patterns

Hook conditions written the way the docs show them — Edit(src/**), Read(~/.ssh/**), Read(.env) — were not matching. They are now. If you ever wrote a hook to guard secrets or scope a check to a directory and quietly gave up because it never triggered, it was this bug.

So what for TSD: Worth a 10-minute pass. A Read(.env) / Read(**/.env.local) deny-or-warn hook across the client repos (Bisque, Studio C, the funnels) is cheap insurance against pasting a Supabase or Resend key into a transcript. If you tried this before and it silently failed, retry it now.

Fix 2.1.176 · Jun 12

/cd and worktree moves no longer report the old directory's git branch

After a /cd or a worktree switch, the session kept showing the branch from the directory you left. That fed a wrong branch into the statusline and anything that reads current-branch state. Fixed.

So what for TSD: Relevant given how much you lean on worktrees for the parallel-build pattern across Praxis, Catena, and the funnels. One less way to commit or push against the branch you think you're on. No action needed beyond the update.
Changelog · 2.1.176
Fix 2.1.176 · Jun 12

Background-agent search by PR URL now finds PRs opened during scheduled wakeups

If a background job opened a PR during a scheduled wakeup, or while the job was blocked, that PR didn't surface when you searched claude agents by its URL. It does now.

So what for TSD: Directly useful for the scheduled-task pattern you already run (the daily-reports scout, Frontier lessons). When an overnight job ships a PR, you can now find its session by pasting the PR link instead of hunting the list.

◆ The two new settings (minor)

New 2.1.176 · Jun 12

Session titles in the conversation language; footerLinksRegexes footer badges

Session titles are now generated in whatever language your conversation is in — pin one with the language setting if you want. Separately, footerLinksRegexes lets user or managed settings add regex-matched link badges to the footer row.

So what for TSD: Skip both for now. Neither moves throughput. footerLinksRegexes is the kind of thing a larger team uses to surface internal dashboards; note it exists, no reason to wire it up solo.
