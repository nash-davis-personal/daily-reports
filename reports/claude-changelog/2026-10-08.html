◆ Guardrails and unattended runs

Fix 2.1.294

prompt and agent hooks written as instructions allowed what they should block

A hook phrased as an instruction, such as "Block commands that...", was letting those commands through. 2.1.294 fixes that. The same release changes how instruction-style prompt hooks on Stop and SubagentStop (such as "Carry on if the build is broken") are judged, so Claude is less likely to stop early.

So what for TSD: Any guardrail you wrote as a plain-English hook may have been doing nothing. Update to 2.1.294, then open the hooks in ~/.claude/settings.json and each client repo and test every prompt/agent hook with a command it should refuse. Priority: anything guarding the Bisque Vercel scope, production deploys, or destructive Supabase SQL.
Changelog 2.1.294
Fix 2.1.293

Claude no longer retracts or redoes finished work after a context compaction

Claude sometimes treated its own last actions before a compaction as done after it, and retracted or redid work that was already complete.

So what for TSD: This hits long sessions hardest: big refactors, multi-hour client builds, the commercial pipeline. If you have seen a duplicate commit, a re-run migration or a reverted edit right after a compaction, this was the likely cause. Update before the next long build.
Changelog 2.1.293
Reverted 2.1.293

Two earlier changes rolled back: the cloud wakeup fix and the auto mode denial message

The 2.1.290 fix for cloud sessions staying asleep after a container restart lost a pending /loop wakeup or scheduled task is reverted. Per the changelog, Claude is no longer told, and the session stays asleep. Also reverted: the 2.1.281 auto mode denial message that told Claude a denial covers the outcome as well as the exact command.

So what for TSD: Tuesday's briefing reported that cloud hole as closed. It is open again. Keep anything that must fire on the hub Mac under launchd, and treat a cloud /loop or cloud scheduled task as best-effort until a new fix lands. The Nash OS run log is your check that a job ran.
Changelog 2.1.293

◆ Daily driving

Fix 2.1.293

Path-scoped rules and nested CLAUDE.md files load when Claude reads through Bash

Rules scoped to a path and CLAUDE.md files in subfolders did not load when Claude viewed a file with a single-file cat, head, tail, sed -n or grep command in the Bash tool. They loaded only through the Read tool. Now both routes load them.

So what for TSD: Any per-folder rules or nested CLAUDE.md files in client repos were being skipped whenever Claude peeked at a file with cat. If Claude ignored a nested rule recently, this explains it. No action beyond updating.
Changelog 2.1.293
Fix 2.1.293

Remote Control: push notifications, queued messages and streaming

PushNotification reported "Remote Control inactive" in sessions started with claude remote-control; fixed. A message sent while Claude was working was lost when ← moved the session to the background; now, if a queued message can't move, ← stays put and says so. ← no longer backgrounds a session after 10 seconds while the prompt holds unsent text or a question is waiting. Very long Remote Control and cloud sessions stream replies again, and a session's starting history is no longer re-uploaded after every credential recovery.

So what for TSD: Your standing rule is a push to your phone when a task runs long or needs a decision. Sessions launched with claude remote-control were silently failing that step. After updating, send one test push from a remote-control session to confirm it reaches the phone.
