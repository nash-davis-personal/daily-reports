Claude Code Changelog ◆Wednesday, August 19, 2026 ◆1 release ◆ 2.1.235

2.1.235 is a repair release. The two entries that matter are a prompt-cache bug and a permission-prompt keystroke.

Nineteen changes shipped, one of them an opt-in spellchecker and the rest cleanup. Read it anyway for two reasons: language-server disconnects had been invalidating the entire prompt cache mid-session, and Shift+Tab inside a permission prompt's comment field had been approving the edit and granting session-wide edit permission.

◆ What this costs you in tokens and machine

Fix 2.1.235

Whole-prompt-cache invalidation when a language server flapped

The changelog entry is one line: "Fixed whole-prompt-cache invalidation when a language server disconnected or reconnected mid-session." The consequence is larger than the line. A cache miss on the prompt prefix means the next turn pays full input price for everything already in the conversation.

Language servers disconnect for ordinary reasons. A TypeScript server restarting after a big dependency install, an editor reload, a machine waking up. On a long session in a large repo, each of those was a full re-charge of the conversation prefix.

So what for TSD: This is the entry that pays for reading today's release. Your heaviest sessions are exactly the profile that got hit: long Next.js builds for Bisque and Studio C with a TS language server attached and an IDE extension connected. Update before the next long build session rather than after it.

Improve 2.1.235

Background cloud sessions stopped thrashing the host session

Cloud sessions such as /ultrareview and /autofix-pr had their event streams re-scanned and re-rendered on every update while they ran in the background. That work is gone, so memory and CPU use during those runs drops.

So what for TSD: You kick off /code-review ultra and keep working in the same terminal. The cost of doing that just went down, which makes it more reasonable to fire a review on a client branch and continue building instead of waiting it out.
Claude Code changelog — 2.1.235
Improve 2.1.235

The embedded grep hardened, and its context flags were wrong

Two changes to the grep bundled with native macOS and Linux builds. Pathological patterns now fail fast rather than exhausting memory, and -m N used together with -A or -C now prints the correct context.

The second half is the one to register. Any search you ran with a match limit plus context lines could have been showing you the wrong surrounding code.

So what for TSD: If a recent search across a client repo looked like it proved a pattern was safe to change, re-run it on the new build before you trust it. This is a native-build fix, so it applies to the macOS binary you run on this machine.

◆ Permissions and approvals

Fix 2.1.235

One keystroke was approving the edit and widening permission for the session

Shift+Tab pressed inside the permission prompt's comment field approved the edit and granted session-wide edit permission, when the expected behavior was closing the comment field. Shift+Tab is also the permission-mode cycle key, which is how a habitual keystroke turned into a silent grant.

Nothing in the changelog says how long this was live. Treat it as a reason to look at what a session was allowed to do rather than a reason to panic.

So what for TSD: You approve fast and you type Shift+Tab reflexively to flip modes. If a recent session on a client repo made edits you did not remember approving individually, this is a candidate explanation. Check git diff and the branch history on anything you shipped in the last few days before assuming the diff was reviewed.
Claude Code changelog — 2.1.235
Improve 2.1.235

Dialogs now match the grant, and withhold "don't ask again" when they cannot show you everything

Permission dialog display text and the "don't ask again" option are now aligned with what the grant would actually cover. When the contents cannot be fully displayed, the "don't ask again" option is withheld rather than offered blind.

Related in the same release: notebook cell delete and replace approval dialogs used to silently omit the existing cell content when the notebook or cell could not be read. The dialog now says why it is empty.

So what for TSD: Fewer blanket grants made on incomplete information. Expect slightly more prompting in sessions where tool input is large or unreadable, and take that as the dialog doing its job instead of a regression to work around.
Claude Code changelog — 2.1.235
Fix 2.1.235

The Agent tool was advertising an agent that was not there

In sessions where the general-purpose agent is unavailable, the Agent tool still advertised it as the default. Omitting subagent_type in those sessions now returns a clear error listing the agents that do exist.

So what for TSD: Relevant to your scheduled and headless runs, where the available agent set differs from your interactive setup. A spawn that used to fail vaguely now names its options, which makes an unattended job's failure readable when you check it the next morning.

◆ The one new thing, plus prompt-input repair

New 2.1.235

Optional spellcheck in the prompt input

A new opt-in spellcheck setting underlines misspelled words in the prompt as you type. It uses whichever of aspell, hunspell or ispell you already have installed, so it does nothing until one of those is on the machine.

So what for TSD: Marginal for code prompts. Mildly useful when you draft client-facing copy in the prompt box, which you do for Studio C and Sonderwerks content. Install aspell via Homebrew first or the setting is inert.
Claude Code changelog — 2.1.235
Fix 2.1.235

Three rendering bugs in the thing you look at all day

Nested markdown list items were misaligning at depth three and deeper, and wrapped list items now get a hanging indent. Prompt input highlights for slash commands, keywords and mentions were appearing shifted by one or more characters in some multi-line prompts. Slash commands run while Claude was responding rendered HTML entities instead of the actual characters.

So what for TSD: No action. Worth knowing that deep nested lists in agent output were previously misaligned in the terminal, so a plan you read as flat may have been nested.
