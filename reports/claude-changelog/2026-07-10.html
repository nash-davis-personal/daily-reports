◆ MCP stops failing silently

Fix 2.1.206

Per-server request_timeout_ms was being ignored in fresh sessions

MCP servers configured through --mcp-config or .mcp.json ignored a per-server request_timeout_ms, which meant every long-running MCP tool call timed out at the 60-second default in a fresh session. Anything you raised that value for was silently getting the default.

So what for TSD: If you ever bumped a timeout for the tsd-portal MCP or a slow Notion query and concluded the setting did nothing, it genuinely did nothing. Re-check any timeout you tuned by trial and error, because the values you landed on were fitted to a bug that no longer exists.
Claude Code changelog — 2.1.206
Fix 2.1.206

OAuth MCP servers no longer need manual re-auth after one failed token refresh

A single failed refresh was enough to knock an OAuth-backed MCP server out until you re-authenticated by hand. The same release also fixed --permission-prompt-tool pointing at an MCP server crashing with "MCP tool not found" on cold start, before the server finished connecting.

So what for TSD: This is the whole OAuth connector shelf — Notion, Gmail, Calendar, Vercel, Calendly. Scheduled jobs that woke up to a dead connector and needed you at the keyboard should now heal themselves. Worth re-enabling any connector you disabled in a cron task because it kept demanding a login.
Claude Code changelog — 2.1.206

◆ Unattended sessions fail legibly

Fix 2.1.206

An expired login stopped pretending to be a model problem

An expired login used to fail every model with "There's an issue with the selected model." It now prompts you to run /login. This lands on top of 2.1.203's warning that fires before your login expires, so the two together close the loop on the most confusing failure in a background fleet.

So what for TSD: Every hour you have spent switching models to chase a phantom availability problem was an auth problem. When a scheduled job — this changelog scout included — dies overnight, read the error at face value now.
Claude Code changelog — 2.1.206
Improve 2.1.206

Background agents upgrade in the background; the agents view got cleaned up

Background agents now upgrade to a new version right after a Claude Code update instead of paying a slow stale-session upgrade the moment you attach. Alongside that: the agents view status column uses the full terminal width instead of truncating at 64 characters, Ctrl+X permanently removes a completed session, sessions stopped rendering twice, deleted background jobs stay deleted, and claude rm no longer leaves the removed job in the daemon roster.

A related fix: CLAUDE_CODE_EXTRA_BODY was being silently ignored by claude agents and --bg workers. The shell-exported override now follows the dispatching session.

So what for TSD: The attach stall was the main reason checking on a background agent felt slower than just doing the work. If you park agents on the Bisque or Sonderwerks builds while you take client calls, that friction is gone and the roster finally reflects reality.

New 2.1.206

/doctor proposes trimming checked-in CLAUDE.md files

A new /doctor check reads your committed CLAUDE.md and proposes cutting content Claude could derive from the codebase on its own. It is a proposal, so you review before anything changes.

So what for TSD: Run it once per client repo. Anything describing file layout or which framework the project uses is dead weight burning tokens on every turn. What survives the trim is the stuff worth keeping: deploy quirks, the proxy.ts convention on the Next 16 apps, the no-Co-Authored-By rule on Vercel-Hobby repos.

◆ Git and worktree ergonomics

Feature 2.1.206

/commit-push-pr respects your push remote; EnterWorktree asks before wandering

/commit-push-pr now auto-allows git push to the repo's configured push remote — remote.pushDefault, or the sole remote when only one is configured — in addition to origin. Separately, EnterWorktree asks for confirmation before entering a git worktree outside the project's .claude/worktrees/ directory. /cd also picked up directory path suggestions, matching /add-dir behavior.

So what for TSD: The push-remote change kills a permission prompt on any client repo where the remote is not literally named origin. The EnterWorktree confirmation is a real guardrail for the loop-style automations you run unattended — an agent can no longer silently start editing a checkout outside the sandbox it was scoped to.
