◆ Context and throughput

New 2.1.261

/skill-doctor shows which loaded skills go unused and what they cost

The changelog entry is plain: it shows "which loaded skills go unused and what they cost in context, so you can prune them." That is the first built-in measurement of a cost you have been paying blind. Every skill description sits in the system prompt of every session on this machine — the advisor roster, the vault skills, the Vercel plugin set, the Anthropic bundle.

2.1.261 also adds --append-subagent-system-prompt-file, which reads a subagent's system prompt from a file when it is too large for the command line.

So what for TSD: Run /skill-doctor the first session after you update, and cut anything it flags as unused. The advisor skills and the client-specific ones are worth their weight; a hundred descriptions you never invoke are pure tax on every Bisque and Studio C session, and they also make the prompt prefix churn more often. Use the subagent-prompt-file flag for the loop scaffolding so the skeptic and steward prompts live in version control instead of a shell string.
Changelog · 2.1.261
Feature 2.1.261

bashOutputMaxChars and taskOutputMaxChars raise inline output to 128K

Both settings control how much command and background-task output Claude receives inline before it is saved to a file, and the ceiling is 128,000 characters. Today the truncation is the reason a long next build failure or a full Vitest run gets summarized down to a file path and then re-read a chunk at a time.

So what for TSD: Raise bashOutputMaxChars in your global settings once you are on 2.1.261 — Next.js build and type-check output is exactly the shape that gets clipped right before the useful stack frame. Raise taskOutputMaxChars too if the scheduled loops hand back long reports. Watch the token cost on the sessions that run builds repeatedly; a 128K dump is not free.
Changelog · 2.1.261
Improve 2.1.261

/context stops spending extra requests to count tokens

When the token-counting API is unavailable, /context now falls back to a local estimate instead of firing extra small-model requests. Related: the /model picker and the VS Code model pill now show a model's name instead of its raw Bedrock, Vertex AI, or gateway ID when Claude Code recognizes it.

So what for TSD: Minor, and it removes a small mystery line item from usage. Nothing to configure.

◆ Behavior changes that will surprise you

Breaking 2.1.261

Prompt word-editing keys switched to Bash semantics and keybindingFlavor was retired

Verbatim from the changelog: "Changed the prompt's word-editing keys to match Bash: Ctrl+W deletes back to whitespace, Alt+F and Alt+D stop at word end, punctuation separates words; keybindingFlavor no longer has any effect."

Ctrl+W deleting back to whitespace means a path like src/app/api/route.ts disappears in one keystroke where the old behavior would have stopped at a slash. If you set keybindingFlavor at any point, that setting is now inert and silently ignored.

So what for TSD: Expect your muscle memory to overshoot for a day after updating. Check whether keybindingFlavor is still sitting in your ~/.claude/settings.json and delete the line so it does not read as live config to future-you. If you have a custom ~/.claude/keybindings.json, this is the moment to confirm it still does what you think.
Changelog · 2.1.261
Safety 2.1.261

Diagram-renderer links now count as an upload, and rm -rf detection got wider

Auto mode now treats a link that packs content into a public diagram renderer's URL as an upload to that site, so it is no longer auto-approved unless you asked for it. That is the mermaid.live / kroki pattern, where the diagram source is base64'd into the URL and therefore sent to a third party.

The dangerous-rm safety prompt also widened to catch rm -rf on positional parameters and inside double-quoted sh -c scripts.

So what for TSD: This one has a client-confidentiality edge. Any time you render an architecture diagram of a client system through a link like that, the content leaves your machine. If you want diagrams in briefings and proposals, keep drawing them as inline SVG or fenced mermaid in the artifact, where nothing gets shipped to a public renderer.
Changelog · 2.1.261

◆ Agent, loop, and session reliability

Fix 2.1.261

Background agents stop pinning the CPU, and teammates stop missing the prompt cache

Two entries land on the same surface you automate against. First: "Fixed sustained high CPU usage when a background agent could not be resumed and its wake-up was retried in a tight loop." Second: "Fixed in-process agent-team teammates re-sending their first-turn tool and skill announcements on the second turn, which changed the request prefix and missed the prompt cache."

A third one matters for long sessions: resuming a session was losing hook output and other context around parallel tool calls, which changed the resumed request.

So what for TSD: If you have ever come back to this Mac and found a fan spinning with no visible session, the retry loop is a candidate explanation. The cache fix is money — a changed request prefix on turn two means the whole prefix reprices at full rate on every teammate turn. Both are reasons to get the scheduled tasks and the Fleet Steward loops onto 2.1.261 or later before the next unattended run.
Changelog · 2.1.261
Fix 2.1.261

Remote Control and SDK sessions get a stop button that actually stops

The batch: SDK and cloud sessions were ignoring a Stop or interrupt sent just after the first prompt, before the turn had started, and would run to completion regardless. Remote Control sessions showed a stuck spinner after a stop from a phone or browser, showed a stale permission mode when a device attached, and uploaded a /teleport-pulled session into the connected one so it appeared appended to the original. SendMessage to an offline Remote Control session on another machine used to read as delivered; it now says delivery is queued until that machine reconnects.

So what for TSD: Relevant the moment you drive a session from your phone between Charlotte site visits. The interrupt fix is the one worth knowing: before this, killing a run right after sending it did nothing, and it billed the whole turn.

◆ The VS Code half of the release

Feature 2.1.261

26 of the 67 entries are VS Code, led by in-IDE MCP server management

The additions: an Add server form and a Remove action in the MCP servers dialog, so servers can be added and removed without leaving the IDE; a "Build a custom style" walkthrough in the Output styles menu that writes the file and lists it immediately; a fold button on permission and question prompts so you can read the conversation behind them; "Archive session" in the session list right-click menu; and a hollow ring marking sessions open elsewhere. The model picker became one flat list of every model, with older model spellings listed last.

The rest is a long tail of session-list, tab-group, and teleport fixes.

So what for TSD: The MCP add/remove form is the practical one — your MCP config is large and several servers currently fail to connect. Being able to add and remove them from inside the editor beats hand-editing JSON and restarting. Ignore the rest unless you live in the VS Code extension.
