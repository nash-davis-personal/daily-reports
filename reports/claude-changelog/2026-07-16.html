2.1.211 stops background agents from faking their own results

Yesterday's report closed at 2.1.210. Since then a single release shipped, and it is the most automation-relevant one in a while: the fix that stops a background agent from reporting a fabricated result instead of waiting for the real one lands squarely on how your scheduled loops behave when you are not watching. It also gives stream-json subagent text and thinking, makes "always allow" survive across worktrees, and hardens the hook-ask floor under auto mode.

◆ Unattended agents got more honest

Improve 2.1.211

Background agents report real status instead of a made-up result

Per the changelog, Claude now "reports the status of still-running agents and waits for the real completion instead of fabricating results." This is the failure mode that is nearly invisible in a scheduled run: a dispatching session that declares a background agent "done" with an outcome it never actually observed, then acts on it.

So what for TSD: This is the single most important line in the release for your Fleet Steward-style loops. Any loop where one session fans out to background agents and then reads their results — a nightly fix pass, a skeptic verifier — was exposed to fabricated completions. Update before your next scheduled run, and if you have loops that logged suspiciously clean results this week, re-check them.
Claude Code Changelog · 2.1.211
New 2.1.211

Subagent text and thinking now forward into stream-json

New --forward-subagent-text flag and CLAUDE_CODE_FORWARD_SUBAGENT_TEXT env var "include subagent text and thinking in stream-json output." Until now, a headless pipeline driving Claude Code could see the top-level agent's stream but not what its subagents actually said or reasoned.

So what for TSD: If you pipe claude -p into any harness that captures stream-json — cycle notes, metrics ledgers, a workflow that logs each subagent's finding — turn this on to get real observability into multi-agent runs instead of a black box. It is the difference between "the loop did something" and a reviewable trail.
Claude Code Changelog · 2.1.211
Fix 2.1.211

Killed agents stop auto-respawning, and subagent model pins survive resume

Two reliability fixes for multi-agent work: background agents you kill no longer auto-respawn and re-run stale prompts from old sessions, and subagents spawned with an explicit model override no longer revert to the parent's model when resumed or sent a follow-up. Separately, /loop no longer hides its session from /resume after a single use.

So what for TSD: If you pin a cheaper model on a mechanical subagent to control cost, that pin now actually holds across resumes. And a loop you kill stays killed. Both remove silent surprises from unattended runs — the kind you only notice on the bill or in a corrupted output.
Claude Code Changelog · 2.1.211

◆ Permissions and hooks, tightened for auto mode

Fix 2.1.211

A hook's ask now beats auto mode for unsandboxed Bash

Previously auto mode could override a PreToolUse hook's ask decision for unsandboxed Bash. Now "a hook ask now floors the decision at a prompt." The hook is treated as a hard minimum, so it can force human confirmation even when auto mode would otherwise let the command through.

So what for TSD: Your propose-only guardrails depend on hooks doing exactly this. If any of your loops run auto mode with a PreToolUse hook gating dangerous Bash, that gate was leaky until now. This is a correctness fix for the guardrail, not a nice-to-have — patch it in.
Claude Code Changelog · 2.1.211
Improve 2.1.211

"Always allow" rules now save at the repo root

Per the changelog, approvals granted in a git worktree now persist "across sessions and worktrees" because the rule saves at the repository root. Before, an approval you granted inside one worktree did not follow you to the next.

So what for TSD: Your loops run in worktrees on purpose. This means you approve a tool once and every future worktree run inherits it, instead of re-prompting per worktree. Fewer stalls in unattended runs, less permission-fatigue when you are driving manually across branches.
Claude Code Changelog · 2.1.211
Fix 2.1.211

Approval previews can no longer be visually spoofed

Permission previews relayed to chat channels now neutralize "bidirectional-override, zero-width, and look-alike quote characters, so tool inputs cannot visually alter the approval message." The Agent tool was also hardened against indirect prompt injection via content a subagent read (that hardening landed in 2.1.210; the preview neutralization is new in 2.1.211).

So what for TSD: When you approve a relayed tool call from your phone, the text you see is now the text that runs — a crafted filename or argument can't render one thing and execute another. Relevant the moment a loop touches untrusted input: a scraped page, a client-supplied file, a PR comment.

◆ Session and connection stability

Fix 2.1.211

Parallel sessions no longer all log out on wake-from-sleep

When many sessions shared one credential store, waking the Mac from sleep logged them all out at once. Also fixed: plugin MCP servers not reconnecting after an idle web session woke (MCP calls kept failing until the next message), and background jobs on LLM-gateway auth coming back "Not logged in" after the daemon respawned them.

So what for TSD: You run parallel sessions across two Macs and lean on scheduled/background jobs. Each of these was a way for an overnight run to silently die on an auth blip. Less babysitting after the machine sleeps.
