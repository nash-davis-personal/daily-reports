◆ Hooks and guardrails

Changed 2.1.300

Hooks that rewrite tool input are now held to the tool's own schema

When a PreToolUse or PermissionRequest hook returns updatedInput, Claude Code now validates it the same way it validates Claude's input. Unknown keys get dropped. If the tool rejects the rewritten input, the call is denied outright.

So what for TSD: Any hook of yours that injects extra fields or rewrites Bash commands will now be silently trimmed or turned into a denial. Grep your ~/.claude/settings.json hooks for updatedInput and run one test call each before tonight's scheduled jobs fire.
Changelog, 2.1.300 Changed
Fix 2.1.300

Agent hooks honor their model and stop allowing on failure

Agent hooks were ignoring their model setting. Aliases like haiku now resolve, a subagent's model no longer overrides the hook's, and an unavailable model falls back to the caller's model where it used to let the action through.

So what for TSD: If you run a cheap Haiku agent hook as a reviewer gate, it was probably running on the bigger model and costing more, and a model hiccup meant a silent pass. Pair this with yesterday's onFailure: block and your gates finally fail closed end to end.
Changelog, 2.1.300 Bug fixes
Fix 2.1.300

A rejected MCP tool schema no longer bricks the conversation

If the API rejected one MCP tool's input schema, every turn failed with a 400. Claude Code now sends that tool without parameters for the rest of the conversation. A related fix tells Claude about an MCP server's tools right away when the server finishes connecting after a compaction.

So what for TSD: You run 20-plus MCP servers (Higgsfield, Supabase, Vercel, Square, your own nash-os and tsd-portal). One sloppy schema in a custom server used to kill a long session. If you saw unexplained 400 loops, this was likely it; still worth validating schemas in your own servers since the degraded tool loses its parameters.

◆ Mods and workflows

New 2.1.300

agent.spawn can rewrite workflow agents; new prompt hooks and view control

The agent.spawn mod hook can now rewrite a workflow agent's prompt and model; before, it could only refuse them. Also new: a prompt.change hook for non-typed edits (history recall, clear, undo, plugin fill), virtualText prompt decorations that never enter the submitted prompt, and $.ui.view({ agentId }) to put an agent's transcript in the main view.

So what for TSD: You can now enforce house rules on workflow fan-outs centrally, such as forcing reviewer agents to a cheaper model or appending the voice rules to every writing agent's prompt, without editing each script. That is a concrete cost lever on the commercial and steward loops.
Changelog, 2.1.300 Added
Changed 2.1.300

Local transcripts now record system prompts, tools and request parameters

Each API request's system prompt, tool list and parameters are now written to the local session transcript so a shared transcript can reproduce a request exactly. Separately, the built-in plugin-authoring skill now scans a mod's files for keys before opening them when sharing.

So what for TSD: Your system prompt carries client context and your CLAUDE.md rules. Treat any transcript as containing that before you hand it to a client or post it for debugging. Useful the other way too: you can now replay an exact failing request when a skill misbehaves.

◆ Unattended runs and cost visibility

Fix 2.1.300

Remote Control, background commands and exit hooks behave under load

claude remote-control servers now retry after a brief sign-in error such as a locked keychain, and warn when you need claude /login. Remote Control sessions are no longer marked stopped while running on a machine serving several. SessionEnd hooks run when you exit with a background command still going, and exit now force-kills background commands still alive after 1.5 seconds. Claude also stops polling or sleeping on a background command's output file.

So what for TSD: Your phone-to-Mac flow and the scheduled scouts both depend on these. A locked keychain overnight used to drop Remote Control for good. Note the breaking bit: --sandbox and --no-sandbox on claude remote-control now exit with an error, so check any launchd plist that passes them.
Changelog, 2.1.300 Changed and Bug fixes
New 2.1.300

OpenTelemetry splits cache writes by lifetime and adds GenAI span attributes

The api_request event gains cache_creation_5m_tokens and cache_creation_1h_tokens. Trace spans now carry GenAI semantic-convention attributes like gen_ai.provider.name, gen_ai.tool.name and error.type.

So what for TSD: 1-hour cache writes cost more than 5-minute ones, and your scheduled loops lean on the 1-hour TTL. If Nash OS ever ingests OTel, this is the field that tells you which runs are paying for long-lived cache they never reuse. Low priority until you wire telemetry.
