◆ Workflow & throughput

Feature 2.1.191

/rewind can now resume from before a /clear

Previously /clear was a one-way door — wipe the context and the prior conversation was gone. Now /rewind reaches back across the clear and lets you pick up where you were before you ran it.

So what for TSD: Your safety net when you clear too aggressively mid-build. When you've been deep in a Bisque or Studio C session, clear to free up context, then realize you needed the earlier thread, /rewind recovers it instead of forcing a cold restart.
Claude Code changelog · 2.1.191
Improve 2.1.191

Streaming uses ~37% less CPU; long sessions leak less memory

Text updates during a streaming response now coalesce into 100ms batches instead of painting on every token, cutting CPU by roughly 37%. A separate fix reduces memory growth from the terminal output cache over long sessions.

So what for TSD: Directly helps your default working pattern — multiple concurrent sessions and background agents on one machine. Less fan-spin and less slowdown on the long all-day sessions you run for delivery work.
Claude Code changelog · 2.1.191

◆ Hooks & permissions

Fix 2.1.191

Hooks with comma-separated matchers were silently never firing

A matcher like "Bash,PowerShell" would register without error and then never run. No warning, no failure — it just quietly did nothing.

So what for TSD: Audit your hook configs. If you ever grouped multiple tools into one matcher with a comma, that hook has been dead and any guardrail or automation it enforced was never running. Split-or-verify it now that the fix is in.
Claude Code changelog · 2.1.191
Fix 2.1.191

/permissions "Recently denied": approvals now persist on close

Approving a previously denied tool from the Recently-denied tab used to be silently discarded when you closed the panel. It now sticks.

So what for TSD: When you reverse a denial to unblock a build step, it actually saves now — no need to re-approve the same tool every session.
Claude Code changelog · 2.1.191

◆ Agents & sandboxes

Fix 2.1.191

Stopped background agents no longer come back to life

Background agents could resurrect themselves after being stopped. Stopping an agent from the tasks panel is now permanent.

So what for TSD: Real control over your agent fleet. When you spin up overnight build runs and kill one that's going sideways, it stays dead instead of quietly restarting and burning tokens.
Claude Code changelog · 2.1.191
Improve 2.1.191

Sandbox network "Yes" is remembered for the session

Allowing a host in the sandbox network permission dialog with "Yes" now remembers it for the rest of the session, instead of re-prompting on every single connection to that host.

So what for TSD: Far fewer interruptions during sandboxed builds that hit the same APIs repeatedly (Supabase, Vercel, an Anthropic or OpenAI endpoint). Approve the host once and the build keeps moving.
Claude Code changelog · 2.1.191

◆ MCP reliability

Improve 2.1.191

MCP capability discovery and OAuth now retry transient errors

Capability discovery (tools/list, prompts/list, resources/list) now retries transient network errors with short backoff. MCP OAuth discovery and token requests retry once after a transient failure, and headless environments skip the browser popup and go straight to the paste-the-URL prompt. HTTP 404 errors now show the offending URL and point to your MCP config.

So what for TSD: You run a lot of MCP servers (Notion, Vercel, Robinhood, Calendar, Gmail). Fewer servers will fail to connect on a flaky network hiccup, and when one does misconfigure, the 404 now tells you which URL to fix instead of leaving you guessing.
