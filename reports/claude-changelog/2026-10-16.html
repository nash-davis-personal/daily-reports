◆ Unattended runs and agents

New 2.1.301

Retry watchdog can give up on a usage limit that resets too far away

Unattended retry mode (CLAUDE_CODE_RETRY_WATCHDOG) previously waited out a usage limit however long the reset took. The new CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS sets a ceiling; past it, the request ends.

So what for TSD: Set this on the scheduled tasks (this scout, the daily reports, Fleet Steward loops) to something like an hour. A run that dies at a limit now logs --fail to Nash OS the same morning, where before it sat silently until the window reset and collided with the next day's run.
Changelog, 2.1.301
Fix 2.1.301

Workflow agents skipping their step while the run reported success

After reading the harness note that their task text carries no user authority, workflow agents sometimes skipped the step, and the workflow still reported success. A second fix stops workflow scripts from asking for permission or being refused when read, edited or re-run after a Bash cd in the same session.

So what for TSD: Any multi-agent workflow you trusted on a "success" before 2.1.301 (review fan-outs, verification passes on client repos) may have had a silent no-op step. If one of those results fed a client deliverable for Bisque, Studio C or Sonderwerks this month, re-run it on 2.1.301 before relying on it.
Changelog, 2.1.301 bug fixes
Fix 2.1.301

Quitting removed hook-created worktrees that held unpushed commits

A worktree made by a WorktreeCreate hook was removed on quit without asking, even when it might hold unpushed commits. It now asks.

So what for TSD: If a loop or session ever "lost" work you remember committing in a worktree, this is a likely cause. Update, and keep pushing worktree branches before quitting anyway.

◆ Models and context

Improved 2.1.301

Switching to a smaller-context model now summarizes with the old model first

When a conversation is too long for the model you switch to, the previous model now summarizes it before the switch. A matching fix stops that summary from spending usage credits without asking first. Separately, conversations behind an LLM gateway that reports a different model name than requested no longer compact over and over on a model you didn't pick.

So what for TSD: Dropping from a long Opus build session to a cheaper model for cleanup work is now safe to do mid-session. Expect a prompt about credits the first time it happens.
Changelog, 2.1.301
Fix 2.1.301

The fable and best aliases fall back instead of erroring

On the Anthropic API, when the newest Fable model isn't available to your organization, Claude Code now retries once on the previous Fable model.

So what for TSD: Scripts and scheduled tasks that pin fable or best stop hard-failing on a rollout gap. Check the transcript's model name if output quality matters for a client run.
Changelog, 2.1.301 bug fixes

◆ Tool correctness

Fix 2.1.301

Grep and Glob no longer report "no matches" when the search itself broke

If the search program failed before returning results, both tools reported zero matches. They now return an error saying the search failed. The Read tool also stops reading binaries such as .xlsm, .parquet, .epub and .heic as text.

So what for TSD: A false "nothing uses this" is how an agent deletes a live component or misses an env var reference in a Next.js app. This closes that hole. The .heic fix matters for client photo drops (salon and shop phones shoot HEIC).
Changelog, 2.1.301 bug fixes

◆ Mods and telemetry

Changed 2.1.301

Mod hook .catch and $.env.set behave differently

A mod hook's .catch now runs only when the hook itself throws or times out; events raised beneath the hook's own calls skip that hook without consulting .catch. $.env.set now resolves with {} on success or { deny } with a reason. Mods also gain multi-line Input fields via rows, and trees above the question dialog can hold Markdown and up to 48 rows outside the terminal.

So what for TSD: If any of your mods relied on .catch firing for nested events or ignored $.env.set's return, check them today. Otherwise no action.
Changelog, 2.1.301 changed
Feature 2.1.301

OpenTelemetry tool decisions now say who blocked what

tool_decision events gain classifier_verdict and permission_mode, plus classifier_category (the built-in rule matched) when OTEL_LOG_TOOL_DETAILS=1. The claude-api skill also picked up OpenTelemetry tracing guidance.

So what for TSD: Only useful if you ship OTel from your loops. If a scheduled run keeps getting blocked, this tells you whether it was auto mode's classifier or your own permission rules.
