◆ Autonomous agents & sandboxing

New 2.1.271

Auto mode gets per-command domain scoping

Bash, PowerShell and Monitor commands running under auto mode with sandboxing can now declare allowed_domains. The hosts a specific command needs are reviewed alongside it and opened for that command alone — every other host stays refused. Previously auto mode's network access was coarser: broad allow or a refusal.

So what for TSD: If you run unattended jobs (this daily scout is one) under auto mode, this is the control you want — a command that needs to hit one API doesn't get blanket network access. Worth tightening any existing auto-mode automation to use it.
Claude Code changelog — 2.1.271
New 2.1.271

Subagents can now skip CLAUDE.md entirely

omitClaudeMd in agent frontmatter (or in the --agents JSON flag) lets a custom or plugin subagent run without loading the user, project and local CLAUDE.md files. Managed policy files still load regardless.

So what for TSD: Useful for narrow-purpose subagents (a linter, a one-off data-transform agent) where the parent project's CLAUDE.md conventions are irrelevant noise. Cuts prompt weight and avoids the subagent inheriting rules meant for a different task.
Claude Code changelog — 2.1.271
Improved 2.1.271

Dynamic workflows survive hitting a usage limit

A dynamic workflow that runs into a usage-limit ceiling now pauses and continues automatically once the limit resets, instead of dropping the agents that were mid-run. A related fix: cloud sessions were rejecting every subagent tool call with a schema-validation error when a workflow or agent approval landed after the session's worker restarted — that's fixed too.

So what for TSD: If you're running multi-agent workflows against a Pro or Max plan cap, this removes a real failure mode — a long fan-out job no longer silently loses work when it bumps the ceiling. Lower risk running bigger workflows unattended.

◆ Billing & client delivery

New 2.1.271

modelPricing now supports a markup multiplier

The modelPricing managed setting and the Claude apps gateway's pricing block accept a multiplier above 1, up to 10, for marking up internal chargeback rates on top of actual model cost.

So what for TSD: This is built for internal chargeback, not straight client rebilling — read the actual setting docs before leaning on it for invoicing Bisque, Studio C or Sonderwerks. Worth a look if you want a defensible, built-in way to mark up usage rather than tracking it by hand.
Claude Code changelog — 2.1.271
Fixed 2.1.271

Code Review stops double-posting and re-flagging resolved findings

Three Code Review bugs fixed: the same findings posting two or three times when GitHub errored on a review that actually succeeded; a security finding re-appearing after a later push moved the lines it was anchored to, even though a person had already resolved it; and reopening a finished /ultrareview cloud session in the Claude app restarting the whole review unprompted.

So what for TSD: If you've enabled Code Review on client repos, this was noise clients would notice — duplicate comments and re-litigated findings look sloppy on a PR. Cleaner now if you're using it as part of what you sell as quality assurance.
Claude Code changelog — 2.1.271

◆ Throughput

Improved 2.1.271

Fast mode now works in Remote sessions

Fast mode is now available in Claude Code Remote sessions — both cloud and self-hosted runners. It follows the host's fast-mode setting, or an in-session /fast, wherever the org allows it.

So what for TSD: If you kick off remote/background Claude Code runs (CI-style jobs, this scout job's own automation pattern), they can now run at fast-mode speed instead of standard — worth turning on if your org allows fast mode.
