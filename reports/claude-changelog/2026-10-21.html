◆ Agents and unattended runs

Fix 2.1.305

Workflow resume no longer pays twice for finished agents

Resuming a Workflow run re-ran pipeline() and parallel() agents that had already completed, instead of serving their results from the run's journal. That's fixed. Separately, scheduled Cowork cloud sessions had more cases fixed where each subagent waited five minutes on a WebFetch URL approval nobody was there to give.

So what for TSD: If you resumed a killed or edited multi-agent workflow recently and the token bill looked high, this is why. Update before the next resume; the journal-based resume now works the way it's documented.
Changelog, 2.1.305 bug fixes
Fix 2.1.306

MCP-heavy sessions stop reporting the wrong error

In sessions with many MCP tools, a real API error was replaced by “prompt is too long” and triggered a compaction that wasn't needed. 2.1.306 also fixes claude -p inside cloud sessions reporting “Not logged in” when started without the session's environment variables.

So what for TSD: If a client repo with several MCP servers (Supabase, Vercel, browser tools) kept compacting early or died with “prompt is too long”, that was likely a masked error. Re-run it on 2.1.306 and read the actual error before trimming MCP servers.
Changelog, 2.1.306
Feature 2.1.305

Unattended retry mode notices lifted usage limits

New CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS lets unattended retry mode (CLAUDE_CODE_RETRY_WATCHDOG) re-check and notice a usage limit that was lifted before its reset time.

So what for TSD: Your Nash OS hub jobs run unattended. If any use the retry watchdog, set this so a job resumes when limits lift early instead of sleeping until the scheduled reset.
Changelog, 2.1.305 added

◆ Providers, sandbox and MCP config

Fix 2.1.305

2.1.304 broke every request behind some gateways; 2.1.305 fixes it

A 2.1.304 regression made every request fail on Vertex, Bedrock and other providers when the endpoint or a gateway rejected tool search, and behind gateways where ToolSearch was disallowed or left out of --tools. Claude Code now retries without it.

So what for TSD: If you run anything through Bedrock, Vertex or a custom ANTHROPIC_BASE_URL (including any client setup you've wired that way), skip 2.1.304 and go straight to 2.1.305 or later.
Changelog, 2.1.305 bug fixes
New 2.1.305

sandbox.allowNestedUserNamespaces lets Chromium run sandboxed on Linux

Sandboxed commands on Linux can now create user namespaces, which Chromium and rootless podman need. The changelog says plainly that this lets them get around the sandbox's file protections.

So what for TSD: Useful for Playwright or headless-Chrome checks on client sites in Linux cloud or CI sessions. Turn it on only in repos where you'd accept a weaker sandbox, and leave it off everywhere else.
Changelog, 2.1.305 added
Changed 2.1.305

allowedMcpServers can now let a previously blocked server load

allowedMcpServers stops filtering managed-mcp.json stdio servers that use ${VAR} only in env. A server your allowlist left out now loads on upgrade; use deniedMcpServers to keep it off.

So what for TSD: Only matters if you use managed MCP config. If you do, check what loads after upgrading and add explicit denies for anything that shouldn't.
Changelog, 2.1.305 changed

◆ Usage and Code Review

Improved 2.1.305

/usage warnings become one-key fixes

Each /usage warning is now a one-line fix that names its source, and pressing f applies the fixes. The same fixes show up in VS Code and /doctor. Rows also no longer get cut off in narrow terminals.

So what for TSD: Run /usage once on your main machine and apply what it suggests. Cheap way to find config that's burning tokens across every client project.
Changelog, 2.1.305 improvements
Fix 2.1.305

Code Review re-reviews stop saying LGTM with blockers open

Re-reviews no longer open with LGTM while earlier blocking findings are still open. Code Review also now reviews the newest commit when several pushes land on a PR during a review.

So what for TSD: If you use Code Review on client PRs, a re-review LGTM now means more. Still read the findings list before merging, since earlier re-reviews could have been misleading.
