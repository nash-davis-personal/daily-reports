◆ Guardrails that stop failing open

Feature 2.1.295 · 2.1.299

Hooks that crash, time out or can't answer can now block the action

2.1.295 adds onFailure: "block" for command and HTTP hooks: a hook that can't start, times out, or exits with an unexpected code blocks the action instead of letting it through. 2.1.299 makes the same rule the default for plugin hooks: an action the hook can block is refused when the hook can't be handed it or can't answer, and a tool that already ran has its result withheld. 2.1.299 also fixes plan mode running a write that a PreToolUse hook or a mod's tool.check hook allowed, and on Windows, PreToolUse and PermissionRequest hooks with no shell set failed open when Git for Windows wasn't installed.

Related: UserPromptSubmit hooks now run before a skill or custom slash command expands, so a hook that blocks the prompt also stops the command's embedded shell lines.

So what for TSD: Add "onFailure": "block" to every command hook that guards something destructive: production Vercel deploys, Supabase migrations, anything touching a client's live data. A guard that silently dies is worse than no guard because you stop watching. Five-minute job: grep ~/.claude/settings.json and each client repo's .claude/settings.json for "hooks" and add the key.

Breaking 2.1.299

MCP allow rules and agent tools: lists match only the server they name

mcp__a no longer allows a server named a__b or a_. To allow a server, write mcp__<server>__* with the server's whole normalized name. Agent tools: lists changed the same way: a server whose name contains __ must be listed as mcp__<whole name>__*. 2.1.299 also fixes deny and ask rules not applying when a server's normalized name contains a double underscore.

So what for TSD: If an unattended job or custom agent suddenly starts prompting for (or getting denied on) Supabase, Vercel or GitHub MCP tools after the update, this is why. Search your settings and .claude/agents/*.md for bare mcp__ prefixes and rewrite them to the mcp__server__* form before the next hub run.
Changelog 2.1.299
Fix 2.1.296 · 2.1.299

Edit no longer corrupts files that aren't UTF-8

2.1.296: Edit and NotebookEdit replaced every non-ASCII character in files that are not valid UTF-8 (Windows-1252, Shift-JIS, GBK); such edits are now refused. 2.1.299: Read no longer garbles UTF-16LE files with a byte-order mark, and Write no longer drops byte-order marks or silently converts Windows-1252, Shift-JIS, GBK or UTF-16BE files to UTF-8 (now refused).

So what for TSD: The danger zone is client-supplied data: old CSV exports from a salon POS, product spreadsheets, legacy site HTML. If Claude edited one of those and accents or curly quotes turned into junk, this was it. Now you'll see a refusal instead; convert the file to UTF-8 first, deliberately, and commit that as its own step.

◆ Cost and long-running work

New 2.1.299

Idle compaction: long sessions compact before the prompt cache expires

In the terminal, a conversation over 200K tokens left idle for about 54 minutes is now compacted before its one-hour prompt cache expires, so your next message doesn't reprocess the whole thing. CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS changes the 200K minimum; "idleCompaction": false in settings.json turns it off. 2.1.299 also adds /usage warnings for max effort, workflows, always-on context and large tool results.

So what for TSD: Your usual pattern of leaving a big client build session open over lunch or a call now costs less on return. The trade-off is that you come back to a compacted context. If a session holds detail you need verbatim (a long spec review, a tricky migration), turn it off for that repo in .claude/settings.json. Run /usage once this week to see which of the new warnings fire on your setup.
Changelog 2.1.299
Feature 2.1.296 · 2.1.299

More control over what subagents and workflow agents cost

2.1.296 adds autoCompactWindow to subagent frontmatter and --agents definitions, so a subagent can compact earlier than the main conversation; CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL runs every workflow agent on one model while other subagents keep theirs; and an allow_large option lets Read take a whole large text file in one call when context has room. 2.1.299 adds /effort and /fast in agent view to set what new sessions start with. Also in 2.1.296: /cost, the status line and --max-budget-usd now price Sonnet 5.5 cache reads at $0.10 per million tokens (was $0.20).

So what for TSD: For fan-out work (audits, multi-page content passes for Bisque or Sonderwerks) set CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL to a cheaper model and keep the main loop on Opus. The Sonnet 5.5 cache-read figure is the one to use when you quote the running cost of a client chatbot with a long cached system prompt; verify it on Anthropic's pricing page before it goes in a proposal.

Fix 2.1.299

Scheduled tasks and loops: DST and wrong-minute fixes

Scheduled tasks and loops fired again after every turn, or early, during the repeated hour when daylight saving time ends; fixed. The scheduling tools now report each job's actual next run time instead of announcing the wrong minute. ScheduleWakeup now fires while a background task runs in Agent SDK, IDE and claude remote-control sessions. Background sessions started with --safe-mode no longer silently leave safe mode when woken or restarted.

So what for TSD: US daylight saving ends Sunday, November 1. Get every machine that runs Claude /loop or scheduled tasks onto 2.1.299 before then, or expect a burst of duplicate runs between 1 and 2 a.m.
