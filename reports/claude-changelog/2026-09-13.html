Fix 2.1.270

Read-only git commands stopped spuriously asking for permission mid-session

2.1.269 introduced a bug where read-only git commands in Bash — things like git status or git log that should already be allow-listed — started unexpectedly re-prompting for permission after a session had been running for a while. 2.1.270 fixes it; that's the entire release.

So what for TSD: If an unattended run got hit with a stray permission prompt on a git read in the last day, that was this bug, not a config problem on your end. Nothing to change — just confirms you weren't misconfiguring permission rules.
