◆ Unattended work stops disappearing

Changed 2.1.221 · Aug 4

Background sessions now commit and push to preserve work

The changelog entry: background sessions were changed "to commit and push to preserve work, open a draft PR only when the task calls for one, follow your CLAUDE.md git instructions, and always end by reporting where the work lives."

Three behavior changes bundled into one line. Work gets persisted to git rather than living in a worktree you have to go find. The draft-PR-every-time habit becomes conditional. And your CLAUDE.md git rules now govern what the background session does, which means the rules you already wrote apply to agents you aren't watching.

So what for TSD: Your scheduled tasks and steward loops now push their own branches. Two things to check before the next fire: your CLAUDE.md commit-trailer rule (no Claude Co-Authored-By on Vercel-Hobby private repos) is now the rule background sessions follow, which is what you want — and the bisqueimports identity comes from the includeIf in your global gitconfig, which a background session inherits the same way an interactive one does. Watch the first unattended push into a Bisque repo and confirm the author resolves the way it does interactively.
Changelog 2.1.221
Changed 2.1.221 · Aug 4

/fork sessions get a worktree of their own

Sessions forked with /fork now create a new worktree instead of working in the original session's checkout. This closes the last shared-state hole in the fork model that landed back in 2.1.212, where /fork became a background session copy of your conversation.

Related in the same release: /status now reports the session kind — interactive, or a background job that is attached or unattended.

So what for TSD: Forking to try two approaches on a Sonderwerks build no longer means both forks editing the same files under you. Fork freely now. The /status session-kind line is the fast way to confirm a session you attached to is actually the unattended one you think it is.
Changelog 2.1.221
Fix 2.1.221 · Aug 4

Print mode wasn't connecting MCP servers before the first turn

MCP servers passed via --mcp-config weren't connected before the first turn in print mode (-p), "which made the model emit tool calls as literal text." Fixed. In the same release, plugin- and org-delivered skills named after terminal-only built-ins (/help, /feedback) were un-invocable in non-interactive sessions; that's fixed too.

So what for TSD: Both bugs hit exactly the surface your scheduled tasks run on. If any headless run you wrote in the last stretch produced a transcript with tool calls printed as text rather than executed, that was this, and it's worth re-running rather than debugging your prompt.

◆ Permission and sandbox hardening

Security fix 2.1.221 · Aug 4

zsh could hide commands inside [[ ]] regex conditionals

A Bash tool permission-check bypass "where zsh could execute hidden commands in [[ ]] regex conditionals" is fixed; affected commands now prompt. A second one landed alongside it: PowerShell permission checks mishandled paths containing quote characters on Windows, and those paths now prompt for approval.

This is the third release in a month to patch a [[ ]]-shaped hole in the permission analyzer — 2.1.214 fixed zsh variable subscripts and modifiers in the same construct. The pattern is that shell constructs the analyzer reads as inert text can still execute.

So what for TSD: Update now. You run Claude Code unattended on a Mac with zsh as the login shell, which is the exact combination this affects, and your permission allowlists are the only thing standing between a scheduled task and your client repos. Take the update before the next cron fire rather than after.
Changelog 2.1.221
New 2.1.221 · Aug 4

Sandbox credential masking — Linux and WSL only

New mode: "mask" for sandbox credential files: sandboxed commands read a sentinel copy of the file (the whole thing, or just the spans captured by an extract regex) while the sandbox proxy substitutes the real value on egress. The agent never sees the secret; the outbound request still carries it.

The caveat is in the same sentence: "on macOS file masking falls back to deny." So on your machine this is a deny rule with a nicer name.

So what for TSD: Nothing to configure locally today. It matters the moment you put a TSD agent on a Linux box or a container — that's the setup where an agent can use a Supabase service key or a Vercel token without the key ever entering its context. File it against whatever you build next that runs somewhere other than this Mac.

◆ Model hygiene and cost visibility

New 2.1.221 · Aug 4

claude-api skill gains a prompt-audit subcommand

A new prompt-audit subcommand in the bundled claude-api skill audits "prompts and tool descriptions for patterns written for older models." It arrives eleven days after 2.1.219 made Opus 5 the default, which is the natural reason to want it.

So what for TSD: Point it at the prompts in every client AI feature you've shipped. Anything you wrote against an earlier model generation — verbose role-play preambles, few-shot padding, defensive formatting instructions — is now cost you're paying per call on a model that doesn't need it. That's a concrete margin item on any build where the client pays for tokens, and a credible line in a maintenance retainer pitch.
Changelog 2.1.221
Improve 2.1.221 · Aug 4

Auto-mode permission checks stop burning fresh tokens

Two related changes. Permission checks for parallel tool calls are now cache-efficient, and switching modes mid-check reliably prompts instead of applying a stale result. Separately, auto-mode permission checks now reuse the cached conversation prefix across decisions, which the changelog frames directly as reduced prompt-cache cost.

The Stats panel also now counts cache tokens in its totals, broken out by input, output, cache read, and cache write.

So what for TSD: Auto mode on a long session got measurably cheaper, which lowers the cost of leaving a loop running. Use the new Stats breakdown once on a real build session to learn what your actual cache-read ratio is — that number is what tells you whether long sessions or frequent /clears are the cheaper habit on your workload.
Changelog 2.1.221

◆ Plugins and editor surface

Improve 2.1.221 · Aug 4

Plugins install and activate without a reload

Plugins installed from /plugin now activate immediately when safe, rather than always requiring /reload-plugins. /plugin install also refreshes a stale marketplace catalog and retries before reporting a plugin not found. Plugins can pass "." as a skills path, and claude plugin validate now warns when a marketplace or plugin name would be rejected by Claude Desktop's managed marketplace sync.

On the editor side, the VS Code extension gained a Focus view: a chat-menu toggle that hides tool activity behind an expandable per-turn summary with a live running-tool indicator, bound to Ctrl+Alt+F.

So what for TSD: The two plugin-install failure modes that used to look like "the plugin is broken" were stale catalog and missing reload. Both are gone, so a plugin that still doesn't show up now is actually a real problem. The validate warning is the one to care about if you ever package a TSD-internal plugin for the desktop app.
