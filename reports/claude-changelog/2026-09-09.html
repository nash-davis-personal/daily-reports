Almost everything worth your attention here is plumbing under unattended runs: working directory persistence in -p and SDK sessions, prompt-cache reuse for resumed subagents, crash-resume integrity, and an SSE fallback that may wake up MCP servers that have never connected on this machine. ◆ Unattended runs got more trustworthy

Fix 2.1.265

Non-interactive sessions stop resetting the working directory every turn

The changelog is specific about which surfaces this covers: -p with stream-json input, the Agent SDK, and cloud sessions. Before this, each new user message reset the shell's working directory, so a cd issued on turn one was gone by turn two. Now it persists across turns.

This is the kind of bug that produces wrong results instead of errors. A multi-turn scripted run that assumed it was still inside a repo would quietly execute against whatever the default directory was.

So what for TSD: Your scheduled tasks are exactly this shape — a stream-json -p session doing several turns of work inside a repo. Any of them that cd once and then rely on it have been running from the wrong directory on later turns. Go read the ones that touch more than one folder, and where you see a bare cd early in the flow, switch to absolute paths anyway so the behavior is the same on 2.1.247 as it is after you upgrade.
Changelog 2.1.265
Fix 2.1.265

Resume after a crash keeps the interrupted tool call

When the previous process died mid-tool, resume used to rewrite the last prompt. Now the prompt is left alone and the interrupted tool call is kept in the transcript, marked interrupted. Two related fixes shipped alongside: background --bg sessions are no longer occasionally retired mid-turn when a message arrives just before the idle timeout, and resuming a workflow run after its container restarted now fails with a clear error when the run journal is missing instead of rerunning every agent.

So what for TSD: That workflow-resume fix is the expensive one. A missing run journal used to mean a full re-fan-out of every agent in the workflow, which you pay for in tokens and wall-clock. If you ever resumed a multi-agent run and it felt like it started over, that was this.

◆ Agent context and token cost

Fix 2.1.265

Prompt-cache reuse restored for resumed subagents and teammates

Two separate fixes, same root cause. Resuming a foreground-spawned subagent changed its tool list and system prompt prefix, which broke prompt-cache reuse for that agent. Separately, agent teammates and resumed subagents were moving SubagentStart hook context and preloaded skills out of the prompt prefix on later turns, breaking cache reuse there too.

A prompt prefix that changes between turns cannot be cached. Every turn after the mutation pays full input token price on the whole prefix, including all those preloaded skills.

So what for TSD: This is a direct line item on your bill, and it hits hardest where your config is heaviest — a global CLAUDE.md, a long skill roster, and hook context all sit in that prefix. Pair this with /skill-doctor from 2.1.261: prune the skills that never fire, then upgrade so the ones that stay actually get cached.

Improve 2.1.265

A 1 GB cap on tool results saved to disk, and faster resume for read-heavy sessions

Tool results written to disk are now capped at 1 GB, and the in-conversation preview says when a saved file was truncated. Resuming long sessions that read many files also got faster. Both are quality-of-life on the same axis: sessions that accumulate a lot of tool output.

So what for TSD: The truncation notice is the useful half. Previously a giant saved result could be silently incomplete when you went back to read it, which matters on the bulk file sweeps your vault and repo work does.

◆ Plugins, skills and MCP wiring

Fix 2.1.265

http MCP servers that only speak legacy HTTP+SSE now connect

An MCP server configured as http that only implements the older HTTP+SSE transport never connected. Claude Code now falls back to SSE the way the MCP spec describes. Two adjacent fixes: some claude.ai connectors in cloud sessions showed as needing authentication despite being connected, because the server answered an unsupported request with HTTP 401, and Claude Code no longer registers an OAuth client with a remote MCP server until you actually authenticate.

So what for TSD: You have servers that fail to connect every session. After you upgrade, retry the dead ones before you assume they are misconfigured — a permanently-failing http entry is the exact signature this fixes. The 401 fix also means a connector that looked unauthorized in a cloud session may have been fine the whole time.
Changelog 2.1.265
Feature 2.1.265

--plugin-dir accepts a folder of plugins, with hot add and remove

Point --plugin-dir at a parent folder and every child folder with a manifest loads. Children added or removed while the session is running are picked up. Alongside it, plugin display metadata now prefers the marketplace entry over plugin.json on the Installed tab and in claude plugin details, and /plugin Discover/Browse plus claude plugin list --json --available stopped showing blank descriptions for marketplace plugins whose metadata lives only in plugin.json.

Two security-adjacent plugin fixes shipped too: a plugin path containing a backslash could bypass the symlink containment check on macOS and Linux, and a default component folder the OS cannot check (a symlink loop, for instance) was silently skipped and is now reported in /plugin with its error code.

So what for TSD: Worth it if you are developing plugins locally — one flag instead of one per plugin, and edits to the set land without a restart. The backslash containment bypass is the reason to actually upgrade rather than sit on 2.1.247, since it is a real path-escape hole in plugin loading.

◆ Artifacts, worktrees and the gateway revert

Improve 2.1.265

Artifact reads treat someone else's page as untrusted content

When the Artifact tool reads an artifact another person wrote, the summary now treats the page as untrusted and flags embedded instructions rather than relaying them. A second artifact fix: publishing is refused when none of the declared connector tool names exist on the connector, and warns when only some are missing.

So what for TSD: Straight prompt-injection hardening on a surface you use for client deliverables. If you ever read a shared artifact into a session that also has write access to a client repo, this is the guardrail that was missing.
Changelog 2.1.265
Improve 2.1.265

--worktree starts faster on large repos, and /workflows shows per-agent detail

New worktrees are now checked out in parallel on git 2.32+. Separately, /workflows agent detail marks tool calls running, failed or done, shows a subagent's task list when it has one, and unfolds listed calls with their inputs and results on Enter.

So what for TSD: Both help the isolated-worktree pattern your loop work is built on. The /workflows detail view is the first decent way to see why one agent in a fan-out stalled while the others finished.
Changelog 2.1.265
Fix 2.1.266

Same-day revert: CLAUDE_CODE_USE_GATEWAY stopped forcing gateway sign-in

2.1.265 changed the undocumented CLAUDE_CODE_USE_GATEWAY environment variable so it forced Cloud-gateway sign-in on its own. Previously it was ignored unless both ANTHROPIC_BASE_URL and ANTHROPIC_AUTH_TOKEN were set. Setups that had it alongside an API key, apiKeyHelper, or custom auth headers failed every request with "Not signed in to the Cloud gateway". 2.1.266 makes the variable on its own ignored again, and the changelog says no configuration change is needed.

So what for TSD: Nothing to do, you have no gateway or proxy setup. The reason it is here is the upgrade rule it implies: if you go to 2.1.265, go to 2.1.266 in the same step.
