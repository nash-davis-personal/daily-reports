A UTF-8 BOM silently disabled skills, agents, and commands

Any .md file for an agent, skill, or slash command that opened with a byte-order mark was ignored with no error. If something in your .claude tree has "never worked" and you never found out why, check its first bytes.

The pattern was accepted and then quietly matched zero files. Anything you rely on being copied into an isolated worktree — env files above all — was not arriving.

◆ Silent failures in the agent layer

Fix 2.1.239

Agents, skills, and commands starting with a UTF-8 BOM were silently ignored

The entry is blunt about the behavior: the file was skipped, and nothing said so. A BOM gets prepended by plenty of editors and by shell redirects on some setups, and it is invisible in every editor you would use to check.

The failure mode is one where you assume you wrote the frontmatter wrong, rewrite the file, and still get nothing.

So what for TSD: Your setup is skill-heavy and you author these by hand, so sweep the tree once after updating with grep -rlI $'\xef\xbb\xbf' ~/.claude --include='*.md'. If anything in your command vault or a client repo's .claude folder shows up, that skill has been dead the whole time.
Claude Code changelog — 2.1.239
Fix 2.1.239

An Esc race could end a turn early and let a resubmit repeat actions

Pressing Esc while a prompt was queued could let the next turn finish before Claude was actually done. The session then sat there looking idle while work was still in flight, and resubmitting later could run the same actions a second time.

For read-only work that is an annoyance. For anything that writes, commits, or deploys, a repeated action is the whole problem.

So what for TSD: This is the bug behind any "why did it push twice" moment you have had on client repos. Take the update before your next Bisque or Sonderwerks deploy session, and stop pressing Esc to clear a queued prompt mid-turn on anything that touches git.
Claude Code changelog — 2.1.239
Fix 2.1.239

.worktreeinclude silently matched nothing for **/ patterns in gitignored directories

Worktree isolation copies in the files a fresh worktree needs. Patterns starting with **/ were matching zero files whenever the target sat inside a gitignored directory, and the pattern was accepted without complaint.

Gitignored is where secrets live, so the practical result was isolated agents starting up without the credentials or local config they were configured to receive.

So what for TSD: Directly relevant to any loop or fleet run using isolation: "worktree". Re-check the .worktreeinclude in each client repo after updating, and confirm a worktree agent can actually read .env.local before you trust an unattended Supabase or Vercel task it produced.
Claude Code changelog — 2.1.239
Improve 2.1.239

Compaction no longer replays a skill's original arguments

The reminder Claude receives after a compaction has been reworked so a skill's original arguments are not re-run as a new request. Before this, a long session that compacted could re-issue work you asked for hours earlier.

Paired with the Esc fix above, this release closes two separate paths to the same outcome: an action running twice without you asking twice.

So what for TSD: Long build days on a single session are where this bit. It matters most for skills with side effects, so treat any repeat behavior you saw around a compaction boundary as this bug rather than a prompt problem.
Claude Code changelog — 2.1.239

◆ Running Claude Code unattended

Improve 2.1.239

Retry watchdog and /goal both stop hanging forever

Persistent retry mode (CLAUDE_CODE_RETRY_WATCHDOG) now fails immediately on organization spend-limit and out-of-credits errors instead of waiting for a reset. Separately, /goal check-ins on long-running background work now back off to 30 minutes, then an hour, then every two hours, and resuming a session from the claude --resume picker restores its active goal.

Remote sessions also keep sending keep-alives while a long SessionStart or Setup hook runs, so the container is no longer idle-reaped mid-hook.

So what for TSD: Your scheduled tasks are the beneficiary here — this daily changelog run, the loose-ends steward, anything on launchd. A credit or spend-limit failure now surfaces as a failed run you can see rather than a process sitting silent until you check on it.
Claude Code changelog — 2.1.239
Improve 2.1.239

Multi-session addressing got a real cleanup

ListAgents now tells a session its own name, the one peers use to reach it, and lists live teammates that previously did not appear at all. SendMessage to your own name explains that rather than reporting no such agent. Sessions whose title began with / were unaddressable and showed as "(untitled)"; both are fixed.

A 2.1.232 regression that caused runaway session-title syncing to Remote Control when two processes shared one background job's state is also resolved, with title updates now deduplicated and rate-limited.

So what for TSD: If you are wiring sessions together for fleet-style work, the addressing layer is now trustworthy enough to build on. Worth re-testing any handoff you abandoned because a teammate session "wasn't there".
Claude Code changelog — 2.1.239
Fix 2.1.239

Resume was picking the wrong session and losing custom titles

Four resume-related fixes land together. claude -c and resume could pick up sessions from a different directory whose path differed only by characters like _, -, or .. Custom session titles disappeared from /resume after roughly 64 KB of conversation was written following the rename. /resume in all-projects mode told you to cd into a deleted directory such as a removed worktree, and it now resumes in the current directory instead. Sessions also stopped being reordered as "recently changed" when their file was merely touched or reopened.

So what for TSD: You run near-identically named project directories across the command vault, the Obsidian vault, and client repos. The path-collision fix is the one to care about, because resuming into the wrong project's session is a mistake that is hard to notice quickly.
Claude Code changelog — 2.1.239

◆ Billing accuracy, and two releases that said nothing

Fix 2.1.239

A Bedrock proxy bug was silently doubling billed API calls

Bedrock streaming behind proxies that strip the response Content-Type header was falling back to re-running every turn non-streaming, which doubled the billed calls without any visible symptom. Cost estimates in /cost, the status line and --max-budget-usd also now include the 1.1× US-only-inference premium for data-residency workspaces, and the usage-limit message tells you when session or weekly limits reset.

So what for TSD: None of this touches you directly on the claude.ai plan, so log it and move on. It becomes relevant only if a client ever asks you to run delivery inside their Bedrock or Vertex account, which is a scenario where you would now want to verify the proxy behavior before quoting usage.
Claude Code changelog — 2.1.239
