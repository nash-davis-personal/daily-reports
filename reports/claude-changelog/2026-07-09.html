2.1.205: the agent list gets readable, and fake approvals get harder

A single large release since yesterday's briefing. Most of it lands squarely on how Nash runs Claude Code — a fleet of nightly loops, a phone-driven Remote Control host, and a stack of background agents that used to be near-impossible to read at a glance. Two things stand out: the agents view now shows real state plus a plain-English headline per row, and unattended sessions got new guardrails so a session can't be talked into acting on an approval that never happened.

◆ Reading and steering the agent fleet

Improve 2.1.205

Agent rows show a state word and a written headline, not tool-call spew

The claude agents view now renders each row as a colored state word plus a classifier-written headline describing what the session is doing, and the peek opens with full status — including the exact question when a session is blocked. Sessions that edit, merge, comment on, or push to an existing PR now link that PR in the list too.

So what for TSD: Nash runs a dozen-plus loops and background agents across the fleet (Fleet Steward, sales loop, site loop, lead-scout, macro-brain). Scanning that list used to mean parsing raw tool output. Now a single glance tells him which one is blocked and on what — check the morning fleet in seconds instead of opening each session.
Changelog · 2.1.205
Feature 2.1.205

/doctor is now a full setup checkup that can fix issues

/doctor became a full setup checkup that diagnoses and repairs problems, with /checkup as an alias. The old startup "claude command missing or broken" warnings moved into /doctor and /status instead of nagging at launch.

So what for TSD: When a scheduled task on the Air or the Desk Mac misbehaves, run /doctor first — it now self-diagnoses across two machines with different auth and PATH setups, which is exactly where the fleet breaks.
Changelog · 2.1.205

◆ Guardrails for unattended sessions

Improve 2.1.205

Sessions can't be tricked into acting on approvals that never happened

Two related changes. Background task notifications now explicitly state that no human input has occurred, which stops fabricated in-transcript approvals from being acted on. And auto mode gained a rule that blocks tampering with session transcript files. A companion tweak makes auto mode ask before running rm -rf on a variable it can't resolve from context.

So what for TSD: This is the exact failure mode that matters for the agentic Robinhood steward and the workspace-scoped trade-confirm gate — an unattended loop convincing itself a human said yes. The guardrail is now built in, but Nash's own confirm gates stay the real control. Worth a note in the loop specs.
Changelog · 2.1.205

◆ Structured output and session reliability

Fix 2.1.205

--json-schema no longer silently degrades to unstructured text

An invalid --json-schema used to silently produce unstructured output, and schemas using the format keyword were rejected outright. Both are fixed.

So what for TSD: Any headless script or loop that pulls structured JSON out of Claude — the report scouts, the sales-queue builders — now fails loudly on a bad schema instead of quietly handing back prose that breaks downstream. If Nash has schemas that lean on format (dates, emails), they'll now work.
Changelog · 2.1.205
Fix 2.1.205

Messages stop vanishing at the --max-turns limit

A message sent while Claude was working was silently lost if the turn ended at the --max-turns limit. Also fixed: session-to-PR linking used to miss a PR created in a Bash call whose output blew past the 30K inline limit.

So what for TSD: If any of Nash's automations cap turns, a queued instruction could quietly disappear. That silent-drop class is closed — one less way for an overnight run to do the wrong thing and never tell you.
Changelog · 2.1.205

◆ Remote Control and platform

Fix 2.1.205

Remote Control stops showing stale status; the updater stops hogging memory

Background tasks in the web and mobile Remote Control panels no longer show a stale "Running" status — full task state is now forwarded on every membership change. Cowork VM-mode local-agent sessions that failed with "Not logged in · Please run /login" on 2.1.203+ are fixed. Separately, auto-update binary downloads now stream to disk instead of buffering in memory, cutting the updater's peak memory by roughly 400 MB.

So what for TSD: Nash drives the Desk Mac from his phone; a lying status panel is worse than none. The 400 MB updater cut also matters on an always-on headless host that has to stay awake and responsive — fewer memory spikes during auto-upgrade windows.
