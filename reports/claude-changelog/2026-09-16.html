◆ Throughput

Fixed 2.1.273

Auto-compact was cutting your working context in half

The context meter and auto-compact logic counted advisor-tool turns at roughly twice their real context footprint. That made auto-compact trigger at about half the actual window size — sessions were losing history and re-summarizing far earlier than the real token budget required.

So what for TSD: If you've felt Claude Code "forget" earlier context sooner than it should on long build sessions, this was likely why. No action needed beyond updating — you should see noticeably longer sessions before compaction kicks in, which means fewer re-explains mid-task on client work.
Claude Code changelog — 2.1.273

◆ Automation & agent reliability

Fixed 2.1.273

Background and subagent runs stop losing their results

Two related bugs: sub-agents and background agents were reported as failed — with their result never delivered — whenever the final streamed reply omitted token usage or carried no model id. Separately, SDK and --output-format stream-json consumers lost a subagent's remaining messages and final report entirely when that subagent got moved to the background mid-run (for example via CLAUDE_AUTO_BACKGROUND_TASKS).

So what for TSD: This directly affects the pattern this scout job itself uses — fire-and-forget subagents and background runs. Fewer silent "it ran but I never got the output" failures if you're leaning on background agents for unattended work.
Claude Code changelog — 2.1.273
New 2.1.273

Fork a phone/remote session into a local background run

A session started with --remote-control or /remote-control from the Claude app can now be forked; the fork runs as a background session on your own computer instead of staying tied to the remote-controlled session.

So what for TSD: If you kick off a task from your phone away from the desk, you can now branch it into a background run on your dev machine without babysitting the remote session — useful for starting client work mid-commute and having it waiting when you sit down.
Claude Code changelog — 2.1.273

◆ Code Review

Fixed 2.1.273

/ultrareview posting and re-review triggers tightened

A retry after a GitHub error on /ultrareview --post could previously post the findings comment zero or two times; it now posts exactly once and names the commit reviewed. Separately, merging the base branch into a PR that already had an "Additional findings" review no longer forces a full re-review — it gets the lighter follow-up pass instead. A whole REVIEW.md being withheld because of a stray @-mention or a wrapped code span is also fixed.

So what for TSD: If Code Review is running on client repos (Bisque, Studio C, Sonderwerks), duplicate or missing review comments look sloppy on a PR you're billing for. This is cleanup, not a new capability — but worth knowing the noise is gone if a client ever asks about it.
