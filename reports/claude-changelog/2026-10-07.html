◆ Unattended runs and agents

Fix 2.1.292

One-shot claude -p and SDK runs wait for background commands and wakeups

Before this, a one-shot claude -p or Agent SDK run stopped any background command 5 seconds after the final result, and claude -p dropped a scheduled wakeup. Both are now waited for. Separately, the first turn of claude -p and SDK sessions no longer waits for HTTP and SSE MCP servers to answer resources/list, and stdio MCP servers that are slow on the newer protocol check are remembered for 7 days and connected the older way.

So what for TSD: Every Nash OS hub job is a headless run. Any job that kicks off a build, a next build, a deploy check or a long script in the background and then wraps up was getting that process killed after 5 seconds. Update the hub Mac to 2.1.292, then check which jobs' outputs looked truncated or "never finished" and rerun them.
Changelog 2.1.292
New 2.1.292

effort parameter on the Agent tool

Claude can now run a sub-agent at the effort level you ask for. Related: subagent definitions with permissionMode: auto no longer enter auto mode when it's unavailable (disabled by settings, circuit breaker, or an unsupported model), and agent names are capped at 256 characters.

So what for TSD: Cost and speed control per task. In client builds, tell Claude to fan out file searches and lint sweeps at low effort and keep high effort for the RLS/auth review on Supabase work. Worth adding a line to your standard CLAUDE.md so it happens without asking.
Changelog 2.1.292
Fix 2.1.292

Scheduled tasks and /loop: another round of dropped runs fixed

Saved scheduled tasks created after /resume, /branch or /clear never fired. Saved tasks ignored later creates and deletes after two writes to the tasks file milliseconds apart. A background session's /loop stopped silently when its process restarted (for example after a crash) because the pending wakeup was lost. In cloud sessions, scheduled tasks and queued notifications were lost when a message was retried or edited mid-read. Scheduled and Run-now routine runs now publish a private artifact without asking for approval.

So what for TSD: This follows yesterday's 2.1.290 batch. If you set up any schedule right after a /clear or /resume, assume it never fired and recreate it on 2.1.292. Routine runs that stalled on an artifact approval prompt should now complete unattended.

◆ Code quality and review

Fix 2.1.292

Grep, Glob, Read and @-mentions stop failing silently

Grep and Glob reported no matches when the given file or folder couldn't be read; Claude now retries once or tells you. Read returned only the first page, with no error, when a PDF's pages was a list such as "6,9,15"; it now errors. @-mentioned text files over 256KB were left out silently; Claude is now told the size and to read in portions. Grep also accepts file_path for path, and Write, WebFetch and Read ignore a few stray parameters instead of failing.

So what for TSD: A "no matches" answer from Grep was sometimes a lie, which means Claude could have concluded a function or env var wasn't used when it was. If a refactor on Bisque, Studio C or Sonderwerks deleted something "unused" recently, spot-check it. Large generated files (Supabase types, lockfiles) @-mentioned in prompts were likely being dropped.
Changelog 2.1.292
Fix Code Review

GitHub Code Review reads CLAUDE.md from the base branch; analytics added

Reviews ignored a CLAUDE.md's rules when the pull request edited that file; they now use the base-branch version. A queued review no longer fails when the PR moves to a new base and the old one is deleted. Code Review analytics gained a period total, change from the previous period, and a per-repository breakdown.

So what for TSD: A PR can no longer loosen the rules it's reviewed against. That makes CLAUDE.md conventions a real gate on client repos. The per-repo chart is a cheap artifact for client reporting: "N PRs reviewed this month" is a line item for a retainer.

◆ Security and plugins

Security fix 2.1.292

Permission and sandbox holes closed

PreToolUse hook approvals and auto mode bypassed the permission prompt for file reads from network (UNC) paths. Sandboxed commands could read staged /ultrareview upload copies under ~/.claude/seed-admin. A notebook or PDF read on macOS could return a file outside what was approved via a link swapped mid-read. A skill's allowed-tools rule could come back in a later turn after leaving auto or plan mode. <system-reminder> tags in hook output are now escaped before reaching Claude.

So what for TSD: Nothing to change in your setup; update and move on. If any hub hook echoes untrusted text (scraped pages, client form input), the system-reminder escaping closes a prompt-injection path you'd otherwise have to handle yourself.
Changelog 2.1.292
New 2.1.292

claude plugin install --marketplace

claude plugin install takes --marketplace <source>: it adds the marketplace if needed, under the same policy checks as claude plugin marketplace add, then installs the plugin. Mods also got prompt.autocomplete, prompt caching on $.model.complete, and workflow agents in agent.spawn; claude plugin test now fails on a failed expect inside a hook.

So what for TSD: One command to put your own plugin on a fresh machine or a client's dev box. If you package your Next.js/Supabase skills as a plugin, the setup step in a client handoff doc shrinks to one line.
