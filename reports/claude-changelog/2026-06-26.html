◆ Auto mode gets stricter and more legible

Feature 2.1.193

Every shell command can now go through the auto-mode classifier

The new autoMode.classifyAllShell setting routes all Bash and PowerShell commands through the auto-mode classifier instead of only the ones matching arbitrary-code-execution patterns. The old heuristic let plenty of ordinary-looking commands skip the safety check; this closes that gap when you want a tighter net for unattended work.

So what for TSD: You run scheduled, unattended jobs under auto mode — this very changelog briefing is one, alongside the daily-reports scout and the ALGC grant-metric runs. Turn classifyAllShell on for those so a malformed or surprising shell command gets classified before it executes, instead of slipping through on a pattern miss.

Improve 2.1.193

Denials now explain themselves

Auto-mode denial reasons are now written to the transcript, the denial toast, and the recent-denials list in /permissions. When auto mode blocks something, you can read the reason instead of guessing.

So what for TSD: When a scheduled run stalls or quietly skips a step, check /permissions recent denials to see exactly which command got blocked and why — far faster than re-running the whole job to reproduce the snag.

◆ Background agents and throughput

Improve 2.1.193

Spawning a background agent no longer halts the main turn

The launch result for a background agent used to instruct Claude to "end your response," so the main thread stopped dead while the agent ran. Now it keeps working on other tasks while the agent churns in the background.

So what for TSD: Real parallelism for solo delivery — kick off a verify or build agent and keep editing the next client file in the same turn instead of waiting on it. Pairs with the bash-mode and long-session fixes below to keep a marathon session moving.

Claude Code Changelog — 2.1.193
Feature 2.1.193

Bash mode gets path autocomplete; idle background shells get reaped

Two quality-of-life wins: ! bash mode now has live file-path autocomplete, and idle background shell commands are reaped automatically under memory pressure (disable with CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP=1).

So what for TSD: Less mistyped-path friction when you drop to a shell across the dozen-plus repos you bounce between, and long Vercel/Supabase build sessions are less likely to balloon memory from forgotten background tails.

◆ MCP reliability

Improve 2.1.193

MCP auth recovers on its own, and tells you upfront what needs login

The MCP headersHelper auth flow now re-runs and reconnects automatically when a tool call returns 401 or 403, so an expired token stops silently breaking a server mid-session. There is also a new startup notice when MCP servers need authentication, pointing you at /mcp.

So what for TSD: Your stack leans hard on MCP — Vercel, Notion, the Robinhood and Calendly servers. Tokens timing out used to mean a dead tool you only noticed when a call failed. Now it reconnects, and the startup notice flags any server that needs a fresh login before you waste a turn on it.

◆ Telemetry heads-up

Watch 2.1.193

OpenTelemetry can begin shipping full model responses after this upgrade

A new claude_code.assistant_response OTEL log event carries the model's response text. It is redacted unless OTEL_LOG_ASSISTANT_RESPONSES=1 — but when that variable is unset it follows OTEL_LOG_USER_PROMPTS. So any deployment that already logs prompt content will start receiving response content on upgrade. Set OTEL_LOG_ASSISTANT_RESPONSES=0 to stay prompts-only.

So what for TSD: Almost certainly a no-op for a solo setup with no OTEL exporter. The one scenario to check: if you ever wire Claude Code telemetry into a dashboard and turn on prompt logging, full model output (which can echo client data) starts flowing to that backend by default. Decide that on purpose, not by upgrade.
