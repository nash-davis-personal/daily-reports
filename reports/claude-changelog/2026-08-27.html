Claude Code Changelog ◆Thursday, August 27, 2026 ◆1 release ◆ 2.1.247

2.1.247 ships a Claude API cost audit you can bill for, and fixes the two failures most likely to wedge an unattended run.

The headline item is /claude-api cost-optimize, which profiles an existing project's Claude API spend and works through the levers — caching, token hygiene, batch, effort, model choice — one measured change at a time. Underneath it are two reliability fixes that matter more than they read: a hook or background agent printing megabytes of error output could overflow the conversation and wedge the session on "Prompt is too long", and a sub-agent that got a 404 on its first model call simply died instead of falling back. The rest of the 33-entry release is hardening around untrusted text and a long tail of terminal fixes.

◆ Unattended runs now fail loudly instead of quietly

Fix 2.1.247

A hook or background agent dumping megabytes of error output could overflow the conversation

The output went into the conversation, the conversation blew past the context limit, and the session wedged on "Prompt is too long". A related fix stops unbounded memory growth when a hook's or background task's output file could not be written — the file now notes where the output was lost.

This is the failure mode of a long unattended run, and it does not announce itself. A hook that starts erroring at 2am takes the whole run down with it, and what you find in the morning is a stuck session rather than a stack trace.

So what for TSD: This is the single best argument in the release for upgrading before your next overnight scheduled task. Your loops run hooks and background agents unattended with nobody watching the output; a noisy failure in one of them was previously enough to kill the run silently.
Claude Code changelog — 2.1.247
Fix 2.1.247

Sub-agents died on a first-call model 404 instead of falling back

A sub-agent whose first model call returned a 404 just died. It now uses the session's fallback model chain, and the error returned to the parent carries the error type, status, request id, and model, so a failure is diagnosable rather than a blank.

The 404 case shows up when an agent definition pins a model that is retired, misspelled, or unavailable on the account — which is exactly the kind of thing that only surfaces months after you wrote the agent.

So what for TSD: Worth a pass over the model: frontmatter in your custom agents anyway, since the fallback chain now hides a pinned model that no longer exists rather than failing. The richer error payload also means a fan-out that comes back short now tells you which agent broke and why.
Claude Code changelog — 2.1.247
Fix 2.1.247

Cloud sessions went silent when the container restarted mid-run

If the session's container restarted between turns while a background agent, shell, or monitor was still running, the session went quiet. The resumed session now reports the work that was lost. A companion fix stops a background session from showing "opening…" forever in claude agents after its terminal host process died — the row now fails within seconds with a reason, and Enter restarts it.

So what for TSD: Both failures looked identical from the outside — a session that appears to be working and is not. If you kick off Claude Code on the web or the desktop app and walk away, you now get told when the work vanished instead of coming back to an idle screen.

◆ Cost, context, and the /claude-api skill

Feature 2.1.247

/claude-api cost-optimize profiles a project's spend and works the levers one at a time

The new command profiles an existing project's Claude API spend and works through cost levers — caching, token hygiene, batch, effort, model choice — one measured change at a time. The "one measured change at a time" framing is the useful part: it produces a before-and-after per lever instead of a pile of simultaneous edits you cannot attribute.

So what for TSD: This is a packaged engagement. Any client with an AI feature in production has an API bill nobody has audited, and a per-lever before-and-after is the artifact that justifies the invoice. Run it against your own builds first so you have a real number to quote from before you sell it.

Improve 2.1.247

The /claude-api skill picked up Admin API coverage

Organization members, invites, workspaces, API keys, rate limit reports, workload identity federation, and CMEK are now covered by the skill.

So what for TSD: Mostly matters at the point where a client wants their own Anthropic org rather than billing through yours. Workspaces and per-workspace API keys are how you keep one client's spend separated from another's, and rate limit reports are how you answer "why did it get slow" without guessing.

Improve 2.1.247

Sonnet 5's default auto-compact window moved up to the full 1M context

Sessions on the 1M window now auto-compact at about 967K tokens instead of about 934K. The old threshold left roughly 33K tokens of the window unused.

So what for TSD: Small but free. Each auto-compact is a lossy summarization, and pushing the trigger later means fewer of them in a long delivery session — which is where compaction actually costs you, since the details that get dropped are the ones from early in the build.

◆ A new agent-written surface, and the permissions thread continues

New 2.1.247

SendFeedback: Claude drafts a feedback report when a session goes wrong

When something goes wrong in a session, Claude can draft a feedback report for you to review and send from /feedback. The feedbackDrafts setting turns it off.

You review before it sends, so nothing leaves without you. Worth knowing the setting exists regardless, since a feedback report drafted from a session is a summary of what was in that session.

So what for TSD: Decide the default now rather than the first time it fires during client work. If you are in a Bisque or Sonderwerks repo when a session breaks, read the draft before sending it — that is the moment a client's code or config would go out in a bug report.
Claude Code changelog — 2.1.247
Improve 2.1.247

Bash permission prompts now offer a one-keystroke switch to auto mode

The prompt carries a tip pointing at auto mode with a "Yes, and switch to auto mode" option. This picks up directly from yesterday's release, which added the Auto mode tab to /permissions and started warning about Bash allow rules with a wildcard before the subcommand.

So what for TSD: Convenient, and it is a one-keystroke widening of what runs without asking. Take the shortcut in a scratch repo; in a client repo, go through /permissions deliberately — especially given yesterday's warning that your existing allow rules match more than they look like they do.

◆ Hardening around text you did not write

Improve 2.1.247

Terminal hyperlinks in rendered markdown are now defanged when the target looks wrong

Link targets that point at a network or automounter path, contain a control character, or lead with an invisible character render as plain text instead of a clickable terminal hyperlink.

The attack this closes is a link whose visible text says one thing and whose target says another, arriving through content Claude read rather than content you wrote.

So what for TSD: Relevant every time an agent renders scraped pages, MCP tool output, or a client's own docs. A link that suddenly renders as plain text in your terminal is now a signal worth reading, rather than a rendering glitch.
Claude Code changelog — 2.1.247
Improve 2.1.247

Plugin marketplace names with control or invisible characters are rejected

Marketplace names containing control or invisible characters are refused outright, and marketplace-supplied text in /plugin and claude plugin output is now escape-safe. Both are aimed at a marketplace entry that renders as something other than what it is.

So what for TSD: You install plugins from marketplaces you did not audit. This does not make a third-party plugin safe; it stops one from lying about its name in the install prompt.
Claude Code changelog — 2.1.247
