◆ Agent fan-out grows guardrails

Breaking v2.1.217

Subagents stop spawning nested subagents by default

Subagents no longer spawn their own subagents unless you explicitly raise CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH. This is the one item in the release that can change the behavior of something you already built without throwing an error, since a workflow that relied on a coordinator agent delegating downward will now just do less work rather than fail loudly.

So what for TSD: If any of your scaffolded loops or the Fleet Steward pattern has an agent that delegates to further agents, run it once and read the output before trusting a scheduled run. Where the nesting is load-bearing, set the depth env var in the launchd or cron wrapper rather than assuming the default carried over.
Claude Code changelog, v2.1.217
Improve v2.1.217

Hard cap of 20 concurrently-running subagents

There is now a ceiling on how many subagents run at once, defaulting to 20 and overridable via CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS. The stated reason is to stop a single message from fanning out unbounded background agents.

So what for TSD: Wide sweeps across a client repo will queue past 20 instead of saturating the Mac. That is the behavior you want on the laptop while a build is running, so leave it alone. Only raise it for a deliberate large audit on a machine doing nothing else.
Claude Code changelog, v2.1.217
Fix v2.1.217

--max-budget-usd now halts background subagents

The spend cap did not stop background subagents. Once the cap is reached, new spawns are denied and already-running background agents are halted.

So what for TSD: This is the flag that makes an unattended overnight loop safe to leave running. If you have been avoiding scheduled agent work over cost anxiety, the guardrail is real now, so put an explicit --max-budget-usd on every scheduled task wrapper.
Claude Code changelog, v2.1.217

◆ Long sessions: memory, transcripts, compaction

Fix v2.1.217

Truncated MCP tool output stopped pinning full results in memory

When an MCP tool returned a large result that got truncated for display, the full untruncated result stayed in memory for the remainder of the session.

So what for TSD: Your heaviest MCP callers are Supabase table dumps and the portal pipeline tools, both of which return fat payloads. Long client sessions that got sluggish by hour three should behave better after you update.
Claude Code changelog, v2.1.217
Improve v2.1.217

Silent transcript loss now raises a warning

Two failure modes that used to lose transcripts quietly now warn: writes failing because of something like a full disk, and session saving being switched off by an inherited environment variable.

So what for TSD: Worth knowing about before the next time you go looking for a session you wanted to mine into the vault. If you see the inherited-env warning, check whatever wrapper script launched that session before blaming Claude Code.
Claude Code changelog, v2.1.217
Fix v2.1.217

Auto-compact never fired for Opus 4.8 on Bedrock

Auto-compact did not trigger at all for Claude Opus 4.8 on Bedrock, and /compact failed once the session was already over the limit, which is the exact moment you would reach for it.

So what for TSD: Only bites if you run through Bedrock, which you do not today. File it under reasons a Bedrock-routed client engagement needs its own smoke test rather than assuming parity with the direct API.
Claude Code changelog, v2.1.217

◆ Isolation and startup hardening

Fix v2.1.217

Background sessions could escape their workspace through a symlink

Background session isolation was not canonicalizing symlinked working directories, which could let a session reach outside its workspace folder. This is the third consecutive release touching symlink handling in isolation boundaries, after the .claude symlink and worktree fixes in v2.1.216.

So what for TSD: Update before the next unattended run. Isolation you assumed was holding was leaky on any project reached through a symlinked path, which is easy to hit given the vault and project folders on this Mac.
Claude Code changelog, v2.1.217
Fix v2.1.217

A brace-heavy paths frontmatter could OOM the CLI at startup

A CLAUDE.md or SKILL.md frontmatter paths value with many brace groups could stall or OOM-kill the CLI before it started. Brace expansion is now budget-bounded.

So what for TSD: A startup hang with no error is hard to diagnose from scratch. Given how many custom skills you carry globally, this is the kind of failure you would have spent an hour on.
Claude Code changelog, v2.1.217
