◆ Background agents and worktree isolation got hardened

Fix v2.1.203

Worktree-isolated subagents were sometimes editing the wrong checkout

Two related worktree bugs are fixed: isolated subagents that occasionally ran shell commands in the parent checkout instead of their own worktree, and worktree creation rejecting nested repositories in multi-repo workspaces (which left background sessions unable to isolate and edit).

So what for TSD: This is load-bearing for your loop fleet. The Fleet Steward, TSD site loop, and sales loop all fix work in isolated worktrees — a subagent silently running against the parent checkout is exactly the kind of quiet corruption that's hard to notice in a propose-only nightly run. Update the Macs that run those loops before the next cycle.

Changelog · 2.1.203
Fix v2.1.203

Returning to the agents view no longer throws away in-flight work

Reopening claude agents used to silently stop running subagents and re-run the prompt from scratch; their work now carries over. Alongside it: TaskStop and TaskOutput now find background agents spawned by another agent (errors list running agents by id and description), and the agent list stopped showing "Needs input" after a question was already answered.

So what for TSD: If you drive background agents from the phone via Remote Control, popping in and out of the agents view was quietly resetting them. That tax is gone — check on a long-running build without paying for it in lost progress.

Changelog · 2.1.203
Fix v2.1.203

Sessions recover from stale tokens and survive a bad auto-upgrade

Background sessions that became permanently unresponsive to attach, reply, and stop when the daemon's session token went stale now recover automatically. Separately, a background-daemon auto-upgrade failure that was silently killing every running background session is fixed, as is a 15–20 second stall opening or switching background sessions on macOS (a regression from 2.1.196).

So what for TSD: These are the failure modes that turn the always-on desk Mac into a dead host you don't notice until a report doesn't ship. Self-recovery and a survivable upgrade path mean fewer mornings spent finding the daemon face-down. Worth the update on the Remote Control host specifically.

Changelog · 2.1.203

◆ Auth, footprint, and agent quality

New v2.1.203

A warning before an expiring login interrupts a running session

Claude Code now warns you when your login is about to expire so you can re-authenticate before a background session gets interrupted mid-run.

So what for TSD: Your unattended loops die silently when auth lapses. A heads-up beats discovering a stalled overnight run at 7am — but it still needs a human at the keyboard, so it does not replace the scheduled-task health checks.

Changelog · 2.1.203
Improve v2.1.203

Smaller footprint, and subagents that re-delegate less

Loading a large bundled dependency lazily instead of inlining it cut ~7 MB off the binary and ~7 MB off startup memory. And subagents are now less likely to re-delegate their entire task to another subagent — a recurring pattern that burned tokens and muddied the trail of who did what.

So what for TSD: Less re-delegation is real money on multi-agent workflows and reviews. When you fan out a job now, expect the worker to actually do it instead of spawning a copy of itself.
