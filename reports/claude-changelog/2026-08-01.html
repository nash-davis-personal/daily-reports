◆ Worth doing while it's quiet

Behavior change 2.1.214 · Jul 18

Your dir/** allow rules stopped matching nested directories

2.1.214 fixed single-segment dir/** allow rules like Edit(src/**), which had been auto-approving writes to any nested src/ directory anywhere in the tree instead of only <cwd>/src. The same release narrowed single-segment dir/** hook if: conditions the same way; write **/dir/** if you want any-depth matching. deny and ask rules kept their any-depth behavior.

This lands as a silent change in behavior. A rule that used to cover a nested package directory now covers only the top-level one, so the practical symptom is extra permission prompts in repos where you thought approvals were already granted, plus the knowledge that those rules were quietly broader than intended before the fix.

So what for TSD: Open the .claude/settings.json in each client repo and read the permission rules once. Anywhere you meant "this directory at any depth," rewrite dir/** as **/dir/**. Cheap now, annoying mid-build.

Config 2.1.210 · Jul 14

Rules written as Write(path) or Glob(path) now warn at startup

2.1.210 added a startup warning for Write(path), NotebookEdit(path), and Glob(path) permission rules, pointing you at Edit(path) or Read(path) instead. If a warning line has been appearing at session start and you have been scrolling past it, this is the likely source.

Pair the rewrite with the two settings still sitting unconfigured from 2.1.219: sandbox.network.strictAllowlist, which denies non-allowlisted hosts for sandboxed commands without prompting, and workflowSizeGuideline, which sets the dynamic workflow size guideline from any settings file. Both were covered in the July 25 briefing.

So what for TSD: Do the rule rewrite and both settings in one pass on your global settings file so client repos inherit them. One sitting clears the startup warning and the two carryovers together.
