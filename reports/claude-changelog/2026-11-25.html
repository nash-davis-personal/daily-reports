◆ Skills and what you can package

New 2.1.332

Skills can now come from MCP servers

In beta, an MCP server can offer skills alongside its tools. They appear in the / menu as server:skill; skills from other places keep their names.

So what for TSD: The tsd-portal and tsdpl servers are yours, so the instructions for using them (the tsdpl skill today lives as a separate local file) could ship from the server itself and stay in sync on both Macs. Wait for this to leave beta before moving anything, but it is also the cleanest way to hand a client a "here's how to drive your site's admin" skill along with an MCP endpoint.
Changelog: 2.1.332 Added
New 2.1.332

PreSkillShellCommand hook gates a skill's inline shell

The new hook event runs when a skill or command loads and can refuse its inline shell commands. The changelog warns that on 2.1.331 and older, a settings file that names the event opens a dialog at start.

So what for TSD: Useful once you install third-party plugin skills you haven't read line by line. Don't add it to ~/.claude/settings.json until the terminal claude is past 2.1.331: on 2.1.316 that start-up dialog would sit unanswered in front of every one of the 28 scheduled tasks.
Changelog: 2.1.332 Added

◆ Long build sessions and unattended runs

Fix 2.1.332

Compaction gets out of the dead ends that ended turns

Turns no longer end in "Prompt is too long" after repeated auto-compaction failures when one more compaction would have kept them going. A summary that keeps running past the output limit now gets a shorter-summary request after three cut-off tries. Sessions behind a proxy with a request size limit, where every message and /compact failed with a 413, now recover. CLAUDE.md and rules files are no longer sent twice, in most cases, after a session moves into a .claude/worktrees worktree.

So what for TSD: The multi-hour Bisque and commercial sessions are the ones that hit this wall, and the CLAUDE.md double-send burns context on every worktree agent. Both are reasons to update the terminal claude today.
Changelog: 2.1.332 bug fixes
Fix 2.1.332

Freezes from hooks, MCP servers and secrets files

Fixed: freezes and runaway memory while a hook prints output without end; a freeze and context overflow when a hook blocks or fails with a very large log (text over about 50,000 characters is now shortened); the terminal freezing and ignoring Ctrl+C while a local MCP server floods standard output; SSE MCP servers hanging or refusing every call after their stream was cut until reconnected by hand; and Read, @-mentions and compaction hanging on a named pipe such as a .env mounted by a locked secrets manager, which now fails after 20 seconds.

Also: claude auth login now exits 1 instead of printing Login successful. when a claude.ai login couldn't be saved, and Remote Control no longer reports a usage limit as reached after it has reset, or shows a waiting desktop session as running.

So what for TSD: A scheduled task that hangs never writes its Nash OS line, so it shows as missing on the Machine page with no error. With about a dozen local MCP servers loaded, the stdout-flood and SSE fixes are the most likely to matter. If a task has gone silent recently, update first and re-run it before debugging the task itself.
Changelog: 2.1.332 bug fixes
Changed 2.1.332

Desktop Code tab: plan mode asks instead of refusing, and save failures are visible

Plan mode in the desktop Code tab and VS Code now asks for approval, instead of refusing, when no auto mode safety check can judge a command (for plans entered from Manual or Accept edits). The Code tab also warns when part of a session couldn't be saved and says how to save it with /compact, and notes when a resumed session's earlier messages weren't loaded.

So what for TSD: Most of your build work runs in the desktop Code tab, so this ships with the app update and needs nothing from you. If you see the save warning, run /compact before closing the session or you lose that history.
