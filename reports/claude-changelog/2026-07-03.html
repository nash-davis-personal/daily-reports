◆ The overnight fleet stops lying to itself

Fix 2.1.199

Subagents no longer report API errors as clean successes

Two related fixes. A subagent cut off by a rate limit or server error used to fail silently instead of handing its partial work back to the parent — that partial is now returned. Worse, a subagent that hit an error like "usage limit reached" used to report it to the parent as a successful result. The parent then acted on a lie. Both are fixed: the error is now surfaced up the chain.

So what for TSD: This is the most load-bearing fix in the release for you. Your Fleet Steward, sales loop, and site loop all fan work out to subagents overnight, then a skeptic or a state ledger acts on what comes back. A subagent silently returning "success" with no work done could corrupt a loop's state and you'd never see it. Update every machine that runs a loop before tonight's cycles fire.

Fix 2.1.199

Partial streaming output is kept when the API errors mid-response

When the API emitted an overloaded or server error after already streaming part of a response, the whole partial output used to be discarded. It's now kept with an incomplete-response notice. Paired with the streaming idle watchdog that shipped on by default in 2.1.197, mid-turn capacity hiccups now degrade instead of wiping the turn.

So what for TSD: Fewer wasted long turns during peak-hours capacity blips — the model keeps whatever it produced instead of starting over. Marginal during the day, real for a loop grinding through a large diff at 5am when Anthropic capacity is tight.

◆ The headless desk Mac gets unblocked

Fix 2.1.199

Background agents cold-starting over SSH on macOS ("Could not switch to audit session")

A regression introduced in 2.1.196 made background agents fail to cold-start over SSH on macOS with "Could not switch to audit session." That's fixed. Separately, claude stop racing a background-agent respawn used to be silently undone — the respawn now honors the stop.

So what for TSD: Your desk Mac is the always-on headless Remote Control host you drive from your phone, and you launch background agents on it over SSH. If any of those have been flaky since late June, this is why — the fix is here. Update the desk Mac specifically, not just your laptop.

Changelog · 2.1.199
Improve 2.1.199

Transient 429s auto-retry, and the retry ceiling jumps to 300

Capacity-side 429s that have nothing to do with your own usage limit now retry automatically with backoff for subscribers, instead of failing the turn. And CLAUDE_CODE_RETRY_WATCHDOG now raises the default retry count for non-capacity transient errors to 300 and lifts the old cap of 15 on CLAUDE_CODE_MAX_RETRIES.

So what for TSD: Unattended loops survive capacity turbulence without you babysitting them. If you'd set CLAUDE_CODE_MAX_RETRIES manually to work around the old 15 cap, you can drop that override now — the default watchdog covers it.

◆ Smaller wins you'll actually feel

Fix 2.1.199

Hooks stop hiding their own errors, and stacked skills all load

SessionStart, Setup, and SubagentStart hooks that exited with code 2 used to swallow their stderr — a silent failure that's brutal to debug. The error now shows in the transcript. And stacked slash-skill invocations like /skill-a /skill-b do XYZ now load every leading skill (up to 5), where before only the first one loaded.

So what for TSD: Two friction removers. Your loops lean on SessionStart/hook wiring — a broken hook will now tell you why instead of failing blank. And you can chain skills in one line (say a humanizer pass after a sales draft) and trust they all fire.

Fix 2.1.199

Plan mode now prompts for state-changing browser tool calls

With Claude in Chrome now generally available (shipped yesterday in 2.1.198), plan mode wasn't prompting before state-changing browser actions. It now does, while read-only browser_batch calls are correctly auto-allowed.

So what for TSD: If you start using Chrome automation for client research or QA, plan mode is now a real guardrail — it won't let a browser session click or submit something without asking, but read-only inspection stays frictionless.
