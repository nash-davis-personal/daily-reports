◆ Guardrails for unattended and heavy sessions

New 2.1.212

Per-session caps on web searches and subagent spawns

Two new limits, both defaulting to 200 and both meant to stop a loop from spiraling. A session-wide WebSearch cap (CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION) stops runaway search loops, and a per-session subagent-spawn cap (CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION) stops runaway delegation. /clear resets the subagent budget.

So what for TSD: You run unattended loops in worktrees. Treat 200 as a safety backstop, not a target — set both env vars deliberately for a scheduled run so a stuck agent trips the cap instead of your bill. If a legitimate deep-research or fan-out job needs more, raise it explicitly rather than discovering the ceiling mid-run.
Changelog · 2.1.212
Improve 2.1.212

Long MCP calls move to the background automatically

An MCP tool call running longer than 2 minutes now backgrounds automatically so the session stays interactive. The threshold is configurable, or disable it, via CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS. Same release also cut token usage in inter-agent messaging (SendMessage bodies no longer duplicated into replayed history) and extended mid-conversation prompt caching to work behind LLM gateways and custom base URLs (Bedrock, Vertex, 1P).

So what for TSD: You lean on slow MCP servers — Vercel, Supabase, Notion. A long deploy-status or query call no longer freezes the whole session. If one server is reliably slow, tune the threshold up for that workflow instead of sitting through it.

◆ Safety fixes worth knowing about

Fix 2.1.212

Plan mode was running file-modifying Bash without a prompt

Fixed a bug where plan mode auto-ran file-modifying Bash commands — touch, rm, and the like — without a permission prompt or an SDK canUseTool callback. Plan mode is supposed to be read-only scoping; this let it write.

So what for TSD: If you use plan mode to scope a change before touching anything — especially in a client repo — you were exposed to unprompted deletes. Update to 2.1.212 before your next planning-heavy or unattended session.
Changelog · 2.1.212
Fix 2.1.212

Worktree creation could follow a symlink out of the repo

Fixed worktree creation following a repository-committed symlink at .claude/worktrees, which could create files outside the repository. Same release also fixed a continue:false hook's halt being dropped when a tool fails or completes mid-stream, and a SIGTERM during a running Bash tool orphaning the command's process tree in print/SDK mode.

So what for TSD: Your loops create worktrees. A repo carrying a hostile .claude/worktrees symlink could have written outside the checkout — the risk is real only if you ever run Claude Code against a repo you didn't author, but that's the direction the business is heading. Update and it's closed.

◆ Session & agent workflow

Feature 2.1.212

/fork spawns a background session; the old behavior is now /subtask

/fork now copies your conversation into a new background session — its own row in claude agents — while you keep working in the original. The in-session subagent it used to launch is now /subtask. If the session has no title, the fork is named after your prompt so the row is recognizable. Alongside it: /resume in the agent view now opens a picker of past sessions, including ones deleted from the list, and resumes your pick as a background session.

So what for TSD: /fork is now a genuine parallel-work spawn — split a client build into two tracks and keep both moving. Retrain the muscle memory: reach for /subtask when you want the old inline delegation, and use the new /resume picker to claw back a session you thought you'd lost.
Changelog · 2.1.212
Breaking 2.1.212

Task tool's mode parameter is deprecated

The Task tool's mode parameter is now ignored; subagents inherit the parent session's permission mode by default. Also for SDK/headless: a set_model control request now applies mid-turn — the next model round-trip uses the new model instead of waiting for the next turn — and transcripts now record the reasoning-effort level on each assistant message.

So what for TSD: If any of your SDK harnesses or loop scripts pass mode into the Task tool, it's now a no-op — audit them so a subagent doesn't silently run with wider permissions than you assumed. Inheriting the parent mode is the safer default, but only if the parent's mode is what you intended.

◆ Review tooling (/ultrareview)

Fix 2.1.212

A cluster of /ultrareview fixes

Four fixes to the cloud review flow: it now accepts PR references like #123, PR 123, and pasted PR URLs (with error hints that name the command you actually typed); /ultrareview <branch> fetches the branch from origin when it exists remotely and suggests the closest name on typos; the billing confirmation is no longer skipped in a new conversation after /clear; and the "not a git repository" error on Claude Desktop now points at the project's repo folder instead of terminal commands.

So what for TSD: The branch-review flow is less brittle. If earlier friction — a rejected PR URL, a branch it wouldn't fetch — made you stop using it on client PRs, it's worth a second look. Paste the PR URL and let it run.
