◆ Two things that were quietly deleting data

Fix 2.1.228

Session cleanup deleted contents inside a project's memory folder

The changelog entry is one line: "Fixed session cleanup deleting contents inside a project's memory folder." No detail on trigger conditions or blast radius, so treat the affected window as "any version before 2.1.228."

This lands on the exact directory the harness manages per project — ~/.claude/projects/<project>/memory/ — rather than on anything you keep under version control.

So what for TSD: Your July migration to a git-backed command vault is what made this a non-event. The harness memory dirs are pointer files now, and the vault is a real repo with history on two Macs. If you ever get tempted to move durable memory back into a harness-managed folder to save a step, this is the counter-argument. Upgrade, then spot-check that ~/.claude/projects/-Users-nashdavis-Documents/memory/MEMORY.md still holds its pointer line.

Fix 2.1.228

Background plugin-cache cleanup wiped symlinked dev checkouts

Background cleanup deleted a plugin's cache when its only installed version was a symlinked development checkout. The symlink target is a working directory you are editing, so the deletion reached live work.

So what for TSD: Only bites if you develop plugins locally by symlinking a checkout into the plugin dir. If you have been doing that for any TSD tooling, confirm the checkout is intact and that it has a remote before you upgrade and forget about it.

◆ Trust boundaries tightened on synced content

Behavior change 2.1.228

Skills synced from claude.ai are now treated as untrusted input

Four changes in one bullet. Synced skills can no longer shadow local commands or MCP prompts. Their descriptions are sanitized and labeled. And on your machine, their bodies no longer execute ! commands or expand @ file references.

The first three are pure hardening. The fourth is a capability removal: a synced skill that shelled out through ! or pulled in a file with @ silently loses that behavior after upgrade.

So what for TSD: Audit the skills you actually invoke. Anything you authored on claude.ai and sync down — the advisor skills, the humanizer, the vault-refresh helpers — needs a check for ! or @ in its body. If one depends on either, move it to a local .claude/skills/ file instead of relying on sync. Name collisions are the other thing to verify: a synced skill that used to win over a local slash command now loses, so check that the version firing is the version you meant.

Fix 2.1.228

Marketplace entries stopped inheriting another tier's custom headers

A settings-merge bug let a marketplace entry redefined in a higher-precedence settings tier inherit custom headers from a different tier. Marketplace entries now merge as whole entries.

So what for TSD: Custom headers on a marketplace entry usually carry auth. If you have marketplace config in more than one settings tier, an entry could have been sending credentials meant for a different registry. Grep your settings files for marketplace blocks with headers and confirm each one points where you think.

◆ The build loop

Change 2.1.228

Write no longer forces a read before overwriting, on newer models

The Write tool now lets newer models overwrite an existing file they have not read this session, matching the Edit tool's rules. Older models still require the read first.

The practical effect is one fewer tool round trip every time a file gets regenerated wholesale rather than patched. The tradeoff is the obvious one: a blind overwrite discards whatever was there, with no diff step in between.

So what for TSD: This is a throughput win on the work you do most — scaffolding a Next.js route, regenerating a Tailwind config, rewriting a component from a spec. It also removes the accidental safety net that read-first provided. Keep the checkout clean before you hand off a batch of file rewrites, so git diff is the review step that the forced read used to be.

Fix 2.1.228

Interactive sessions could stop redrawing while still running

A rare internal layout error could stop an interactive session from redrawing entirely. The process kept going underneath a frozen screen, which reads as a hang from the outside.

So what for TSD: If you have a habit of Ctrl-C-ing a session that looks stuck on a long build or migration, some of those were live and about to finish. After upgrading, give a silent session more rope before killing it.
Claude Code changelog — 2.1.228
Fix 2.1.228

Long-session papercuts: /tui model reverts and blind compaction

Two items for anyone who keeps sessions alive for hours. /tui could revert the session to an earlier model when /model had been changed since the last response — you would end up on a different model than the one you selected, silently. And compaction now surfaces its retry countdown and stall hint instead of showing only a progress bar.

So what for TSD: The /tui one matters if you switch models mid-session, which you do when a task escalates. Worth re-checking /status after any /tui toggle on versions before 2.1.228. The compaction hint means a stalled compaction on a long Bisque session now tells you it is stalled rather than looking like slow progress.

◆ Agent-to-agent messaging becomes readable

Improve 2.1.228

Cross-session messages display inline with their sender

Cross-session messaging shipped in 2.1.224. In 2.1.228 the sender and body render inline instead of collapsing to a single line, and messages sent to Remote Control sessions on other machines show your Remote Control session name as the sender. A companion fix stops cross-session messaging from starting without an inbox in the first session after an install or upgrade.

So what for TSD: This is the feature to watch for multi-repo work — a session in the Bisque checkout messaging one in Sonderwerks without you relaying by hand. Readable inline messages are what make it debuggable enough to actually try. Worth one experiment on a low-stakes pair of repos before you build any routine around it.
