◆ Agent & workflow reliability

Fix 2.1.187

Structured-output workflows stop looping forever

Two structured-output bugs are closed. With --json-schema and workflow agent({schema}), the model could keep re-calling the StructuredOutput tool indefinitely after it had already succeeded, and follow-up turns sometimes failed to return structured output at all. Both are fixed — the call resolves once and later turns stay structured.

So what for TSD: If you run multi-agent workflows that force a JSON schema (the RAG-demo eval passes, any pipeline that returns validated objects), this removes a class of runs that silently burned tokens or returned junk. Worth re-running any workflow you'd shelved as flaky.
Changelog · 2.1.187
Fix 2.1.187

Hung remote MCP calls now abort instead of blocking the turn

A remote MCP tool call that hangs with no response used to block for a full 5 minutes before anything happened. It now aborts with an error, and you can tune the threshold with CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT. Paired fixes also stop background jobs from getting stuck in "working" when an agent ends a turn without structured output, and clean up leaked worktree locks left by killed agents.

So what for TSD: You lean on remote MCP connectors (Vercel, Notion, Supabase tooling) across builds. A flaky connector now fails fast and you retry, instead of a scheduled or background run silently stalling for five minutes. Direct win for unattended scout/automation runs.

◆ Security & access control

New 2.1.187

New setting keeps secrets out of sandboxed commands

The new sandbox.credentials setting blocks sandboxed commands from reading credential files and secret environment variables. Separately, organizations can now restrict which models appear in the picker, --model, /model, and ANTHROPIC_MODEL, with a clear "restricted by your organization's settings" message when a blocked model is picked.

So what for TSD: You run agents against repos full of live keys (Resend, Supabase service-role, LemonSqueezy webhook secrets). Turning this on is cheap insurance that a sandboxed shell step can't slurp a .env — set it before the next unattended fleet run.
Changelog · 2.1.187

◆ Workflow & UI quality-of-life

Improve 2.1.187

GitHub App install no longer forces the Actions setup

/install-github-app now makes the GitHub Actions workflow setup optional — you can install just the GitHub App and skip the workflow and secret steps. Alongside it, select menus (permission prompts, /model, /config) gained mouse-click support in fullscreen mode.

So what for TSD: When you wire the GitHub App onto a client repo (Bisque, the renters funnel) you don't need the full CI workflow scaffolding to get App-level access. Fewer steps to skip, less to clean up afterward.
