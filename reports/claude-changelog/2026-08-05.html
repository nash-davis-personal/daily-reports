2.1.222 is a containment patch: worktree isolation was leaking into your real checkout

◆ Isolation stopped being a suggestion

Fix 2.1.222

Worktree-isolated sessions could run destructive git against the main checkout

The changelog states it plainly: worktree-isolated sessions and their subagents were able to run destructive git commands against the main checkout. The fix extends isolation to file edits and Bash across every session type, which means the previous boundary was covering less than the name implied.

This lands one day after 2.1.221 changed /fork to create its own worktree and changed background sessions to commit and push on their own. Those two features were shipping into a boundary that had this hole in it.

So what for TSD: Update before the next unattended run of anything that uses worktree isolation. If a loop or background session touched a client repo since 2.1.221 landed, run git reflog and git status on the main checkout for Bisque, Studio C, and Sonderwerks before you trust the tree. A destructive git command against a main checkout is the one failure mode that survives a rerun.

Fix 2.1.222

PreToolUse auto-allow hooks skipped tool restrictions in background agent tasks

Auto-allow hooks were bypassing tool restrictions during the background work Claude Code does on its own: summaries, compaction, and renames. Those tasks run without you watching them, which is exactly where a restriction is doing its most useful work.

So what for TSD: Re-read any PreToolUse hook you wrote to auto-allow a narrow command set. It was broader than you configured during background tasks, so a hook that allowed a safe subset of Bash was effectively allowing more. Worth a pass over hooks in the daily-reports and client repos.
Claude Code changelog ◆ 2.1.222
Improve 2.1.222

Auto mode now classifies SendMessage before it dispatches

Messages sent to other agent sessions via SendMessage are now evaluated by the permission classifier before they go out. Previously an agent could instruct a sibling session without that message being checked, which turns agent-to-agent messaging into a way around the classifier.

A related refusal change: when Claude tries to invoke a skill marked disable-model-invocation, it is now told to ask you to run the skill instead of reproducing the skill's workflow itself.

So what for TSD: Both changes make multi-agent runs behave closer to how they read on paper. The skill one matters if you flagged any skill as human-invoke-only expecting that to stop the workflow from happening. Until now Claude would just do the work inline.
Claude Code changelog ◆ 2.1.222

◆ Control surface moved

Breaking 2.1.222

Repo-local settings can no longer turn Remote Control auto-start on

Remote Control auto-start is now user-scope only, set through /config. A repo's .claude/settings.json or .claude/settings.local.json can still turn it off, and the off direction still works from the repo.

The asymmetry is the point: a checked-in settings file should not be able to switch on remote access to a machine that clones it.

So what for TSD: If any repo enables Remote Control auto-start in its settings file, that line is now dead and the feature silently stops arriving. Set it once at user scope through /config and delete the repo-level line so the config stops lying about what is active.
Claude Code changelog ◆ 2.1.222
Breaking 2.1.222

Ultraplan removed

One line in the changelog, no replacement named and no migration path given. Planning work goes back to plan mode and the planning skills.

So what for TSD: Check any skill, scheduled task, or CLAUDE.md that references ultraplan and cut the reference. A scheduled task that invokes a removed feature fails at 3am with nobody reading the output.

Improve 2.1.222

Diffs now read raw git blob content

/diff, the Remote Control workspace diff, and file-edit diffs in Claude Code on the web now use raw git blob content, ignoring workspace-configured diff drivers and textconv.

So what for TSD: Diffs now show what is actually in the file. If a repo configured a diff driver to prettify or filter something, the review surface was showing you the filtered version while the commit carried the raw one.

◆ Metering and connection accuracy

Fix 2.1.222

/usage was attributing far too much to MCP servers

A server's share of usage previously counted every turn after any call to it. It now counts only the requests that actually consumed that server's tool results.

So what for TSD: Re-run /usage before you drop any MCP server for being expensive. With a connector surface as wide as yours, the old numbers inflated whichever server you happened to call earliest in a session.
Claude Code changelog ◆ 2.1.222
Fix 2.1.222

Three connection failures that were reporting the wrong thing

The startup connectivity check was hanging and then failing behind an HTTPS proxy; it now uses the same proxy-aware transport as API requests and times out with a clear message. "Connection closed mid-response" was being reported on responses that had actually completed. Stream idle timeout was firing on custom ANTHROPIC_BASE_URL gateways even while server keep-alive pings were arriving.

Separately, claude.ai connectors were being marked as needing authorization when the real problem was an invalid session token. They now show a /login hint.

So what for TSD: The connector one saves real time. If a claude.ai connector has been showing as needing authorization on this Mac, try /login before re-authorizing anything through connector settings.
