◆ Still open from the last window

Fix 2.1.225

Get every unattended runner onto 2.1.225 or later

The transient-401 bug replaced a long-lived CLAUDE_CODE_OAUTH_TOKEN with a stored login's short-lived token and left headless sessions broken until the process restarted. Same release also fixed cross-session messages parking in headless sessions with no notice and no expiry.

Both failures only show up in long-running unattended work, which is precisely the category that nobody watches until it has been quietly failing for a while.

So what for TSD: Check the version on whatever machine runs your scheduled jobs, not the one you sit at. A quiet Sunday is the cheapest time to bounce a runner, and the next scheduled cadence will tell you whether it took.
Changelog · 2.1.225
Feature 2.1.224

The 2.1.224 features are unconfigured until you configure them

Three items from Thursday still need a deliberate decision: claude self-hosted-runner for running web, mobile and desktop sessions on your own machines (Team and Enterprise plans), the archive plugin source for installing plugins from a zip over HTTPS with optional SHA-256 pinning, and cross-session SendMessage with ListAgents on macOS and Linux.

The same release also removed the 200-subagent-per-session spawn cap, so long-running sessions no longer refuse new agents. Concurrency and depth limits still apply.

So what for TSD: Cross-session SendMessage is the one with near-term value for you, since it is what lets a Bisque build session hand off to a separate verification session rather than doing both in one context. Prove it works between two sessions you can watch before you put it anywhere near a scheduled job.
