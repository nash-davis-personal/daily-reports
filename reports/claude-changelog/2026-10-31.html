Claude Code Changelog ◆Saturday, October 31, 2026 ◆Release 2.1.316

Subagents get their own effort dial, and Opus 4.8 fast mode dies November 30

One release landed since yesterday's briefing. The useful parts for TSD are a setting that stops subagent fan-outs from burning top-effort tokens by default, plus a batch of fixes that make unattended scheduled runs exit cleaner and fail honestly.

Subagent effort is now its own setting

CLAUDE_CODE_SUBAGENT_EFFORT sets the effort subagents run at when nothing else names one. Before this they inherited the session's.

On macOS and Linux, commands no longer keep running after Claude Code exits on its own, such as a refused credential or an archived cloud session.

◆ Agent cost and control

New 2.1.316

CLAUDE_CODE_SUBAGENT_EFFORT decouples subagents from the session's effort

Subagents used to run at whatever effort the parent session ran at. The new environment variable sets a default effort for subagents whenever no agent definition or call names one. A main session at xhigh can now send its Explore and search helpers out at a lower level.

So what for TSD: Set it to medium in the env for the scout, fleet-steward and vault-refresh scheduled tasks, where subagents mostly grep and read. Leave client build sessions alone until you see a quality difference. It cuts token spend on every fan-out without touching how the lead agent thinks.
Changelog 2.1.316 · Added
Fix 2.1.316

Woken subagents no longer jump to the main model

A nested sub-agent that inherited its parent sub-agent's model was switching to the session's main model when a background job or message woke it. That is fixed.

So what for TSD: If any long-running workflow showed a cheap Haiku or Sonnet helper suddenly billing like Opus partway through, this was the likely cause. No action needed beyond updating.
Changelog 2.1.316 · Bug fixes
Feature 2.1.316

Ultrathink gets an off switch, and VS Code matches the terminal

CLAUDE_CODE_DISABLE_ULTRATHINK turns the ultrathink keyword off. In VS Code, ultrathink now runs its turn at xhigh effort, as the terminal already did. A VS Code bug that hid the Effort slider and model name when the model carried the [1m] tag is also fixed.

So what for TSD: Worth setting the disable flag in unattended runs whose prompts are pasted from client text or scraped pages, so a stray word can't push a cheap job to top effort.

◆ Deprecation

Breaking 2.1.316

Fast mode on Opus 4.8 ends November 30, 2026

Fast mode for Opus 4.8 was deprecated on October 30 and will be removed on November 30. After that, fast mode requests on Opus 4.8 return an error. They do not fall back to standard Opus 4.8. The changelog says to move to Opus 5.5 to keep the speedup.

So what for TSD: Your global Claude Code settings don't pin a model, so interactive sessions are fine. Before Nov 30, grep client repos and any API code (Bisque, Studio C, Sonderwerks, Nash OS scripts) for claude-opus-4-8 or opus-4.8 paired with fast mode and switch them to claude-opus-5-5. A silent error in a client-facing feature is the failure to avoid.

◆ Unattended runs

Fix 2.1.316

Shell commands stop with Claude Code, and Bash scripts run past line one

When Claude Code exits by itself on macOS or Linux, for example after refused credentials, its shell commands no longer keep running. Separately, bash scripts started from the Bash tool no longer stop after their first command when SHELLOPTS is exported, and multi-line alias values no longer get garbled.

So what for TSD: The two Macs run a lot of launchd and scheduled-task jobs. Orphaned dev servers or tail processes from a crashed run are one fewer thing to clean up. If any scheduled job ever ran "half" a script, re-check it after updating.
Changelog 2.1.316 · Bug fixes
Change 2.1.316

Auto mode keeps its scheduled-task rule, and stopped runs are marked failed

An autoMode.allow list written without "$defaults" no longer removes the built-in rule on scheduled-task prompts. Cloud sessions and cloud scheduled tasks are now marked failed when auto mode stops a turn because the server returned no safety verdict, and claude -p text output says why auto mode stopped a turn even with a background agent running.

So what for TSD: The Nash OS Machine page relies on runs reporting their own outcome. A run that auto mode halted used to look finished; now it shows as failed, so expect a few honest reds where there used to be false greens.
Changelog 2.1.316 · Changed / Bug fixes

◆ Review and cloud sessions

Improve 2.1.316

/code-review from the Desktop Code tab shows the findings card

/code-review started from the Desktop Code tab or the web now shows the findings card in cloud and claude remote-control sessions, where it used to print a plain-text list. Cloud sessions also gain a form card for MCP servers that ask for input, which used to be canceled without you seeing it, and a "Catching up…" line when you switch back to a session that is still syncing.

So what for TSD: Reviewing a client PR from your phone over Remote Control gets readable. Run a review before each client deploy from wherever you are.
