◆ What last week's feature drop buried

Security 2.1.223

Four permission escapes patched in one release

2.1.223 fixed a Bash permission bypass where a crafted command could hide parts of itself from permission checks, and separately fixed permission prompts so that commands padded with tabs or invisible Unicode can no longer hide part of the command from the approval dialog. It also stopped workflow scripts from using dynamic import() to run code outside the workflow sandbox, and closed a gap where an agent definition's bypassPermissions mode ignored the org bypass-permissions disable policy.

All four share a shape: the approval you clicked did not cover what actually ran. That is the failure mode that matters most on a machine where you approve a lot of commands quickly.

So what for TSD: This is the release floor. Anything below 2.1.223 that touches client repos should move up today, including whatever runs your scheduled jobs. You approve Bash constantly across Bisque, Studio C and Sonderwerks work, and the padded-command fix is the one that protects a prompt you skim rather than read.
Changelog · 2.1.223
Security 2.1.222

Worktree isolation and hook restrictions both leaked

Worktree-isolated sessions and their subagents could run destructive git commands against the main checkout. Isolation now applies to file edits and Bash in every session type. The same release stopped PreToolUse auto-allow hooks from bypassing tool restrictions inside background agent tasks such as summaries, compaction and renames.

Worth naming plainly: if you reached for worktree isolation as the safety net that let you run agents unattended against a client repo, that net had a hole in it until August 4.

So what for TSD: Re-check any loop or scheduled agent you built on worktree isolation before August 4 and confirm it is on 2.1.222 or later. If you wrote a PreToolUse auto-allow hook to smooth out an unattended run, re-read it now that it no longer overrides tool restrictions in background tasks, because its real blast radius was wider than you designed for.
Changelog · 2.1.222

◆ Two settings that deserve a deliberate decision

Privacy 2.1.224

The feedback-survey transcript share now includes your system prompt

Per the changelog, with your consent the share now also uploads the last request's model settings: the system prompt, which includes your CLAUDE.md instructions, plus tool definitions and model parameters. Secrets are redacted as before, and these fields are dropped first if the share is too large.

Redaction catches secrets. It does not catch client names, internal vault paths, deploy-scope guardrails or the account rules you keep in your global instructions, because none of that looks like a credential.

So what for TSD: Your global CLAUDE.md names Bisque, the Vercel team scopes and your vault layout. Treat the feedback survey as a client-confidentiality decision from now on and decline the transcript share on any session running client work, or accept it knowing exactly what goes with it.
Changelog · 2.1.224
Change 2.1.223

Context-window enforcement got stricter for 1M-context models

CLAUDE_CODE_DISABLE_1M_CONTEXT now holds every Claude model with a native 1M window to 200K through auto-compaction instead of a fixed list, and a startup warning appears when auto-compaction is not holding the session to 200K. Separately, auto-compact now keeps sessions on unrecognized model IDs inside the assumed context window; CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1 restores the old behavior.

Both changes trade some session length for predictable token spend on long runs.

So what for TSD: Only relevant if you set that env var somewhere and forgot. If a long session starts compacting earlier than you expect, check for it before you start debugging anything else.
