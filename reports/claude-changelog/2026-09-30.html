◆ Models, cost and effort

New 2.1.284

Claude Sonnet 5.5 is the default Sonnet on the Anthropic API

2.1.284 adds claude-sonnet-5-5 and makes it the default Sonnet on the Anthropic API. The changelog lists a 1M context window at $2 input and $10 output per million tokens, with cache reads at $0.20. A related 2.1.285 change: sessions behind a custom ANTHROPIC_BASE_URL now use the 1M window on models that have one (Opus 4.7+, Sonnet 5+, Fable); run /autocompact 200k if your gateway caps at 200K.

So what for TSD: Any client feature that calls Sonnet by a pinned older ID keeps its old price and behavior until you change it. Spend 20 minutes this week listing every model string in the Bisque, Studio C and Sonderwerks repos, run each feature's eval or smoke test against claude-sonnet-5-5, and update the per-client cost line in the retainer math with the new rate.

Changed 2.1.284

Ultracode split out of the effort slider

Ultracode is now a separate toggle in /effort (Tab, or /effort ultracode [on|off]). It stays on at any effort level and no longer forces xhigh. New keybinding actions effortSlider:decreaseEffort, increaseEffort and toggleUltracode let you rebind the slider keys. VS Code gets a matching switch under the Effort slider.

So what for TSD: You can now run multi-agent Ultracode at medium effort on routine client tickets and keep xhigh for the hard ones, which should cut token burn on big fan-out jobs. Try it on the next Bisque batch task and compare cost in /cost.

◆ Defaults that changed under you

Default change 2.1.284 / 2.1.285

Auto mode becomes the default permission mode

In 2.1.284, interactive terminal and VS Code sessions start in auto mode when no permission mode is configured, on every plan and provider. permissions.defaultMode still overrides it. In 2.1.285, claude -p and Python Agent SDK sessions on third-party providers or with telemetry off follow suit; --permission-mode still wins. Auto mode also gains a "Yes, but ask again next time" answer for one-off reads outside the working directories.

So what for TSD: The 2.1.283 briefing flagged the narrower version of this; now it covers every fresh machine and every repo without a settings file. Put an explicit permissions.defaultMode in user settings on both Macs, and in any project that can reach the Bisque Vercel scope or a client's production Supabase, so the behavior is a choice you made.

Default change 2.1.285

Background shell commands get a hard time limit

Background Bash and PowerShell commands now stop after their timeout when run with run_in_background. The default is 30 minutes and the maximum is 2 hours. Claude is notified when one is killed. Separately, synchronous hooks no longer hang when they spawn a daemon with & that holds its output open.

So what for TSD: Anything you or a scheduled task starts in the background and expects to outlive half an hour (a long Vercel build tail, a video render, a watcher) will now be killed silently from your point of view. Pass an explicit timeout up to 2 h, or move truly long jobs to launchd where the Nash OS runners already live.

◆ Unattended runs, MCP and artifacts

Feature 2.1.284

/mcp reconnect all and steadier MCP on resume

/mcp reconnect all retries every MCP server that failed or needs auth in one go. MCP tool calls in a resumed session now wait up to 10 seconds for a still-connecting server before failing with "No such tool available". 2.1.285 also makes claude mcp list show WebSocket servers with health status.

So what for TSD: Your setup routinely has a few servers timing out at startup (this very run saw chrome-devtools and notebooklm drop). Make /mcp reconnect all the first move when a session looks tool-starved, before restarting it.
Changelog 2.1.284
Fix 2.1.284 / 2.1.285

Scheduled-run and workflow reliability fixes

A failed agent(), parallel() or pipeline() call that a workflow script awaits late (or never) no longer counts as an unhandled rejection that can end a background session. /loop in self-paced mode now writes each status update as visible text. "Prompt is too long" after compaction now triggers a second, tighter compaction. Damaged response streams are retried instead of writing "undefined" into answers.

So what for TSD: These hit the daily scout, the Fleet Steward style loops and any multi-agent Workflow you run overnight. Nothing to change; if a scheduled task was dying mysteriously last week, rerun it on 2.1.285 before debugging.

Feature 2.1.285

claude --desktop, resuming background sessions, and a VS Code diagnostics tool

claude --desktop opens the desktop app on the current folder, or on a session with --continue / --resume <id>. /resume on a session running in the background now opens it, and claude --resume <id> "prompt" sends that prompt as its next turn. In VS Code, Claude can now read the Problems panel on demand, beyond the check right after an edit.

So what for TSD: claude --resume <id> "prompt" is a clean way to nudge a long-running background build from a script or phone shortcut. The VS Code diagnostics tool means type errors in Next.js client repos get caught mid-task; ask Claude to check Problems before it declares a feature done.
