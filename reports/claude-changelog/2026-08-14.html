◆ Agent throughput and token spend

Feature 2.1.232

Subagent forking flipped to on by default

Two changes in one bullet. A subagent_type: "fork" subagent inherits the full conversation and the prompt cache, so a forked agent starts already knowing what the parent session knows. And non-teammate agent spawns in interactive sessions now run in the background by default, so spawning one stops blocking the turn you are in.

The economics matter more than the ergonomics. A cold subagent re-reads context from scratch and pays for it; a fork reads the cache.

So what for TSD: This makes delegation cheap enough to be the default on long client sessions. On a Bisque or Sonderwerks build where you have already loaded the schema, the component tree and the deploy history into context, forking a subagent to chase a side question no longer costs a second full context load. Watch the flip side: background-by-default means spawned agents finish while you have moved on, so check /tasks before you assume nothing ran.
Claude Code changelog — 2.1.232
Improvement 2.1.229

Workflow fan-outs stagger same-prefix siblings to hit the cache

When a workflow fans out to sibling agents that share a prompt prefix, they are now staggered so the later ones read the cached prefix instead of re-paying for it. The stagger is tunable off with CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS=0.

Paired with this, /code-review at high, xhigh and max effort now runs in a background agent like the other levels (2.1.232).

So what for TSD: Every wide fan-out you run gets cheaper with no change on your end. The /code-review change is the one you will feel day to day: high-effort reviews stop pinning the session, so you can keep editing while a review runs against the branch. Leave the stagger alone unless you are debugging a workflow that depends on simultaneous starts.
Claude Code changelog — 2.1.229
Improvement 2.1.232

Fullscreen streaming stops re-normalizing the whole conversation

Long sessions stay responsive because the entire conversation is no longer re-normalized on every update. 2.1.229 separately fixed long responses partly disappearing while streaming and then being printed twice, and fixed multi-second UI stalls after editing a file with thousands of IDE diagnostics while the extension is connected.

So what for TSD: The sessions that got sludgy were the ones worth keeping — a full afternoon on one client repo. If you have been starting fresh sessions to escape the lag and re-paying for context every time, stop doing that and upgrade instead.

◆ MCP connections and OAuth

Fix 2.1.231 · 2.1.229

Two separate MCP OAuth failures got fixed two days apart

2.1.231 is a single-bullet release: MCP OAuth sign-in was failing with a redirect URI mismatch for servers that use a pre-registered OAuth client, with Slack named as the example. 2.1.229 fixed a different one — strict authorization servers rejecting the callback — by using 127.0.0.1 in the redirect URI instead of localhost.

Both present the same way from your seat: you click through the browser flow, it looks fine, and the server comes back unauthenticated.

So what for TSD: Go re-auth the connectors you wrote off. Several of yours are sitting unauthenticated right now, including the Vercel plugin server, Stripe and Square — all three are exactly the pre-registered-client shape 2.1.231 fixed. Upgrade first, then run the sign-ins from an interactive session. A working Stripe and Square connector is the difference between reading a client's payment data and asking them to screenshot it.
Claude Code changelog — 2.1.231
Fix 2.1.232

A broken MCP server no longer burns the full connect timeout

MCP connections hung for the entire 30-second connect timeout when a server failed to answer the protocol-version probe or sent a malformed reply. They now fail fast.

So what for TSD: You run a long MCP list across Supabase, Vercel, Notion, Calendly, Vapi and the rest. One sick server was taxing every session start by half a minute. If startup has felt slow, this is a chunk of it, and the fix costs you nothing but the upgrade.

◆ Permission gates got stricter

Behavior change 2.1.229

/commit-push-pr stopped auto-approving destructive git flags

Git and gh commands carrying dangerous flags — the changelog names --force, --amend and --no-verify — are no longer auto-approved inside /commit-push-pr. They stop for permission like any other risky command.

So what for TSD: This touches the one workflow you have already been burned on. Your Bisque deploy path is a plain git push now that the Vercel seat is resolved, so the happy path is unaffected. Where you will notice it is any cleanup pass that amends a commit or force-pushes a branch preview: expect a prompt, and read it rather than reflexively approving. An extra confirmation before a force-push into a client repo is a feature.
Claude Code changelog — 2.1.229
Behavior change 2.1.232

Nested git repositories no longer inherit trust from the parent

Each repository now requires its own trust confirmation. Previously a repo nested inside a trusted directory was trusted along with it. Alongside this, Bash input redirections (< file) are now permission-checked like their argument spellings on all platforms, and sandbox.ripgrep is honored only from user, managed and --settings settings so project settings can no longer override the sandbox's ripgrep binary.

So what for TSD: You work out of ~/Documents with client repos and two vaults underneath it. Expect a run of trust prompts on the next upgrade, one per repo, and treat that as a one-time tax. The sandbox.ripgrep change is the one to remember if you ever script a project-level settings file and wonder why the override is ignored.
Claude Code changelog — 2.1.232

◆ Sessions can now address each other by name

Feature 2.1.232

@-mention another Claude session from the prompt

Type @ in the prompt to mention another Claude session by name, and Claude uses SendMessage to reach it directly. SendMessage now delivers to a bare name that exactly matches one live session instead of asking you to confirm with a ref first. To keep that unambiguous, interactive sessions on one machine now hold unique names: starting or renaming a session to a name another live session already uses produces a name-word-word variant and tells you. /config gained rows for "Dialog expiry" and "Messages from your other sessions".

So what for TSD: This is the multi-repo pattern you already work in — one session on a client build, another on the vault or a report — finally wired together. Name your sessions per client and you can push a finding from the Studio C session into the Sonderwerks one without copy-paste. Check the new /config inbound row before you rely on it; cross-session messages can be set to hold for approval rather than auto-deliver.
