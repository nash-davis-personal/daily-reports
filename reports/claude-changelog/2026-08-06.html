◆ The permission layer got four holes patched

Fix 2.1.223

A crafted Bash command could hide part of itself from the permission check

Two separate fixes land here. The first closes a Bash permission bypass where a crafted command could hide parts of itself from permission checks. The second covers the display side: commands padded with tabs or invisible Unicode could hide part of the command from the approval dialog, so what you read and what ran were different things.

This is the third consecutive release touching Bash permission parsing. 2.1.221 fixed zsh executing hidden commands inside [[ ]] regex conditionals and PowerShell mishandling quoted paths on Windows.

So what for TSD: Update today, before the next scheduled task fires. Your daily-reports scout, the vault refresh, and any loop you leave running all approve Bash on your behalf while you are not at the keyboard. That is exactly the shape of session this class of bug abuses.

Fix 2.1.223

Workflow scripts could run code outside the workflow sandbox

Workflow scripts were able to use dynamic import() to execute code beyond the sandbox that is supposed to contain them. Workflow scripts are plain JavaScript with a deliberately narrow surface — no filesystem, no Node APIs — and this defeated that boundary.

So what for TSD: Direct hit on the loop-engineering pattern you build for repos and vaults. A loop's whole safety argument rests on the sandbox holding. If you have written workflow scripts you have not read end to end since, skim them for import( before your next unattended cycle.

Fix 2.1.223

An agent definition's bypassPermissions ignored the org disable policy

An agent definition that declared bypassPermissions mode would take it even when the organization policy disabling bypass-permissions said otherwise. The agent file effectively outranked the admin setting.

So what for TSD: Low impact for a solo operator with no org policy to violate. Worth filing under what you can say when a client's IT contact asks whether the agent respects their guardrails — the answer is now yes, and pinned to a version.

◆ Context budgets and model resolution

Behavior change 2.1.223

The 1M-context kill switch now covers every 1M model, and unknown model IDs get held to a window

CLAUDE_CODE_DISABLE_1M_CONTEXT used to apply to a fixed list of models. It now holds every Claude model with a native 1M window down to 200K through auto-compaction, and prints a startup warning when auto-compaction is failing to enforce that ceiling.

Separately, auto-compact now keeps sessions running on unrecognized model IDs inside an assumed context window rather than letting them grow unbounded. CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1 restores the old behavior.

So what for TSD: You run Opus 5 on 1M context. If you use the disable flag anywhere to keep long sessions cheap, its blast radius just widened to every 1M model, so check any wrapper scripts or launchd env before you get surprised by a mid-session compaction. If you point Claude Code at a gateway with custom model IDs, the second change will start compacting sessions that previously ran uncapped.
Changelog · 2.1.223
Improve 2.1.223

You now get told when a subagent silently ran on the parent model

Workflow agents, forked skills, slash commands, and resumed background agents that request a restricted subagent model now emit a warning explaining the parent model ran instead. Previously the downgrade was silent.

Related plumbing in the same release: gateway model discovery no longer hides Claude models registered under provider-prefixed IDs like vertex_ai/claude-* or bedrock/anthropic.claude-*, and modelOverrides keys that are not Anthropic model IDs are now ignored as documented rather than being treated as the session's canonical model.

So what for TSD: If a workflow stage has been producing weaker output than the model you specified should give, this warning is how you will finally see why. Worth a rerun of your loop-engineering workflows to check nothing has been quietly running on the wrong tier.

◆ Commands you actually type

Behavior change 2.1.223

/review is now an alias of /code-review, with a sticky effort level

The two review commands are one. /code-review reviews the current diff or a PR via /code-review <level> <pr#>, and /code-review ultra launches the deep cloud review. Calling /code-review with no effort level reuses whatever level you typed last, so you set it once by typing something like /code-review high and every bare call after that inherits it.

So what for TSD: Set the level deliberately on your first review of a client branch, because every bare /code-review after it silently inherits that choice. Cheap habit: run /code-review high once per session on Bisque or Sonderwerks work, then bare calls for the rest.

New 2.1.223

Cloud sessions now show you the teleport command

Cloud sessions display a /teleport hint with the exact invocation to continue that session on your own machine: claude --teleport <session id>.

So what for TSD: Makes the phone-to-desk handoff practical. Kick a client fix off from claude.ai while you are out, teleport into it at the desk with the context intact instead of re-explaining the problem to a fresh session.
