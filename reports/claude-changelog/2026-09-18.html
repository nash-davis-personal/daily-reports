Claude Code Changelog ◆Friday, September 18, 2026 ◆2 releases in window

A send-now key ships for queued messages, and a memory bug that was quietly busting prompt caches on every resume gets fixed

2.1.275 (Sep 17) is the bulk of this window: a ctrl+enter "send now" key that interrupts the current turn and fires all queued messages at once, claude.ai skills and plugins syncing straight into terminal sessions, a fix for a memory-file bug that was breaking prompt cache hits on every compaction or resume, and npm-sourced plugins now installing with their scripts blocked and integrity-checked. 2.1.276 (Sep 18) is a single regression fix for sessions running behind a proxy or gateway.

◆ Top signals — read these first
01

A send-now key for queued messages

ctrl+enter (or ctrl+x ctrl+s) interrupts the current turn and sends every queued message at once, instead of waiting for the turn to finish or sending them one by one.

02

Prompt cache no longer breaks on a resumed session

A restored memory file's age note was changing between requests after a compaction or resume, which quietly busted the prompt cache on that request. Fixed.

03

npm-sourced plugins can't run install scripts anymore

Plugins installed from an npm source are now fetched with npm pack --ignore-scripts and integrity-verified, so a malicious package's install script no longer executes on your machine.

04

claude.ai skills and plugins now sync to your terminal

Whatever skills and plugins are enabled on your claude.ai account now sync into terminal sessions signed in with it. Opt out with syncClaudeAiSkills: false / syncClaudeAiPlugins: false.

05

/code-review stops dropping part of its analysis

Reviews occasionally lost part of their findings when one of the reviewing agents returned its output in an unexpected format. Fixed.

◆ Working faster

New 2.1.275

A send-now key clears your queued messages immediately

ctrl+enter, or ctrl+x ctrl+s, interrupts whatever turn is currently running and sends every message you've queued up in one shot. Sent and queued messages show in gray until the model actually receives them.

So what for TSD: If you're stacking up follow-up instructions while Claude works through a long client task — say, three build tweaks on the Bisque storefront back to back — you no longer have to wait out the current turn or watch them trickle in one at a time. Worth building into how you queue work on longer sessions.

New 2.1.275

claude.ai skills and plugins now sync into terminal sessions

Skills and plugins enabled on your claude.ai account now show up automatically in terminal sessions signed in with that account. It can be turned off per-type with syncClaudeAiSkills: false or syncClaudeAiPlugins: false.

So what for TSD: If you build or enable a skill in the claude.ai web UI for one client's workflow, it now shows up in your terminal sessions on that project without a manual reinstall. Check your settings if you rely on a lean, project-specific toolset per client — this syncs by default.
Claude Code changelog — 2.1.275
Changed 2.1.275

Scheduled and routine runs can now edit an artifact you already gave them access to, without asking each time

A scheduled or "Run now" routine run can now save data to, and republish, an artifact you can already edit — no permission prompt. Public artifacts, first publishes, and deletes still ask.

So what for TSD: This scout routine itself is exactly this kind of unattended run — the pattern applies to any client-facing recurring report or dashboard you build on artifacts instead of the git-based flow this repo uses. Less friction if you go that route for a client deliverable.

◆ Cost & reliability

Fixed 2.1.275

A resumed session's memory file was quietly busting the prompt cache on every request

A restored memory file's age note was changing between requests after a compaction or resume, which caused prompt cache misses. It's fixed, so the cached prefix should now hold across those requests.

So what for TSD: Directly tied to what you're already tracking on token spend for this scout job and any other long-running or resumed session — a stale cache means paying full price to re-process context that should've been a cache hit. This should show up as lower spend on resumed sessions without you doing anything.
Claude Code changelog — 2.1.275
Fixed 2.1.275

[Code Review] Reviews stop dropping part of their analysis

Reviews occasionally lost part of their findings when one of the reviewing agents returned its results in an unexpected format. Fixed.

So what for TSD: If you run /code-review or ultrareview against client PRs and a pass has ever come back thinner than expected, this was a live cause. No action needed, but worth re-running a review on anything you suspected got a shallow pass recently.
Claude Code changelog — 2.1.275

◆ Security & editor

Changed 2.1.275

npm-sourced plugins install with scripts blocked and integrity verified

Plugins installed from an npm source are now fetched with npm pack --ignore-scripts and integrity-verified, so a package's install scripts no longer run on install.

So what for TSD: Standard supply-chain hardening — an npm-sourced Claude Code plugin can no longer run arbitrary code on your machine just by being installed. Relevant if you or a client ever pull in a plugin from an unfamiliar npm publisher.
Claude Code changelog — 2.1.275
New 2.1.275

[VS Code] Diff tab gets accept/reject buttons per change

The proposed-change diff tab now shows accept and reject buttons under each individual change, instead of only an all-or-nothing accept for the whole file.

So what for TSD: If you review Claude's edits in the VS Code extension before they land on a client repo, you can now keep the three good hunks in a diff and reject the one bad one, instead of accepting everything or redoing the edit from scratch.
